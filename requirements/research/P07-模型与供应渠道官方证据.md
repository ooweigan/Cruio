## 1. 研究问题与证据规则

本文件只回答 P07 所需的五类问题：

1. 候选名称究竟对应什么厂商、官方渠道和精确执行标识；
2. 各精确模型支持哪些生成场景和输入素材；
3. 官方调用是同步响应、流式响应还是异步任务，公开了哪些状态和结果形式；
4. Toonflow 固定提交中，真实存在的供应商、模型配置和执行路径是什么；
5. 哪些能力可以复用，哪些仍必须由 M03/M04/M05/M07/M11 补齐。

证据分级：

- **已核验事实**：可由官方文档、官方仓库或固定提交源码直接确认。
- **源码事实**：只说明 Toonflow 固定提交中存在某段实现，不等于对应第三方渠道已经通过真实账号验收。
- **设计影响**：根据事实对产品边界作出的建议，不把建议写成外部事实。
- **待核验事项**：公开资料不足，或必须依赖目标账号、地域、合同、实际调用才能确认。

## 2. 先行结论

1. **模型展示名不能直接执行。** “Seedance”“Nano Banana”都是系列或品牌名称；即使 `GPT Image 2`、`MiniMax-H3` 已能对应官方 ID，也仍需记录渠道、别名／快照和账号。
2. **同一展示模型可映射多个渠道，但渠道不等价。** 官方直连、TF-router、APIMart、秘塔版 MiniMax 使用不同请求结构、任务状态、素材处理和凭证体系；不能因为展示名相同就复用上游任务 ID、素材 ID 或成本规则。
3. **Seedance 官方火山方舟和 Toonflow 中的中转渠道必须分开。** 火山方舟当前公开精确 ID 包括 `doubao-seedance-2-5-260628`、`doubao-seedance-2-0-260128` 等；Toonflow TF-router 使用 `Seedance 2.5`、`Seedance 2.0` 等渠道内部标识，APIMart 又使用 `seedance-2.5`、`seedance-2.0`。这些只能通过明确的渠道模型映射关联。
4. **MiniMax H3 的提示词理解端点不等于视频生成端点。** `/v2/h3_context_ir` 只返回增强提示词；真正生成视频使用 `/v2/video_generation`，两者虽共享查询端点但 `task_type` 和成功内容不同。
5. **GPT Image 2 仍是有效模型，但已不是官方新集成首选。** 官方保留别名 `gpt-image-2` 和快照 `gpt-image-2-2026-04-21`；查询日图像指南已将新集成引向 GPT Image 2.5。产品不能静默把用户选择从 2 换成 2.5。
6. **Nano Banana 当前至少代表四个精确模型。** Google 官方文档列出 `gemini-3.1-flash-lite-image`、`gemini-3.1-flash-image`、`gemini-3-pro-image`、`gemini-2.5-flash-image`，能力和推荐用途不同。
7. **Toonflow 的“生成中”不等于可恢复的后台任务。** 节点对用户立即返回 generating，但服务器仍在同一 HTTP 请求内轮询；请求关闭会触发 abort，节点状态只存于本次组件实例，源码未将供应商任务 ID 保存为可恢复业务记录。
8. **Toonflow 可复用的是创作执行适配框架，不是完整 SaaS 模型供应模块。** 可保留供应商适配器、能力元数据、模型分组、参数校验、素材读取、结果下载落盘；供应渠道账户、租户权限、成本、健康状态、上下架、变更影响、持久任务追溯和可靠交付仍需补齐。

## 5. 各官方渠道详细证据

### 5.1 Seedance／火山方舟

#### 已核验事实

1. 火山方舟视频生成通过创建任务、按任务 ID 查询、列表查询和取消／删除组成异步任务接口；创建 API 的 `model` 接受精确 Model ID 或已配置的 Endpoint ID。[创建视频生成任务 API](https://www.volcengine.com/docs/82379/1393047?lang=zh)、[查询视频生成任务 API](https://www.volcengine.com/docs/82379/1521309?lang=zh)、[任务列表 API](https://docs.volcengine.com/docs/ark/list-video-generation-tasks-api?lang=zh)。查询：2026-09-28；适用：火山方舟视频生成 API。
2. 当前模型列表把 `doubao-seedance-2-5-260628` 与 `doubao-seedance-2-0-260128` 分开；2.5 公开为 4–30 秒、480p／720p／1080p，2.0 公开为 4–15 秒并另有 4K 能力。具体组合仍应由精确模型元数据和账号返回约束。[火山方舟模型列表](https://docs.volcengine.com/docs/ark/model-list?lang=zh)。查询：2026-09-28。
3. 创建请求的 `content` 可组合文本、图片、视频、音频和样片任务 ID；公开参数还包括 `generate_audio`、`return_last_frame`、`resolution`、`ratio`、`duration`／`frames`、`seed`、`watermark`、callback、服务等级和任务过期阈值等，但各字段并非所有模型均支持。[官方 API Explorer](https://api.volcengine.com/api-explorer/?action=CreateContentsGenerationsTasks&groupName=%E8%A7%86%E9%A2%91%E7%94%9F%E6%88%90API&serviceCode=ark&version=2024-01-01)。查询：2026-09-28。
4. 官方任务状态公开包括 `queued`、`running`、`cancelled`、`succeeded`、`failed`；设置执行超时后还可能出现 `expired`。只有排队状态可取消，取消状态会按官方规则自动清理。[任务列表 API](https://docs.volcengine.com/docs/ark/list-video-generation-tasks-api?lang=zh)。查询：2026-09-28。
5. 成功后的 `video_url` 和可选 `last_frame_url` 有效期为 24 小时，必须及时下载或转存；2.5 输出链接另有下载次数限制。官方建议用 TOS 数据订阅进行长期备份。[任务列表 API](https://docs.volcengine.com/docs/ark/list-video-generation-tasks-api?lang=zh)、[TOS 数据订阅](https://docs.volcengine.com/docs/TorchObjectStorage/Creatingdatasubscriptionrules?lang=zh)。查询：2026-09-28。
6. Seedance 2.5 官方提示词指南称其可输入文本、图片、视频和音频组合，单次最多 50 个参考素材，并区分会锁定输出时间轴属性和仅语义参考的任务。[Seedance 2.5 提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)。查询：2026-09-28；适用：Seedance 2.5。
7. 火山方舟的真人参考不只是普通文件上传：官方可信素材库要求真人认证、补充素材可能进行人脸一致性检查，成功入库后进入私域素材库。[录入真人形象素材](https://docs.volcengine.com/docs/ark/upload-real-person-portrait-assets?lang=zh)。查询：2026-09-28；适用：火山方舟可信素材库。

#### 对产品的影响

- M03 需把“火山方舟渠道 + 精确 Model ID／Endpoint ID”设为可追溯组合；Endpoint 不等于基础模型名。
- M05 必须区分普通平台素材、可传 URL 的生成参考、火山方舟可信素材／厂商素材 ID；后两者不能由文件路径自动等价替换。
- M04 在成功后应先转存并验证用户可访问，再视为可靠交付；上游 URL 到期或下载次数耗尽不能算已完成交付。
- 状态映射必须保留 `expired` 和未知状态，不应只处理成功／失败。
- 取消只能表达“已请求取消”；运行中任务能否取消由上游实际状态决定，不能承诺无成本撤销。

#### 待核验

- 本项目火山方舟账号实际能开通哪些 Seedance 模型、地域、Endpoint 和并发／配额。
- Seedance 2.5 每种具体任务类型下 50 个参考素材的分类、锁定规则及请求字段组合。
- 可信素材库面向 API 的登记、授权人管理、素材 ID 生命周期、删除和跨 Endpoint／账号可用范围。
- 内容审核错误、重试、账单 usage 与“仅成功计费”在本项目真实账号返回中的对应关系。

### 5.2 MiniMax H3 官方云 API

#### 已核验事实

1. 视频生成端点为 `POST /v2/video_generation`，`MiniMax-H3` 支持文本、首／尾帧、参考图片、参考视频和参考音频；必须包含非空文本项。H3 的公开输出规格为 768P／2K、4–15 秒。[创建视频生成任务](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)、[视频生成指南](https://platform.minimax.io/docs/guides/video-generation)。查询：2026-09-28；适用：MiniMax H3 官方 Pay-as-you-go API。
2. 首尾帧模式与参考素材模式互斥。图片参考最多 9 张；参考视频最多 3 段、每段 2–15 秒且总时长不超过 15 秒；参考音频最多 3 段，时长规则相同；混合参考总文件数还受官方总量约束。[创建视频生成任务](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)。查询：2026-09-28。
3. 创建返回 `task_id`；可轮询或配置 callback。状态包括 `queued`、`running`、`succeeded`、`failed`、`cancelled`；成功生成视频时结果位于 `task.content.url`。[查询任务](https://platform.minimax.io/docs/api-reference/video-generation-v2-query)。查询：2026-09-28。
4. 查询端点只保证可查询最近 7 天内的任务，因此平台必须自行持久化任务事实和转存结果。[查询任务](https://platform.minimax.io/docs/api-reference/video-generation-v2-query)。查询：2026-09-28。
5. `DELETE /video_generation/v2/{task_id}` 对 queued 是取消，对 succeeded／failed 是删除记录；running／cancelled 不可按该端点处理。[取消或删除任务](https://platform.minimax.io/docs/api-reference/video-generation-v2-delete)。查询：2026-09-28。
6. `POST /v2/h3_context_ir` 虽也返回 `task_id`，但只生成增强提示词，成功结果是 `content.prompt`，不是视频文件；应通过 `task_type=h3_context_ir` 与生成任务区分。[H3-Context-IR](https://platform.minimax.io/docs/api-reference/video-generation-v2-h3-context-ir)。查询：2026-09-28。

#### 对产品的影响

- M03 至少要把“视频生成能力”和“Context-IR 提示词处理能力”登记为两个场景／操作，不得只用模型名区分。
- M04 保存上游 `task_id`、`task_type`、渠道和提交能力快照，不能只保存最终 URL。
- 自动切换渠道时不得沿用 MiniMax `task_id`；素材引用也必须按目标渠道重新准备。
- 删除上游任务记录不等于撤销本平台任务事实，更不能删除积分和交付记录。

#### 待核验

- 本项目官方账号的地域、余额、限流、callback 可达性和实际结果 URL 有效期。
- H3 和 H3 Max 是否都进入产品目录；若进入，应分开能力快照和销售规则。
- 真实失败错误码、审核拒绝、usage 字段和计费结算之间的关系。

### 5.3 OpenAI GPT Image 2

#### 已核验事实

1. `gpt-image-2` 是有效别名，固定快照为 `gpt-image-2-2026-04-21`；支持文本输入、图像输入和图像输出，不支持音频或视频。[GPT Image 2 模型页](https://developers.openai.com/api/docs/models/gpt-image-2)。查询：2026-09-28。
2. Images API 分为 `/v1/images/generations` 和 `/v1/images/edits`；编辑端点最多接收 16 张图像输入，并可提供 mask。[创建图像](https://developers.openai.com/api/reference/resources/images/methods/generate)、[创建图像编辑](https://developers.openai.com/api/reference/resources/images/methods/edit)。查询：2026-09-28。
3. GPT Image 2 支持 `low`／`medium`／`high`／`auto` 质量、PNG／JPEG／WebP、透明背景预览以及满足约束的自定义分辨率；图像输入始终按高保真处理，不能用 `input_fidelity` 降低。[图像生成指南](https://developers.openai.com/api/docs/guides/image-generation)。查询：2026-09-28。
4. 直接 Images API 可返回完整 base64 图像，也可用 SSE 返回最多 3 个部分图事件再返回完成事件；这不是视频任务式的持久 `task_id` 查询模型。[创建图像 API](https://developers.openai.com/api/reference/resources/images/methods/generate)。查询：2026-09-28。
5. 官方查询日已将新集成推荐为 GPT Image 2.5 Sunburst／Flare，并把 GPT Image 2 放在早期模型参考段落；GPT Image 2 尚未被列为弃用。[图像生成指南](https://developers.openai.com/api/docs/guides/image-generation)、[弃用清单](https://developers.openai.com/api/docs/deprecations)。查询：2026-09-28。

#### 对产品的影响

- 展示模型可继续叫 GPT Image 2，但执行记录宜锁定快照，或明确记录使用浮动别名。
- “生成图片”和“编辑图片／局部 mask”应是不同场景能力；Toonflow 当前通用图像节点只向 provider 传 prompt、images、ratio、size，尚未把其类型中已有的 mask、质量、格式等字段完整贯通到生成路径。
- 直连 OpenAI 时应保存响应使用量和最终文件，不要虚构供应商任务状态；平台内部仍可统一呈现“处理中”，但须标明它是平台状态而非 OpenAI task status。
- 2 → 2.5 的迁移应走显式的新模型／版本变更和回归验证，不能覆盖既有模板的能力快照。

#### 待核验

- 本项目 OpenAI 组织是否完成所需验证、地域可用性、速率限制和目标快照权限。
- 最终选择 Images API、Responses API 还是 Batch；三者任务和多轮语义不同。
- 产品是否仍首发 GPT Image 2，或把 2.5 作为另一个模型上架；本研究不代替采购决策。

### 5.4 Google Nano Banana／Gemini 图像系列

#### 已核验事实

1. Nano Banana 是 Gemini 原生图像生成系列名，不是单一执行 ID。查询日有四个精确模型：`gemini-3.1-flash-lite-image`、`gemini-3.1-flash-image`、`gemini-3-pro-image`、`gemini-2.5-flash-image`。[图像生成指南](https://ai.google.dev/gemini-api/docs/image-generation)。查询：2026-09-28；适用：Gemini API。
2. Gemini 图像模型接受文本和图像输入并输出图像／文本；指南还展示在上下文中处理视频。所有生成图像包含 SynthID 水印。[图像生成指南](https://ai.google.dev/gemini-api/docs/image-generation)。查询：2026-09-28。
3. Gemini 3 图像模型支持多参考：Flash Lite 最多 14 个对象参考；Flash Image 最多 10 个对象加 4 个角色一致性参考；Pro 最多 6 个对象、5 个角色、3 个风格参考，总量最多 14 张。2.5 Flash Image 官方建议最多 3 张输入图效果较佳。[图像生成指南“Use up to 14 reference images”](https://ai.google.dev/gemini-api/docs/image-generation#use-up-to-14-reference-images)。查询：2026-09-28。
4. Gemini 3.1 Flash Image 支持 0.5K／1K／2K／4K，Pro 支持最高 4K，Flash Lite 只支持 1K；输出比例和尺寸通过 `response_format` 配置。[图像生成指南](https://ai.google.dev/gemini-api/docs/image-generation#aspect-ratios-and-image-size)。查询：2026-09-28。
5. 多轮编辑通过 Interaction 延续，可使用 `previous_interaction_id`；批量生成另走 Batch API，官方说明可能有最长 24 小时周转。[图像生成指南](https://ai.google.dev/gemini-api/docs/image-generation#multi-turn-image-editing)。查询：2026-09-28。
6. `gemini-2.5-flash-image` 是稳定 ID，旧 preview ID 已弃用；模型页列出图像和文本输入／输出。[Gemini 2.5 Flash Image 模型页](https://ai.google.dev/gemini-api/docs/models/gemini-2.5-flash-image)。查询：2026-09-28。

#### 对产品的影响

- M03 必须把四个精确模型分为独立能力快照；“Nano Banana”只能作为模型系列／营销标签。
- 多参考图不能只记一个统一 `multiReference=true`；需记录对象、角色、风格参考及各自限制，否则画布只能做粗粒度校验。
- 多轮 interaction ID 是上下文延续标识，不应与视频异步 task ID 混成同一种供应商任务字段。
- Toonflow APIMart 源码中的 `gemini-3-pro-image-preview`、`gemini-3.1-flash-image-preview` 与当前 Google 官方稳定 ID 不一致，必须视为 APIMart 渠道内部映射，不能证明 Google 官方直连已经适配。

#### 待核验

- 采购走 Gemini Developer API 还是 Vertex AI；本轮只核验了 Gemini API，未证明两条渠道完全等价。
- 中国大陆实际访问、结算主体、数据区域及企业账号条款。
- 目标渠道是否完整支持 Interaction、多轮、Batch、Google Search grounding 和官方所列参考图分类。

### 6.1 已存在且可复用

| 层次 | 源码事实 | 可复用边界 |

| 供应商定义 | provider 可以声明 `id`、`label`、版本、配置表单、模型数组及图片／视频／音频生成函数；模型元数据含类型、模式、音频、图片尺寸／比例、时长—分辨率映射 | 可作为渠道适配器协议和画布能力快照的起点 |

### 6.2 当前执行链

```text
画布节点选择 providerId + modelId
  → 根据 provider 的静态／刷新后能力元数据校验模式和参数
  → POST /api/ai/media/generate
  → 服务器从本机数据目录加载 provider TypeScript 和本机配置的 API Key
  → provider 提交上游请求，并在同一调用中轮询／等待最终结果
  → 服务器下载 URL 或解码 base64，校验格式和大小
  → 写入工作区 assets/<nodeId>/...
  → HTTP 返回本地相对路径
  → 节点把该路径写成输出
```

### 6.3 已确认的缺口

| 缺口 | 源码依据 | M03／相邻模块影响 |
|---|---|---|
| 上游任务 ID 未形成平台业务记录 | provider 类型要求生成函数只返回最终 `MediaAsset[]`，任务 ID 在各 provider 内部局部变量中轮询后丢弃 | M04 必须保存平台任务、渠道、精确模型、上游任务 ID、提交参数快照和最后核验时间 |
| HTTP 请求与上游轮询耦合 | `/api/ai/media/generate` 等到最终文件后才响应；响应／socket 关闭会 abort | 首发 SaaS 不能依赖浏览器长连接维持任务；需要可恢复后台执行边界 |
| 节点状态仅在本次打开后有效 | `useNodeGeneration` 明确状态为 `idle/running/succeeded/failed`，说明只查询“本次打开节点后的生成状态” | 刷新、进程重启、换设备不能靠节点状态恢复；M04 是权威任务状态 |
| 取消不等于上游取消 | 节点说明取消请求不能保证供应商撤销任务或费用；现有 provider 多数只 abort 本地 fetch／轮询，未调用各厂商取消 API | 取消需分“本地停止等待”“已请求上游取消”“上游已取消”；积分不能在状态未知时释放 |
| 未覆盖未知／过期等状态 | provider 轮询通常只显式识别成功和失败，其他状态继续等待直到本地超时；部分未显式处理 cancelled | M04 必须保留 unknown、cancelled、expired、delivery_failed 等平台状态及人工核查入口 |
| 任务恢复不足 | TF-router 源码注释明确等待供应商开放恢复能力后再单独保存任务 ID；节点卸载会 abort | 必须补持久化、回调／轮询恢复和人工查询，不得把现状描述成重启可恢复 |
| 模型能力元数据偏粗 | 图像只有 text／singleImage／multiReference，视频模式使用字符串和数量上限；没有参考角色语义、mask、渠道限制、版本阶段等完整字段 | M03 应新增结构化能力快照，但可向下兼容现有字段 |
| provider 配置是本机设置 | API Key 从本地 settings 读取；缺少租户／岗位／密钥所有权和操作审计语义 | M02/M11/M14 需控制凭证归属、可查看范围、轮换、停用和变更记录 |
| 没有经营配置 | provider 模型结构不含采购成本、积分售价、余额、限额、健康状态、用户可见性、上下架和受影响任务 | 成本归 M03，积分销售规则归 M07，凭证及运营变更归 M11/M14；不得塞进画布节点 |
| 第三方源码存在不等于已安装 | `app.ts` 自动安装列表只有 `tfRouter.ts`；APIMart 与 meta 只是仓库源码 | M03 初始化必须有明确安装／启用状态，不能把源码文件当成上线渠道 |
| 结果有落盘但缺少可靠交付事实 | 工作区文件写入成功后返回路径，但没有用户级资产归属、可访问验证、积分实结事实 | M04/M05/M07 需组成“转存—关联—访问验证—可靠交付—积分实结”闭环 |

## 7. 对 M03 功能范围的直接影响

### 7.1 M03 应负责

1. **展示模型目录**：产品展示名、系列、模态、适用用户／场景、上下架和可见范围。
2. **精确模型版本**：官方 Model ID／别名／快照／Endpoint ID、版本阶段、发布日期或核验日期。
3. **供应渠道**：官方直连或中转渠道、渠道状态、地区、凭证所属账户、渠道内部模型 ID。
4. **模型—渠道映射**：一个展示模型可有多个映射；每个映射拥有独立能力、参数、素材要求、上游限制和采购成本。
5. **能力快照**：输出模态、场景、输入类型及角色、数量／格式／尺寸／时长限制、输出规格、音频、mask、多轮、Batch、回调／轮询能力。
6. **运营控制**：模型和渠道启停、用户可见性、余额／配额告警、健康状态、变更记录、受影响模板／课程／待执行任务查询。
7. **凭证引用和最小权限**：记录凭证归属与状态，但不向画布、普通用户或日志返回明文。
8. **采购事实**：记录成本口径和 usage 来源；不负责客户积分扣费或货币商品定价。

### 7.2 M03 不应负责

- 平台生成任务的状态机、重试、未知任务人工处理和可靠交付：归 M04。
- 用户素材、作品和转存结果的归属：归 M05/M06。
- 预占、实结、释放和积分售价：归 M07。
- 外部收款、订单和退款：当前线下处理；未来归 M08。
- 供应商凭证明文展示、安全事件和永久审计：由 M11/M14 共同约束。

### 7.3 现有 Toonflow 能力的处理建议

| Toonflow 现有能力 | P07 建议 |
|---|---|
| provider TypeScript 适配器 | 保留为执行适配层；增加平台渠道记录与 providerId 映射，不要求一次性重写 |
| `providerId + modelId` 选择 | 保留为执行键的一部分；在其上增加稳定的展示模型 ID、渠道映射 ID和能力快照版本 |
| provider 内静态 `models` | 作为默认／回退能力声明，不直接视为运营已上架；导入 M03 后需审核、核验日期和发布状态 |
| `modelsUrl` 刷新 | 仅作为候选同步；新模型缺少能力时保持不可用，源码已经采用“不猜测生成能力”的方向 |
| 本地 API Key 配置 | 改造成平台受控凭证引用；迁移时不得把桌面端个人密钥默认共享给全部用户 |
| 节点通用参数 | 保留 UI；选项由 M03 渠道能力快照返回，不使用全局通用值覆盖模型限制 |
| provider 内轮询 | 短期可作为适配逻辑参考；平台任务编排应在 M04 持久化上游任务后驱动，不由浏览器请求寿命决定 |
| 工作区结果落盘 | 作为转存步骤复用；只有资产关联及访问验证完成后才向积分模块发送可靠交付事实 |

## 8. 进入 M03 PRD 前仍需明确的少量事项

这些事项不阻塞 PRD 草案，但必须保持“待确认”，不能由研究文档代替决策：

1. **首发采购渠道组合**：Seedance 是否优先火山方舟官方直连，MiniMax 是否用官方云 API，OpenAI／Google 是否具备目标地区和结算主体条件；TF-router／APIMart／秘塔是否仅作备选。
2. **首发精确模型清单**：Seedance 2.5／2.0 各上哪些变体；MiniMax H3 是否同时上 H3 Max；GPT Image 2 是否保留，是否另上 2.5；Nano Banana 四个模型选哪些。
3. **凭证所有权**：首发由平台统一采购密钥，还是允许管理员接入自有渠道账号；普通用户是否永远不可自带密钥。
4. **渠道切换策略**：用户提交前是否允许选渠道；提交后仅在确认原任务未创建／已失败时才能新建另一任务，还是一律人工处理未知状态。
5. **厂商素材策略**：火山方舟可信素材库是否进入首发；若进入，需要单独核验企业授权、素材登记 API、账号／Endpoint 作用域和删除治理。
6. **版本锁定策略**：浮动别名和固定快照如何用于新项目、旧模板与课程；版本变更是自动迁移、提示迁移还是保留原能力快照。
