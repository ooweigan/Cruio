## 1. 证据口径

本文件只核对任务创建、上游任务 ID、轮询／回调、状态持久化、刷新／重启恢复、结果下载转存和取消语义。

- **源码存在**：固定提交中可定位到实现，只证明代码存在，不证明渠道账号可用或行为已经实测。
- **官方声明**：来自厂商官方文档、官方 SDK／CLI 仓库；只适用于所注明渠道和查询日版本。
- **待实测**：官方未公开，或必须用目标账号与真实网络环境才能确认。
- **设计影响**：基于证据对 M04 范围的建议，不擅自确认产品决策。

本轮把以下概念严格分开：

1. **提交已受理**：供应商返回任务 ID，或同步调用已返回结果；
2. **供应商生成成功**：供应商任务进入成功态；
3. **结果可获取**：上游 URL／字节当前可以下载；
4. **平台转存成功**：平台已把结果保存到受控存储；
5. **可靠交付**：结果已关联到正确任务和用户，且用户可正常访问；
6. **积分实结**：按已确认规则，仅发生在可靠交付之后。

这些不是同一个事件。

## 2. 先行结论

1. **Toonflow 固定提交不是可恢复的 SaaS 后台任务系统。** 节点工具虽然立即返回 `generating`，但服务端仍在原 HTTP 请求中等待供应商轮询；浏览器／请求连接关闭会触发 abort。
2. **上游任务 ID 被适配器内部消费，没有进入宿主返回值或持久任务记录。** `GenerateMedia` 合同明确只返回最终媒体数组；TF-router、APIMart、秘塔 MiniMax 适配器的任务 ID 都只是函数局部变量。
3. **页面刷新、节点卸载和进程重启不能依靠现有生成状态恢复。** 节点状态被定义为“本次打开节点后的生成状态”；卸载会 abort。固定提交媒体生成链路中未发现以供应商任务 ID 为键的持久化、恢复扫描或回调接收实现。
4. **现有“取消”只是终止本地等待，不等于供应商取消。** 源码自己也明确写明不能保证撤销供应商任务或费用；三个媒体 provider 都没有调用上游取消端点。
5. **现有结果下载落盘是可复用的交付原语，但还不是完整可靠交付。** 它校验协议、体积、MIME，写入工作区并对本次部分写入回滚；仍缺业务任务关联、所有权、交付状态、用户访问校验和积分实结触发证据。
6. **超时或断线不能直接映射为“生成失败”。** 如果提交已经被供应商接受，本地 10／30 分钟超时、请求断开或重启只说明平台失去观察；在未对账前应进入“未知／待核查”，不能自动重提或释放预占。
7. **官方视频渠道本身具备恢复所需的任务 ID 与查询能力。** 火山方舟和 MiniMax H3 都是异步任务；但查询窗口、短期结果 URL 和取消限制意味着平台必须在供应商窗口内持久保存 ID、持续对账并尽快转存。
8. **官方图片直连不能套用视频式任务假设。** OpenAI GPT Image 2 的 Images API 与 Google Nano Banana 的常规图片调用直接返回图片数据／交互结果；除非明确采用各自的后台或 Batch 路径，否则不存在与视频任务相同的可查询 task ID。

### 3.3 状态、刷新、重启与取消

#### 已由源码确认

- 节点状态只有 `idle/running/succeeded/failed`，并被说明为“本次打开节点后的生成状态”；`idle` 仍可能有历史输出。[节点生成状态](https://github.com/HBAI-Ltd/Toonflow-app/blob/d86cce6b689916ab73f75bc4c1f42a2a7424516c/packages/nodeScaffold/src/useNodeGeneration.ts#L5-L15)。
- 节点刷新在生成中会被显式阻止；节点卸载、节点删除、用户点击停止均调用本地 `AbortController`。[图片节点](https://github.com/HBAI-Ltd/Toonflow-app/blob/d86cce6b689916ab73f75bc4c1f42a2a7424516c/packages/nodes/imageGenerationNode/src/index.vue#L154-L158)、[视频节点](https://github.com/HBAI-Ltd/Toonflow-app/blob/d86cce6b689916ab73f75bc4c1f42a2a7424516c/packages/nodes/videoGenerationNode/src/index.vue#L195-L199)。
- `cancelGeneration` 的源码说明明确指出：只能请求停止当前后台生成，**不能保证供应商撤销任务或费用**；本地 AbortError 会把节点状态记为 `failed`、错误文案为“生成已取消”。[取消与状态处理](https://github.com/HBAI-Ltd/Toonflow-app/blob/d86cce6b689916ab73f75bc4c1f42a2a7424516c/packages/nodeScaffold/src/useNodeGeneration.ts#L17-L41)。
- 三个媒体 provider 均把取消信号用于中止本地 HTTP／等待；本轮检查的媒体路径中未发现调用供应商取消接口。

#### 本轮源码检索未发现

在固定提交的 `apps/server/src`、`packages/providers`、`packages/nodes`、`packages/nodeScaffold` 媒体生成路径中，本轮未发现：

- 生成任务数据库／仓储；
- 持久化的上游 task ID；
- 媒体生成 callback／webhook 接收路由；
- 进程启动后的未完成任务恢复扫描；
- 按上游 task ID 继续轮询的宿主接口。

这是一项**限定范围的源码检索结论**，不是对仓库外服务或未来版本的否定。仓库中的 A2A agent task ID 属于远端团队任务，不是媒体生成任务，不能混用。

### 3.4 结果转存与“可靠交付”差距

现有下载落盘已做到：

- 仅接受 HTTP／HTTPS 结果 URL；
- 检查 `Content-Length`，并在实际读取过程中再次限制 100 MB；
- 检测实际文件头和 MIME，拒绝不支持的媒体格式；
- 使用新 UUID 文件名写入节点资源目录；
- 多结果写入中途失败时，仅回滚本次已经创建的文件，保留历史资源。

但源码没有证明以下业务事件已经发生：

- 文件属于哪个平台用户、项目和业务生成任务；
- 上游成功结果与本地文件之间有不可丢失的关联；
- 文件写入后用户权限链路能够读取；
- 用户已收到可访问结果；
- 交付失败可在供应商 URL 过期前恢复；
- 可靠交付事件已唯一触发积分实结。

因此，现有实现可作为转存机制参考，不能直接把“provider 返回成功”或“文件写入完成”定义为完整交付闭环。

## 4. Seedance／火山方舟官方任务语义

### 4.1 已核验官方声明

1. 视频生成是异步任务；提交后取得任务 ID，可按 ID 查询，也可列表查询。官方 Ark CLI 同样把视频默认行为描述为“返回 `task_id` + `queued`，随后 `gen get` 续查”。[火山方舟官方 Ark CLI 生成说明](https://github.com/volcengine/ark-cli/blob/main/skills/arkcli-gen/references/arkcli-gen.md)。查询：2026-09-28；适用：Ark CLI 2.1.0 文档及其对应火山方舟 Runtime API。
2. 任务列表公开状态包括 `queued`、`running`、`cancelled`、`succeeded`、`failed`；`execution_expires_after` 超时会使任务被终止并标记为 `expired`。[查询视频生成任务列表](https://docs.volcengine.com/docs/ark/list-video-generation-tasks-api?lang=zh)。查询：2026-09-28；适用：火山方舟视频生成 API。
3. 官方列表只支持查询最近 7 天的任务记录；视频结果 URL 有效期 24 小时；Seedance 2.5 产物 URL 还有最多 100 次下载限制。[查询视频生成任务列表](https://docs.volcengine.com/docs/ark/list-video-generation-tasks-api?lang=zh)。查询：2026-09-28。
4. 仅 `queued` 任务可取消；`cancelled` 状态记录 24 小时后自动删除。[查询视频生成任务列表](https://docs.volcengine.com/docs/ark/list-video-generation-tasks-api?lang=zh)。查询：2026-09-28。
5. 创建任务可传 `callback_url`；官方 Ark CLI 文档列出的生命周期事件为 `created/running/succeeded/failed`。[官方 Ark CLI 生成说明](https://github.com/volcengine/ark-cli/blob/main/skills/arkcli-gen/references/arkcli-gen.md)。查询：2026-09-28。
6. 官方 CLI 在任务成功时可自动下载，但下载失败只警告，不改变供应商成功状态；文档明确提醒不能仅凭生成成功声称文件已保存。[官方 Ark CLI 任务管理说明](https://github.com/volcengine/ark-cli/blob/main/skills/arkcli-gen/references/gen-meta.md)。查询：2026-09-28；适用：Ark CLI 2.1.0。

### 4.2 不能从公开文档直接确认

- 回调失败后的重试次数、退避、最长投递期和消息去重标识；
- 同一状态是否可能重复投递、不同状态是否保证严格有序；
- `expired` 是否也发送回调；
- 创建请求在客户端超时但服务端已受理时，官方是否提供业务幂等键；
- 取消请求与状态跃迁竞争时的全部边界响应。

这些必须进入回调和异常验收；不能把“支持 callback”写成“回调可靠且有序”。

### 4.3 对 M04 的直接影响

- 收到上游 task ID 后应立即持久记录；7 天查询窗口不能替代平台长期账务与故障记录。
- 供应商 `succeeded` 后要在 24 小时和下载次数约束内完成转存；下载失败仍是“供应商成功、平台未交付”，不能实结。
- 平台取消只有在上游确认取消后才能标成“供应商已取消”；本地停止观察与取消请求失败要分别记录。
- `expired`、回调未知事件和本地等待超时都必须保留为可对账状态，不能挤进 `failed`。

## 5. MiniMax H3 官方任务语义

### 5.1 已核验官方声明

1. `POST /v2/video_generation` 是异步创建接口，成功返回 `task_id`；随后使用查询接口取得状态与结果。[创建视频生成任务](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)。查询：2026-09-28；适用：MiniMax H3／H3 Max Pay-as-you-go API V2。
2. 查询单个任务使用 `GET /v2/query/video_generation/{task_id}`；只保证可查询最近 7 天的任务。成功结果在 `task.content.url`。[查询任务](https://platform.minimax.io/docs/api-reference/video-generation-v2-query)。查询：2026-09-28；适用：同上。
3. 列表公开状态为 `queued`、`running`、`succeeded`、`failed`、`cancelled`，列表总数也只统计最近 7 天。[任务列表](https://platform.minimax.io/docs/api-reference/video-generation-v2-list)。查询：2026-09-28。
4. 创建请求可设置 `callback_url`。MiniMax 先发送含 `challenge` 的验证请求，接收端需在 3 秒内原样返回；验证成功后，状态变化时 POST 与查询接口同结构的数据。回调状态同样为五种状态。[创建视频生成任务](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)。查询：2026-09-28。
5. `DELETE /v2/video_generation/{task_id}` 依状态执行不同动作：`queued` 可取消且官方注明未开始处理、不收费；`succeeded/failed` 是删除任务记录；`running/cancelled` 不允许操作并返回错误。[取消或删除任务](https://platform.minimax.io/docs/api-reference/video-generation-v2-delete)。查询：2026-09-28。

### 5.2 公开资料未确认

- 本轮官方 H3 V2 创建、查询、列表和删除页没有给出成功 `content.url` 的明确有效期；必须按短期 URL 处理并通过实测／商务支持确认，不能照搬火山方舟的 24 小时。
- 回调重试、签名／鉴权、重复投递、顺序保证和最长投递时间未在本轮公开页中确认。
- 创建请求超时后的幂等与任务检索策略未公开确认。
- 删除成功／失败记录对账务凭据、内容 URL 和服务端底层文件的影响未公开确认；平台不应把“删除上游记录”用作普通用户取消。

### 5.3 Toonflow `meta` 适配器与官方语义的差异

- 适配器使用秘塔代理地址，不是 MiniMax 官方直连渠道；源码存在不代表官方渠道已接入。
- 适配器只识别 `succeeded`、`failed`；官方还有 `queued/running/cancelled`。若代理返回 `cancelled`，当前代码会继续轮询直到本地超时。
- 适配器没有传 `callback_url`，也没有调用官方取消／删除端点。
- task ID 只保存在函数局部变量；10 分钟本地超时或进程中断后无法由宿主续查。

## 6. OpenAI GPT Image 2 与 Google Nano Banana：不同任务形态

### 6.1 OpenAI GPT Image 2

**官方声明：** `POST /v1/images/generations` 返回完整 `ImagesResponse`，或在开启流式后返回部分图和完成事件；GPT 图像模型结果为 base64 图像数据。官方示例在请求返回后直接解码并写入文件。[图像生成指南](https://developers.openai.com/api/docs/guides/image-generation)、[Images API 参考](https://developers.openai.com/api/reference/resources/images/methods/generate)。查询：2026-09-28；适用：OpenAI Images API、`gpt-image-2`。

**结论：** 常规 Images API 不是火山方舟／MiniMax 那种“创建后拿 task ID，再过几分钟查询”的视频任务。流事件属于同一请求过程，不应把 partial image 当作可靠交付。若采用 Responses 后台模式或 Batch API，应作为另一条精确渠道执行方式另行建模，不能从 Images API 文档推导其取消和保留语义。

**待实测：** 客户端中断流式请求后服务端实际计费与计算是否停止、最终完成事件缺失时的对账方式，需结合目标合同／账号验证；本轮没有执行调用。

### 6.2 Google Nano Banana／Gemini 图像

**官方声明：** Gemini 图像指南通过 `interactions.create` 提交请求，并从返回的 interaction 中取得 base64 图像数据；多轮编辑可传 `previous_interaction_id`。[Nano Banana 图像生成指南](https://ai.google.dev/gemini-api/docs/image-generation)。查询：2026-09-28；适用：查询日 Gemini API 图像模型。

**结论：** 常规图片生成路径可以有 interaction ID，但公开示例不是视频式异步任务轮询协议。若启用 Gemini 的 background、webhook 或 Batch 能力，必须把具体 API 路径、状态、保留期和取消语义作为独立执行模式核验，不能只凭“Nano Banana”模型名推断。

**待实测：** 当前目标账号最终采用 Developer API 还是 Vertex AI、interaction 的服务端保存期限、后台执行／取消可用性、网络中断后的可恢复性。本轮没有执行调用。

## 8. 对 M04 职责与范围的证据性建议

以下是设计建议，不是本轮自动确认的实现决定。

### 8.1 M04 应拥有的业务边界

- 在任何可扣费提交之前创建平台任务，并保存用户、项目／画布节点、模型、渠道、参数快照、引用素材快照和积分预占关联；
- 把供应商返回的 task ID、渠道响应标识和首次已受理时间持久化，不能只留在进程内 Promise；
- 对异步渠道同时支持轮询与可选回调，两者都更新同一平台任务；回调必须按重复、乱序和迟到事件处理；
- 保存供应商原始状态，并单独映射平台状态；未知状态不得自动当失败；
- 在页面关闭和服务器重启后继续观察未终态任务；不能靠阻止刷新维持正确性；
- 把结果发现、下载、校验、转存、业务关联、访问验证、交付、积分实结拆成可追踪阶段；
- 提供人工对账入口，允许按渠道和上游 task ID 查证，但不改写历史事件；
- 取消请求只表达用户意图；必须记录“未支持、已请求、上游已取消、已在运行无法取消、状态未知”等真实结果。

### 8.2 建议的平台状态层级

不要求直接使用下列字段名，但语义至少应覆盖：

| 平台阶段 | 典型含义 | 不应自动推导为 |
|---|---|---|
| `preparing` | 校验参数、引用和积分预占 | 供应商已受理 |
| `submitting` | 正在创建上游任务 | 可以安全重提 |
| `queued/running` | 上游已受理并排队／执行 | 已交付 |
| `supplier_succeeded` | 上游报告成功 | 用户已可访问、积分可实结 |
| `transferring` | 正在下载、校验、转存 | 必然可恢复 |
| `delivered` | 结果已关联且用户可访问 | 仅文件写入成功 |
| `failed` | 有明确、可证明的终态失败 | 网络超时、未知响应 |
| `unknown/review_required` | 是否受理或最终结果无法确认 | 自动失败、自动成功、自动重提 |
| `cancel_requested/cancelled` | 用户已提出取消／上游已确认取消 | 本地请求被 abort |

积分状态应作为相邻但独立的账务状态关联，不塞入生成状态字段：预占、实结、释放和人工纠正各自留痕。

### 8.3 必须覆盖的异常场景

1. 创建请求超时，但供应商可能已经创建任务；
2. 成功响应返回 task ID 后，平台落库失败；
3. 同一用户操作被重复提交，产生一个或多个上游任务；
4. 轮询超时、临时 5xx、限流或拿到未知状态；
5. 回调重复、乱序、迟到，或先于创建事务完成到达；
6. 页面刷新、关闭、节点删除、浏览器断网；
7. 应用或服务器在 queued、running、转存中间重启；
8. 供应商成功，但结果 URL 已过期、次数耗尽、返回 403／404 或内容损坏；
9. 文件已转存，但关联作品／节点失败；
10. 已可靠交付，但用户通知失败；
11. 多结果任务部分成功、部分失败；
12. 用户请求取消，但供应商不支持、任务已 running、或取消响应未知；
13. 供应商删除“任务记录”与取消“生成执行”语义不同；
14. 模型版本、渠道配置在任务运行期间被下架或更改。

### 8.4 不应照搬 Toonflow 的部分

- 不照搬“节点组件持有 Promise 就是后台任务”；
- 不照搬仅四态的组件内状态作为业务任务真相；
- 不照搬 provider 只返回最终媒体、丢弃 task ID 和原始状态的合同；
- 不把 HTTP 断开／AbortError 统一显示为“生成已取消”后即结束账务处理；
- 不把 10／30 分钟本地等待超时当供应商失败；
- 不把工作区文件存在直接当成用户可靠交付。

## 9. 进入 M04 前应保留的少量关键待核验项

这些问题不阻塞先写 PRD；PRD 可按保守假设继续，并把它们列为供应商接入验收项。

1. **渠道优先级**：Seedance 首发是否以火山方舟官方直连为主，MiniMax 是否以官方 H3 V2 为主；TF-router／APIMart／秘塔是否只作为独立候选渠道。
2. **创建幂等**：各目标渠道是否支持可由本项目控制的幂等键；若不支持，创建超时后的默认策略应是先对账、不自动重提。
3. **回调可靠性**：火山方舟和 MiniMax 的签名、重试、重复、乱序、IP／域名要求和到达时延，需要在测试环境验证。
4. **MiniMax URL 时效**：官方公开页未标出 H3 `content.url` 有效期；上线前必须得到官方支持答复或实测证据。
5. **图片执行路径**：OpenAI／Gemini 首发使用直接请求、流式、后台模式还是 Batch；只有确定路径后才能确认恢复和取消语义。
6. **“用户可正常访问”的验收动作**：需在 M04 明确是服务端读取校验、受控下载校验，还是还包括前端成功打开；这会直接决定积分实结事件。
