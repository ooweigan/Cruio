本文定义积分额度、面向用户的生成报价、预占、实结、释放、外部成交充值、外部退款扣回和账本对账。积分是产品使用额度，不是现金、订单、退款金额或佣金；M03 的采购成本与 M07 的用户积分报价分别维护。

## 1. 模块目标

M07 使用户在创作前知道预计积分、在提交时锁定可用额度、在结果可靠交付后按确认规则结算，并能通过明细理解每次积分变动。运营人员能够根据线下／第三方成交凭据发放积分、根据已确认退款扣回积分，并在异常时核对 M04 任务事实和本模块账本。

成功意味着：同一积分不能被并发任务重复消费；没有确认报价不进入计费提交；只有可靠交付才最终扣分；失败与永久不可交付按确认规则释放预占；未知状态持续预占直到核查；任何账本错误通过新的冲正事实修复，不覆盖历史；当前产品不生成平台订单、支付或退款事实。

## 3. 概念、证据与设计原则

### 3.1 关键概念

| 名称 | 含义 | 不等同于 |
|---|---|---|
| 积分总账面余额 | 已获得积分净额减已实结消耗和已扣回调整后的结果；可以为负 | 可立即提交的额度 |
| 可用积分 | 当前可供新任务预占的额度；负余额时为 0 | 账面余额本身 |
| 预占积分 | 用户确认报价后为特定任务暂时锁定的额度 | 最终消费或额外积分 |
| 实结积分 | 可靠交付后按已确认规则正式记为消耗的积分 | 供应商成本金额 |
| 报价 | 对具体模型能力、参数、输入和数量计算的预计积分及确认上限 | 账本变动、采购成本或平台订单价格 |
| 积分批次／来源 | 解释某次积分来自外部成交、运营补发、纠错或未来订单权益的来源信息 | 必须拥有不同兑换价值或不同消费顺序的独立钱包 |

## 7. 关键用户流程

### 7.1 报价、确认与预占

1. M01 汇总用户已选择的工具／模型能力、输入、参数和输出数量；M03 提供当前有效能力快照，M07 计算报价。
2. 报价展示计费单位、预计积分或明确上限、影响价格的主要因素、当前版本和有效期。
3. 输入或关键参数改变、能力／渠道切换、报价规则失效或报价过期时，重新报价；旧确认不覆盖新输入。
4. 用户确认该报价后，M07 按账户状态和可用额度建立该任务的积分预占；余额不足或负余额限制存在时拒绝预占并阻止 M04 调用供应商。
5. M04 仅在收到成功预占事实后继续建立任务；重复确认必须返回原报价／任务结果或安全拒绝，不重复预占。

### 7.2 可靠交付后的实结或释放

1. M04 提供可追溯任务、可靠交付和用户可访问事实；M07 核对该任务对应的原报价、预占和结算幂等标识。
2. 满足 GLB-024 后，M07 将确认的实际积分记为实结消耗；预占高于实结时释放差额。
3. 明确失败或经人工确认最终不可交付时，释放全部预占，不产生本次实际扣分，也不自动赠送补偿积分。
4. 任务状态未知、上游成功但转存未确认、积分交接超时或证据冲突时，保持预占并建立差异待办；不得自动实结或释放。
5. M07 将最终账本结果反馈 M04/M01 和用户明细；M12 通知送达失败不回滚账本。

### 7.3 外部成交后人工积分充值

1. 线下财务／合同／第三方渠道订单确认外部成交后，授权人员在 M11 录入目标用户、积分数量、成交渠道、外部订单号／合同号、凭据、操作人、时间与备注。
2. M11 将经过校验的充值请求和凭据引用交给 M07；M07 检查数量、用户状态、幂等关联和负余额。
3. M07 追加一条积分来源账本事实。若用户有负余额，本次到账先填平欠额，剩余部分才增加可用积分。
4. M07 返回成功／失败账本结果，M11 更新后台操作记录，M12/M13 可按职责接收事件。
5. 发生错误时新增冲正和正确记录；不删除旧记录，不创建平台订单或支付事实。

### 7.4 外部退款与积分扣回

1. 线下财务或第三方渠道先确认退款；授权人员在 M11 登记退款凭据、原外部订单／合同关联、对应积分数量和操作说明。
2. M07 校验是否已处理同一退款／积分扣回请求，并追加相应负向账本事实。
3. 余额足够时扣回；余额不足时保留真实负余额，不强制归零、不删除已使用消费记录。
4. 用户存在负余额时，暂停新的付费生成预占；后续新积分入账优先冲减负余额，之后余额才恢复可用。
5. 产品内不申请或执行资金退款；M07 只记录积分扣回结果。

### 7.5 人工冲正与争议核查

1. 用户通过客服提出异议，或 M07/M04/M11 检测到重复事件、积分不平、未知任务超时等差异。
2. 先由事实主责模块核查：M04 核实任务／交付，M11 核实外部凭据／操作，M07 核算账本。
3. 仅授权积分岗位可发起有依据的补记、释放或冲正；纠正项目引用原条目和处理理由。
4. 核查未完成前不得静默改余额或擅自改变未知任务结论；若需要临时限制新付费生成，应依账户／任务规则说明范围。
5. 完成后给用户提供安全化说明，后台保留操作者、证据引用、时间和处理结果。

### 9.3 状态与账户公式

| 状态／指标 | 定义 |
|---|---|
| 账面余额 | 已入账积分 + 冲正／调整 − 已实结消耗 − 退款扣回 − 已过期；可为负 |
| 预占总额 | 所有未结预占数量之和；不能再次被其他请求使用 |
| 可用积分 | `max(0, 账面余额 − 预占总额)`；账户处于限制状态时即使有可用积分也可能不可新预占 |
| 报价有效 | 报价未过期，能力、输入、参数和规则版本与确认快照一致 |
| 预占中 | 已锁定积分，等待 M04 明确任务／交付事实 |
| 部分释放／部分实结 | 只有报价明示可分割交付单位且 M04 给出可核验单位事实时使用；否则单个任务按整体结算 |
| 已结清 | 该预占已全部实结或释放，结果与原报价规则可核对 |
| 核查中 | 任务或账务事实未知／冲突，预占继续持有并等待人工处理 |

## 12. 页面账单与用户说明

### 12.1 用户侧

- 总览至少区分“可用积分”“任务预占中”“账面余额”；存在负余额时显示欠额和暂停付费生成说明。
- 报价页面标出单位、预计积分／最高确认值、影响因子、规则适用条件和报价有效期；“确认并生成”不得与“查看报价”混淆。
- 账单按业务动作显示正负数量、原因、任务或外部凭据的安全化引用和处理时间。
- 对于预占、释放、实结和冲正分别解释其含义；失败结果不能只显示“积分退回”而隐去任务事实。
- 用户不能看到付款截图等凭据原件、供应商秘密、其他用户账号或内部风控资料。

### 12.2 后台侧

- M11 展示外部成交充值或退款扣回的凭据完整性和操作状态；M07 回传账本处理结果。
- 账本差异页能从任务、预占、实结、释放、外部凭据和冲正引用逐笔追踪，不提供直接编辑余额入口。
- 已确认的线下交易与用户积分变动可对账，但不将积分数量当作现金金额；商品货币售价如未来启用由 M08 提供。
- 成本信息、付款凭据原件和用户任务内容按岗位最小权限隔离。

| 步骤 | 账面余额 | 预占 | 可用 | 说明 |
|---|---:|---:|---:|---|
| 初始 | 1,000 | 0 | 1,000 | 假设初始已入账 |
| A/B/C 分别预占 | 1,000 | 1,000 | 0 | 三个任务独立锁定；同一积分不得重复使用 |

### 算例 B：外部退款扣回造成负余额与后续充值填平

假设用户累计外部成交入账 500 积分，已可靠交付并实结使用 700 积分（其中另有之前入账积分），随后线下确认退款并由 M11 请求扣回 500。

| 步骤 | 账面余额 | 可用 | 说明 |
|---|---:|---:|---|
| 退款扣回前 | 0 | 0 | 已用额度已包含此前余额 |
| 扣回对应 500 | -500 | 0 | 保留负余额，不抹除 700 的历史消费 |
| 后续充值 300 | -200 | 0 | 全部先填平欠额 |
| 再充值 600 | 400 | 400 | 先填平剩余 200，余下 400 成为可用积分 |

账面负余额只限制新的付费生成，不自动封禁浏览、课程访问或账户登录；相关账户治理由 M02/M14 负责。

### 算例 C：同一任务重复回调与冲正

假设某任务预占 250，M04 对同一可靠交付发送两次相同结算事件，实际应结为 210。

| 步骤 | 账面影响 | 预占／可用变化 | 说明 |
|---|---:|---|---|
| 初次预占 | 0（仅锁额） | 预占 250 | 报价确认后发生 |
| 首个可靠交付结算 | -210 | 预占减少 250，释放差额 40 | 结果可访问，按原报价规则实结 |
| 重复相同事件 | 0 | 不变 | 关联原结算，不能再次扣 210 |
| 后续发现首笔记账错误，例如重复实结 420 | 追加 +210 冲正 | 依核查后的正确事实调整 | 不删除历史记录；冲正指向错误条目，重新核对预占状态 |

冲正数值仅演示追加式纠错；任何实际冲正需有权岗位依据 M04/M11 核查结果处理，不由重复事件自动触发。

## 17. 风险、工作默认与非目标

### 17.1 风险与控制

| 风险 | 影响 | 控制 |
|---|---|---|
| 积分被用户理解为现金 | 退款、提现或兑付预期不一致 | 所有用户界面统一标记“积分”，不显示货币符号；说明其用途边界 |
| 报价与上游成本耦合错误 | 价格变动或第三方成本被事后转嫁给用户 | M03/M07 各自主责版本；报价确认上限封顶，成本超差进入内部核查 |
| 并发／重复事件导致多扣 | 用户额度错误、资金争议 | 每任务独立预占、重复识别，差异时暂停自动写账 |
| 结果不可访问但先实结 | 违反用户确认的扣分条件 | M04 可靠交付事实是 M07 实结门槛；存储恢复失败保持待核查 |
| 外部退款和积分扣回映射不清 | 多扣、少扣或对账争议 | M11 记录退款凭据与对应积分，M07 保存原入账引用／处理原因 |
| 后台凭据泄露 | 个人资料、交易编号或支付账号暴露 | M11 限制凭据原件访问；M07 账单只显示安全化引用 |
| 赠送积分到期规则复杂 | 用户误解、余额优先级争议 | 首发不开活动赠点和自动过期；未来引入需另定有效期、扣减和提醒规则 |
| 负余额被误当账户封禁 | 用户无法使用不依赖积分的产品能力 | 仅限制新的付费生成；登录、浏览和课程等由各自权益决定 |

### 17.2 按用户指示采用的工作默认

你已指示未确定事项按建议推进。以下为当前可调整默认，不构成新的已确认商业规则：

1. **积分类型：** 首发只开放外部成交积分包；保留“外部成交、运营纠错、未来赠送、未来课程／订单权益”等来源类别用于追溯，但当前未开放来源不产生余额。来源不同不先拆成多个钱包。
2. **会员／赠点：** 当前不做会员、周期积分或活动赠送。未来是否赠点另行决策，不能用会员话术包装积分包。
3. **有效期：** 首发对已入账积分不自动过期；积分包若将来需设置有效期，必须在成交前明确对用户展示并经目标市场／合规评估。未确定前默认长期有效。
4. **扣减顺序：** 同一可用池内先按最早有效／入账顺序使用；首发没有自动过期批次时即按最早入账批次优先。该顺序只服务对账，不改变用户余额价值。
5. **价格和超额：** 用户确认报价同时确认单任务最高可扣积分；实际结算不超过上限，规则变化不追溯，无法可靠算出上限则不允许提交。超成本部分由平台列为内部差异处理。
6. **计费粒度：** 首发以用户确认的单个生成任务为结算单位；批次内各子任务独立。多输出任务只有在报价时逐项显示且 M04 能提供相应交付事实时才允许部分结算，否则按任务整体处理。
7. **未知任务：** 沿用已确认规则持续预占，直到人工核查后产生明确结果；不设置自动释放期限。
8. **纠错权限：** 不增加双人审批或线上审批流；保留最小岗位授权、操作理由、凭据引用和追加式账本记录。
