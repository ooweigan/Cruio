本文定义工具运行、工作流运行、节点运行和生成任务的业务状态、异常处理、交付门槛、积分联动及验收口径。不选任务队列、数据库、存储方案或供应商 SDK；供应商接入遵循 M03 已确认的官方 SDK／协议基线。

## 1. 模块目标

M04 为每次用户确认的创作执行建立可追踪事实，使任务能够脱离页面和画布继续运行、核查、恢复并可靠交付。用户能理解当前状态、结果是否可访问、积分处于何种阶段以及下一步可采取的操作；运营能定位上游任务、结果转存和积分交接中的异常。

成功意味着：用户刷新、关闭页面或稍后重新登录后仍能查看任务；供应商完成与平台可交付、作品保存、积分结算各自有明确状态；发生未知状态时系统保留原任务和预占，不制造重复调用；最终结果不可访问时可恢复，或经核查后按既定规则释放积分。

## 2. 业务定义与职责边界

### 2.1 M04 主责

- 用户确认报价后的生成请求快照、工具运行、工作流运行、节点运行和任务批次。
- 对外部模型／供应渠道的任务尝试、上游任务标识、供应商原始状态和安全化错误摘要。
- 提交确认、轮询／回调／主动核查结果、取消请求、恢复、结果取得和交付副本状态。
- 任务过程摘要、异常处理记录，以及向 M01、M07、M06、M12、M13 交接事实。

### 2.2 M04 不负责

- M01 负责画布定义、节点布局、连接关系和用户编辑；画布任务卡仅展示 M04 状态。
- M03 负责模型、精确版本、供应渠道、协议兼容映射、能力快照和采购成本参考。
- M05 负责素材、授权和厂商资产身份；M04 按任务快照记录实际引用及校验结果。
- M07 负责报价规则、积分预占、实结、释放和账本。M04 只能发起有据可追踪的结算请求。
- M06 负责用户主动保存后的长期作品、分享和公开发布。任务输出不自动变成作品。
- M11 负责后台入口和权限化待办；客服不得越过 M04 标记成功或改写上游事实。
- M12 负责通知送达；通知失败不回滚任务、交付或账务事实。
- M14 负责授权与安全决定；M04 执行其对新任务或现有任务适用的决定。

### 2.3 执行对象关系

| 对象 | 含义 | 业务关系 |
|---|---|---|
| 生成请求 | 用户确认模型、参数、素材和报价后的执行意图快照 | 一个确认请求可触发一次工具／工作流运行；不得由未确认的页面编辑直接产生 |
| 工具运行 | 对一个工具版本的一次用户确认执行 | 可包含一个或多个节点运行；工具定义属于 M01 |
| 工作流运行 | 用户执行某一工作流定义版本的一次整体过程 | 由一个或多个节点运行构成；引用执行时的定义快照 |
| 节点运行 | 某次工作流中一个可执行节点的一次运行事实 | 可关联一个或多个供应商任务；节点状态不能替代任务状态 |
| 供应商任务尝试 | 对某实际渠道的一次提交或可确认的外部执行 | 保存实际供应渠道和 M03 能力快照；重提会产生新的尝试事实 |
| 交付副本 | 平台已取得、校验并能在承诺范围内向用户提供的结果 | 可靠交付后可供画布继续创作或用户保存为作品 |
| 批次 | 用户一次确认多个相互独立的任务 | 每个子任务有独立状态与积分处理；批次汇总不掩盖部分成功 |

## 4. 范围与分期深度

| 阶段 | 功能深度 | 状态 |
|---|---|---|
| 首发建议 | 报价确认、积分预占、幂等提交、独立任务中心／项目任务列表、视频异步状态、图像同步／流式结果收敛、结果转存校验、页面关闭后恢复、失败／未知处理、人工核查、取消请求、单任务重试和积分闭环 | 建议范围，尚待总基线确认 |
| 下一阶段 | 批次任务、部分成功汇总、工作流运行细节、更多供应商回调、可配置异常队列、批量运营处理、任务影响分析 | 视首发负载与供应商能力决定 |
| 后续阶段 | 大规模并行工作流、自动恢复策略、跨模型多阶段运行、可配置团队级执行配额和更丰富的进度估算 | 完整产品候选，不承诺当前实现 |

首发即使暂不开放批量工作流，也要保留批次对象和各子任务独立结算原则，以免未来批量执行时把部分成功混成整批成功或失败。

## 5. 用户、角色与权限

| 角色 | 允许操作 | 边界 |
|---|---|---|
| 普通创作者／学员 | 查看本人任务、结果和过程摘要；发起确认、取消请求、继续查询、在可重试条件下重新生成 | 仅能访问自己有权访问的项目、任务及结果；重生成可能产生新报价和积分预占 |
| 老师 | 在被授权课程／练习范围内查看运行结果或处理课程内容 | 不得查看学员其他私有项目与任务 |
| 客服 | 按工单关联查看任务的安全摘要、状态和用户可见结果 | 不得查看密钥、任意原始素材或直接更改任务状态 |
| 任务／模型运营 | 查询渠道任务、处理未知状态、申请恢复或完成核查 | 不得伪造供应商成功；结算仍由 M07 负责 |
| 管理员 | 授予受限运营权限、查看必要审计信息 | 管理员身份不自动获得无范围限制的任务内容访问权 |

权限服从 M02、M11、M14 的角色范围和最小披露规则；供应商原始错误、回调内容或素材信息对用户展示前必须去除凭证及无关敏感数据。

## 6. 信息架构与用户操作

### 6.1 用户端／创作台

| 入口 | 核心信息 | 主要操作 | 状态与错误反馈 |
|---|---|---|---|
| 画布任务卡 | M04 最新任务投影、当前状态、结果数量 | 查看详情、继续创作、保存作品、在允许时取消或重试 | 页面重开后刷新真实状态；卡片旧数据标为正在更新 |
| 我的任务 | 最近任务、所属项目／工具、模型展示名、创建时间、状态 | 筛选、打开详情、继续查询 | 不以浏览器会话作为任务生命周期 |
| 任务详情 | 用户请求摘要、参数与素材引用摘要、状态时间线、结果、失败安全说明 | 取消请求、下载／继续使用结果、保存为作品、申请客服协助 | 显示“正在生成／正在保存结果／需要核查”等可理解状态；没有精确进度时不显示百分比 |
| 批次详情（后续） | 批次总体状态及每个子任务结果 | 查看成功、失败、未知子项并分别处理 | 明确部分成功，不提供一个掩盖差异的总成功标记 |

### 6.2 管理后台

- **异常任务待办**：未知、下载失败、回调冲突、长期处理中、无法关联积分或交付验证失败的任务。
- **任务详情**：平台任务标识、用户和项目范围、M03 渠道／精确模型／能力快照、上游任务标识、原始及映射状态、提交与结果时间、交付校验、积分交接回执。
- **受控动作**：重新查询原任务、重新取得同一结果、登记人工核查结论、恢复待办、向 M07 发起释放／结算请求、通知客服或用户。
- 原始请求／响应只对获得专项权限的岗位显示，默认呈现经脱敏摘要；任何后台动作保留操作者、原因和前后状态。

## 7. 关键用户流程

### 7.1 报价确认与任务提交

1. M01 将确定的操作、输入、素材引用、M03 展示模型映射、参数和用户身份交给 M04。
2. M04 形成运行前计划，列出本次执行范围、操作模式、逐项输入版本、具名素材用途、模型／接口、能力快照、预计调用数、候选数量、媒体处理步骤、创作确认点和费用边界。V1 只允许单节点计划；依赖前序结果才能确定的后续步骤不得用虚假总价一次性授权。
3. M04 校验用户权限、资源归属、素材及授权状态、模型能力快照、渠道可用性和必需输入；不满足时返回字段级阻塞原因，尚未预占积分。
4. M07 根据已校验计划返回积分报价；用户确认本次范围与报价。
5. M07 对该任务预占报价积分。只有预占成功，M04 才可进入供应商提交阶段。
6. M04 冻结画布／工作流版本、节点操作、端口解析结果、输入与资产版本、创作要求生效结果、模型能力、实际渠道和报价确认快照，再提交一次任务。收到明确受理后记录上游标识；立即响应图像任务也进入结果取得／交付校验阶段。
7. 如果提交明确在供应商受理前失败，按失败规则释放预占；如果请求超时、连接中断或响应不完整，不能判断是否受理时进入“状态待核查”，保持预占并先查询原任务。
8. M01 显示任务投影。页面退出不停止后台任务；任务返回只写入对应运行和候选记录，不覆盖用户提交后的新草稿。

### 7.2 等待、完成和可靠交付

1. M04 根据 M03 对应渠道能力，通过供应商回调、查询或即时响应更新上游状态；保留原始状态和更新时间。
2. 供应商报告成功后，M04 验证结果引用、数量、格式和可取得性，随后取得结果副本。
3. 下载或转存失败时，任务显示“正在保存结果”或“交付处理中”，继续恢复同一结果；不得立即重跑生成。
4. 只有结果副本通过完整性和用户访问校验后，M04 才确认“可靠交付”。
5. M04 向 M07 发起按实际结果结算的请求；M07 按确认的实际积分实结并释放差额。M04 向 M01 更新结果投影并允许用户继续使用。
6. 用户主动保存时由 M06 创建作品；未保存结果不会自动成为长期作品或公开内容。

### 7.3 失败、未知与恢复

- **明确失败**：供应商给出可确认的最终失败，或核查证明没有成功结果且无法继续恢复。M04 记录安全原因，通知 M07 释放全部预占，向用户说明可否新建任务。
- **状态未知**：供应商是否接单、是否成功或结果是否仍可取得无法确认。任务保留未知／核查状态和积分预占；不自动重提、不实结、不释放。
- **结果下载失败**：优先从同一供应商任务重新查询／下载；不新建生成尝试。若临时 URL 过期，检查供应商是否能重新签发或重新取得。
- **最终无法交付**：经规定的人工核查确认不可恢复后，M04 记录最终无法交付，向 M07 请求释放全部预占；不产生实际扣分，不额外发补偿积分。
- **创建新任务**：仅在原任务被确认最终失败／未受理，或用户明确选择重新创作并重新看到报价后进行。新任务有独立任务尝试和积分预占。

### 7.4 取消请求

1. 用户发起取消请求，M04 显示“正在请求取消”，不先承诺停止供应商执行或自动免单。
2. M04 按 M03 渠道及当前原始状态请求取消或继续查询；不同渠道允许取消的状态可能不同。
3. 只有供应商明确确认取消且确认没有可交付结果时，M04 才将任务映射为已取消，并请求 M07 释放预占。
4. 供应商不支持取消、任务已运行／完成、请求超时或取消结果未知时，继续等待／核查；若结果仍可靠交付，按可靠交付规则结算。

### 7.5 批次与工作流

- 用户确认批次报价时，明确本次子任务数量或最高积分额度；批次不能以一个总预占掩盖不同子任务的状态事实。
- 每个可收费子任务分别预占和结算；无法启动的子项释放其预占；未知子项保留自己的预占。
- 批次完成状态按子任务汇总为全部完成、部分完成、全部失败或仍在处理中／核查中。
- 工作流中前序节点失败时，后续未执行节点不产生生成任务或积分预占；已有成功节点结果保留，不因另一个节点失败而回滚。
- 首发若不提供批次用户入口，批量规则作为下一阶段验收输入，不能用“整批原子成功”替代。

## 9. 业务状态与状态转换

### 9.1 平台任务主状态

| 内部业务状态 | 含义 | 用户可见状态示例 | 积分状态建议 |
|---|---|---|---|
| 待确认 | 已准备请求或报价，但用户尚未确认 | 等待确认 | 未预占 |
| 已预占 | M07 已成功预占，等待提交 | 正在提交 | 已预占 |
| 提交中 | 正在向原定渠道提交，尚无明确受理结论 | 正在提交 | 已预占 |
| 供应商处理中 | 已确认受理，等待上游执行 | 排队中／生成中 | 已预占 |
| 结果取得中 | 上游成功或返回结果，平台正在取得文件 | 正在获取结果 | 已预占 |
| 交付验证中 | 文件已取得，正在验证可访问和完整性 | 正在保存结果 | 已预占 |
| 可靠交付 | 结果副本通过校验，用户可访问 | 已完成 | 请求 M07 实结 |
| 明确失败 | 有证据确认无法完成或交付 | 生成失败 | 请求释放预占 |
| 已取消 | 渠道结果确认取消且无可交付结果 | 已取消 | 请求释放预占 |
| 状态待核查 | 无法确定是否受理、成功、取消或可交付 | 正在核查 | 保持预占 |
| 最终无法交付 | 经核查已确认不能恢复结果 | 无法交付 | 请求释放全部预占 |

“结算中／积分已结算”是 M07 负责的账务状态，可与 M04 可靠交付状态关联展示；M04 不把积分状态写成自己的任务结果。作品是否保存由 M06 单独表达。

### 9.2 转换规则

| 当前状态 | 触发事实 | 目标状态 | 规则 |
|---|---|---|---|
| 待确认 | 用户确认有效报价、M07 预占成功 | 已预占 | 同一报价快照只接受明确用户确认 |
| 已预占 | 发起原定渠道请求 | 提交中 | 产生一个可追溯提交尝试 |
| 提交中 | 明确返回已受理／任务 ID | 供应商处理中 | 保存原始状态与任务 ID |
| 提交中 | 明确未受理且最终错误 | 明确失败 | 通知 M07 释放 |
| 提交中 | 超时、断连、返回不完整，受理不明 | 状态待核查 | 不盲目再次提交，先查同一任务／渠道 |
| 供应商处理中 | 上游明确成功并有结果 | 结果取得中 | 临时链接不能直接作为可靠交付 |
| 供应商处理中 | 最终失败 | 明确失败 | 保存安全错误摘要并通知 M07 释放 |
| 供应商处理中 | 状态无法确认或矛盾 | 状态待核查 | 原始状态保留；预占继续 |
| 结果取得中 | 同一结果成功下载 | 交付验证中 | 下载重试不产生新生成任务 |
| 结果取得中 | 可恢复下载失败 | 结果取得中 | 保持等待或运营核查 |
| 交付验证中 | 文件完整、关联正确且用户访问可用 | 可靠交付 | 允许向 M07 请求实结，允许交 M06 保存 |
| 交付验证中 | 文件损坏、关联错误或访问不可用 | 结果取得中／状态待核查 | 能修复则重取同一结果；不明则核查 |
| 任一可取消状态 | 用户请求取消 | 原状态 + 取消请求中 | 记录取消意图，不覆盖上游状态 |
| 取消请求中 | 供应商确认取消且无结果 | 已取消 | 通知 M07 释放 |
| 取消请求中 | 不支持／拒绝／状态未知 | 原状态或状态待核查 | 按任务真实进度继续，不能自判已取消 |
| 状态待核查 | 查明上游成功且可取回 | 结果取得中 | 沿同一原任务恢复 |
| 状态待核查 | 查明最终失败／未受理 | 明确失败 | 释放预占；新任务需重新报价确认 |
| 状态待核查 | 人工确认永久无法交付 | 最终无法交付 | 记录理由并释放预占 |

禁止将明确的历史状态覆盖成新状态；后续查询可增加状态事实，矛盾或逆序变化应成为异常而非静默回退。

### 9.3 上游状态与用户状态的映射

M03 提供特定渠道的能力和状态语义；M04 映射为平台状态，同时保留上游原始状态。平台不得要求每家供应商必须提供同一组状态、任务百分比、回调或取消能力。

| 上游情况 | 平台处理 | 用户呈现 |
|---|---|---|
| 同步返回完整图像／结果 | 进入结果取得和交付验证 | 正在保存结果／已完成 |
| 流式返回部分图像 | 可作为预览；最终完成事件前不得作为最终交付 | 生成中；可标记预览未完成 |
| 异步 queued／running 等状态 | 映射为等待或生成中并保存原状态 | 排队中／生成中，不展示臆测进度 |
| 上游 success 但结果链接过期／不可取 | 结果取得或核查中 | 正在保存结果／需要核查 |
| 上游 failed／拒绝且结论明确 | 明确失败，错误安全摘要 | 生成失败和可操作建议 |
| 上游状态未知／查询暂不可用 | 状态待核查 | 正在核查，不提示用户重复生成 |

## 11. 异常处理与客服／运营处置

| 异常 | 用户提示 | M04 处理 | 积分／交接 | 是否允许新建任务 |
|---|---|---|---|---|
| 用户重复点击／客户端重发 | 已收到请求，展示原任务 | 返回相同请求对应任务 | 不新增预占 | 用户明确选择重新生成并重新报价后允许 |
| 请求超时，供应商可能已接单 | 正在确认任务状态 | 查原渠道、原请求或可得任务列表；转未知核查 | 保持预占 | 查明未受理或最终失败前不允许自动新建 |
| 页面刷新／关闭／浏览器崩溃 | 任务仍会继续，可在任务页查看 | 恢复最新任务状态 | 不变 | 不自动重提 |
| 回调重复或乱序 | 通常无额外操作 | 去重／按业务状态处理；冲突进入核查 | 不重复结算 | 不因回调异常重提 |
| 服务重启 | 不应丢失已确认任务 | 按持久任务事实继续查询／恢复 | 保持原积分状态 | 不创建重复尝试 |
| 供应商限流 | 暂时无法生成，可稍后查看 | 未受理时可受控恢复；已受理则查原任务 | 未受理按失败释放；受理不明保持预占 | 仅明确未受理后可重提，重新报价规则由 M07 决定 |
| 素材失效／厂商资产不可用 | 素材不可用于当前任务，需更换或重新登记 | 阻止提交或记录供应商拒绝 | 提交前无预占；已提交后的最终失败释放 | 更换素材后需新报价确认 |
| 内容拒绝／审核失败 | 显示安全原因摘要及可调整建议 | 保存原始类别的安全映射，不泄露内部规则 | 最终失败释放预占 | 修改内容后用户可新建任务 |
| 上游完成但下载失败 | 正在保存结果，不要重复生成 | 重新获取同一结果；检查 URL 时效和下载限制 | 保持预占直到交付或最终失败 | 不重跑原生成；永久不可交付后可重新确认创建 |
| 转存成功但画布／通知未更新 | 任务详情显示真实结果 | 修复 M01 投影或 M12 通知交接 | 不改变已实结事实 | 可继续使用已有结果 |
