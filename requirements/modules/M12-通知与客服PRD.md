> 决策状态：通知、工单和客服是横向支撑能力；通知送达不代表业务成功，工单关闭不代表源业务已修复。渠道范围、通知偏好及服务响应目标属于工作建议／待确认。

本文定义服务型通知、用户通知偏好、轻量客服工单、业务核查交接和用户可见的处理进度。当前目标是让用户知道任务、积分和权益发生了什么，并让客服能够沿同一业务事实协助排查；不建设完整营销自动化或外部客服平台。

## 1. 模块目标与边界

### 1.1 目标

- 关键业务状态改变后，通过适当渠道告知用户，并允许用户回到对应任务、账单、课程、素材或作品页面核对真实状态。
- 为用户报告重复扣费、结果未交付、课程未解锁、素材授权争议等问题提供工单入口、关联业务对象和可追踪处理进度。
- 让客服基于授权摘要向事实主责模块提出核查／补偿请求；用户沟通、通知送达和业务事实分开留痕。
- 合并同一任务或批量运行的重复提醒，避免高频进度消息造成打扰。

### 1.2 M12 主责

- 用户服务通知的生成、渠道尝试、送达／失败／阅读状态、模板版本、通知偏好和用户可见通知箱。
- 用户工单、沟通回复、证据补充、转派／升级、处理状态、关联对象和结案／重新开启记录。
- 客服面向各事实主责模块发起处理申请并向用户传递结果；保存用户可见的服务过程。
- 服务通知与营销通知的分类、订阅选择、退订入口和渠道适用工作规则。

### 1.3 M12 不负责

- 不确认任务成功、交付、积分入账／扣回、作品发布、素材登记、课程权益、订单退款或佣金结算；这些状态由对应事实主责模块产生。
- 不代表 M11 管理后台权限、运营配置或财务凭据；后台工单／待办由 M11 提供受控入口，客服权限依 M02/M11 授予。
- 不替代 M14 作授权、内容安全、举报、申诉或隐私治理决定；只接收案件引用并协助用户沟通。
- 不直接访问供应商密钥、内部安全阈值、无关用户资源、任意私人作品或素材原文件。
- 不承诺未经确认的客服响应时限、供应商恢复时间或外部通知渠道送达率。

### 1.4 统一对象区分

| 对象 | 含义 | M12 处理方式 |
|---|---|---|
| 业务事件 | M02/M04/M05/M06/M07/M08/M09/M10/M14 等模块确认的状态事实 | 作为通知触发依据；M12 不以用户消息或第三方送达回执改写事件 |
| 通知 | 对特定用户或岗位发送的状态摘要／行动提示 | 独立记录内容版本、接收者、渠道尝试、送达／失败／阅读；失败不回滚业务 |
| 用户偏好 | 用户对可选择通知类别／渠道的设置 | 不覆盖法律、安全或必要服务消息的适用规则；不得把偏好解释为业务操作撤回 |
| 工单 | 用户与客服之间的服务处理过程及一个或多个业务关联 | 工单状态属于 M12；关联任务／账本／订单状态仍属于各源模块 |
| 处理申请 | 客服向事实主责模块提出的核查、恢复或补偿请求 | 只有源模块确认结果后，客服才可将结果表述为已完成 |

## 2. 服务对象与权限

| 用户／角色 | 主要任务 | 可见范围与限制 |
|---|---|---|
| 游客 | 查看公开服务说明、联系客服入口 | 不可查看账户通知、私有任务或未登录工单历史；身份核验后方可访问账户特定事项 |
| 普通用户／学员／创作者 | 查看本人服务通知、调整可选偏好、创建工单、补充材料、追踪并回复工单 | 仅访问本人通知、本人资源关联工单及被明确授权的共享事项 |
| 推广者 | 查询本人推广归因／佣金相关通知并提交争议工单 | 不可查看其他推广者、被推荐人的个人资料或交易凭据 |
| 客服 | 根据工单查看最小必要摘要、沟通、转派、催办事实主责模块 | 不可明文查看供应商 Key、任意私人作品／素材、完整支付凭据或直接改业务状态 |
| 业务处理岗位 | 接收与自身模块有关的核查请求，提供事实主责模块的处理结果 | 仅查看对应对象与授权字段；不能查看工单中无关的用户材料 |
| 安全／隐私岗位 | 处理 M14 案件关联、授权撤回、举报和隐私请求 | 仅在案件授权范围访问必要证据；M12 不展示超出案件处理需要的材料 |

用户与客服之间的附件、回复和内部备注必须区分受众。内部备注不能意外展示给用户；用户附件也不能默认被所有后台岗位查看。

## 3. 通知渠道与偏好

### 3.1 渠道工作默认

| 渠道 | 工作默认 | 适用限制／待确认 |
|---|---|---|
| 站内通知／通知箱 | 首发建议优先支持；用户可在产品内回看关键通知 | 需提供未读／已读状态和关联业务页；不得因用户未读而隐藏业务真实状态 |
| 邮件 | 可选扩展，用于账户、任务或重要服务通知 | 用户邮箱验证、退订和目标市场规则待 M02/M14 确认；非关键消息不默认开启 |
| 短信 | 不作为默认首发渠道 | 涉及成本、用户同意、号码验证与市场规则；须单独确认必要场景与供应渠道 |
| 浏览器推送／其他即时渠道 | 后续候选 | 依赖明确权限、用户场景与通知频控设计，不默认订阅 |

站内通知作为工作基线；邮件、短信等只有在渠道、用户授权、模板内容和合规要求核清后才可启用。渠道发送失败时，用户仍可在对应业务页看到源模块状态。

### 3.2 服务通知与营销通知

| 类别 | 内容示例 | 偏好规则工作建议 |
|---|---|---|
| 关键账户／安全服务通知 | 账户安全状态、隐私请求处理、需要用户采取行动的授权／安全决定 | 必须依适用规则和必要性分类；不得用营销退订选项误导用户以为可停止安全信息 |
| 交易／权益服务通知 | 积分到账／扣回结果、未来订单及退款处理、课程权益发放／失效 | 只在对应业务事实确定后发送；服务渠道和必要通知依据由市场／隐私评审确认 |
| 任务／交付服务通知 | 已可靠交付、明确失败、未知状态需核查、结果可访问 | 通知用语必须区分供应商成功、交付成功和积分实结；未知状态不能写成功／失败定论 |
| 内容／资产服务通知 | 厂商资产登记失败／失效、作品审核、授权撤回、内容下架 | 展示安全化原因与处理入口，不暴露审核阈值、他人举报身份或敏感资料 |
| 营销／活动通知 | 新功能、课程推荐、活动或商业推广 | 独立于服务通知分类和订阅；未确认营销授权前默认关闭／不发送；提供清晰退订入口 |

### 3.3 偏好设置

- 用户可按可选通知类别和支持渠道配置偏好，查看最近修改时间；渠道未启用时不展示虚假开关。
- 服务通知偏好与营销偏好分开；关闭营销通知不得影响用户查看站内业务状态。
- 用户取消邮件／短信营销订阅后，相关营销渠道不得继续发送；站内是否保留营销内容另按市场规则确认。
- 账户注销、停用、封禁或退订后，对待发送队列重新核对账户状态、接收资格、服务必要性和渠道权限；不得把已排队等同于已发送。
- 用户偏好变更只影响生效后的通知尝试，不改变过去的业务事件或已经合法送达的消息历史。

## 4. 事件 × 通知矩阵

“建议”仅表示工作默认；任何外部渠道启用前需确认用户场景、授权、模板和渠道规则。高频状态更新以通知箱／业务页为主，通常不逐个发送邮件／短信。

| 源业务事件 | 用户可见内容／推荐动作 | 推荐通知级别与渠道 | 合并／避免重复 | 事实主责 |
|---|---|---|---|---|
| 生成任务已提交／长时间处理中 | 任务已提交、可离开页面，提供任务页；未知状态明确说明正在核查 | 站内通知或画布任务状态；长时间等待是否主动提醒待设目标 | 同一任务状态合并，只保留最新摘要；不每次轮询通知 | M04 |
| 生成结果已可靠交付且可访问 | 提供结果入口，并显示积分结算状态（可能仍在确认） | 站内；邮件为可选 | 同一任务只发一次关键交付通知；重复回调不重复提醒 | M04；积分结果由 M07 |
| 生成明确失败／最终无法交付 | 说明任务失败／结果不可交付、积分预占如何处理及查看账单入口 | 站内关键服务通知；邮件候选 | 同一任务失败重试／恢复过程合并，不覆盖早前状态 | M04 与 M07 各自事实 |
| 任务长期未知、需人工核查 | “状态仍在核查”，告知积分继续预占、不自动重提及后续联系入口 | 站内；是否提醒节奏待确认 | 同一任务重复核查不重复推送；状态变化时更新原通知或发关键更新 | M04/M07；M11 承接人工待办 |
| 余额不足／预占失败 | 无法提交任务、当前可用积分及补充额度入口（当前外部渠道说明） | 提交时界面即时反馈；站内通知可选 | 同一提交失败不额外批量通知 | M07 |
| 外部积分人工入账／退款扣回结果 | 显示实际账本动作、积分数量／余额变化、安全化来源摘要；扣回形成负余额时说明生成限制 | 站内；关键额度变化可提示 | 同一 M07 账本事实去重；不得由 M11 登记事件提前发“已到账” | M07；M11 提供凭据关联 |
| 未来订单支付／权益发放／退款变化 | 分开呈现真实支付状态、积分／课程权益到账和退款／回收结果 | 当前关闭；未来站内及按适用市场启用的渠道 | 一个订单按权益差异合并摘要，失败补发单独跟踪 | M08 与 M07/M10/M09 分责 |
| 课程权益授予／失效／撤销 | 课程可访问范围、有效期和处理入口；退款／下架的依据说明 | 站内；邮件候选 | 同一课程同一批变更合并；不把课程权益当积分 | M10 |
| 厂商资产登记失败／可用／失效 | 指定资产状态和对现有练习／任务的影响、替换或核查入口 | 站内项目内提示；高影响失效可主动提醒 | 以资产与项目／任务影响合并；不对每个引用重复发送 | M05；治理限制由 M14 |
| 作品审核／公开／拒绝／撤下 | 公开范围、审核结果安全化摘要和修改／申诉入口 | 站内关键内容通知 | 每个发布记录按状态变化通知；批量治理时汇总但保留各作品链接 | M06/M14 |
| 佣金归因／冻结／未来结算 | 只向推广者显示本人归因或佣金状态与申诉入口 | 当前不发送平台佣金通知；未来站内 | 同一规则周期汇总，个人明细仍可查 | M09；订单事实由 M08 |
| 工单状态／客服回复 | 编号、状态、待用户补充或处理结果摘要及工单链接 | 站内；邮件是否可选待确认 | 连续内部更新聚合；用户需行动或结案时主动通知 | M12 |
| M14 授权／举报／隐私决定 | 仅发送用户身份核验后可见的决定摘要、影响和申诉路径 | 站内关键通知；额外渠道依规则 | 避免在标题或锁屏泄露举报、侵权或敏感隐私内容 | M14 决定，M12 沟通 |

通知生成规则：只有源模块已确认的状态变化可触发结果通知；“请求已提交”只能说明请求记录成功；“消息已发送／送达／已读”是 M12 状态；都不能替代源业务状态。

## 5. 通知功能与状态

### 5.1 用户通知箱

| 需求 ID | 通知需求 | 优先级 | 依赖 |
|---|---|---|---|
| REQ-M12-001 | 支持站内通知列表、已读／未读、类别筛选、时间和关联业务对象跳转 | P0 | M02、源业务模块 |
| REQ-M12-002 | 通知内容显示源业务事件的安全化摘要、事件时间、通知生成时间和当前业务页入口 | P0 | 源事实主责模块 |
| REQ-M12-003 | 展示通知生成、排队、渠道尝试、失败／送达／阅读等不同状态，不合并成“处理成功” | P0 | GLB-036 |
| REQ-M12-004 | 同一业务对象高频进度变化可合并或仅更新通知摘要；关键最终状态与待用户行动事件不得被静默吞并 | P0 | M04、M05、M07、M10 |
| REQ-M12-005 | 通知跳转前重新校验用户身份、源资源所有权及当前权限；通知链接不授予额外访问权 | P0 | M02、M14；GLB-001、002 |
| REQ-M12-006 | 支持按用户类别与渠道记录服务／营销偏好；营销偏好与必要服务通知分别控制 | P1 | M02、M14 |
| REQ-M12-007 | 用户退订营销渠道后按适用规则停止该渠道营销通知，并显示偏好已更新结果 | P1 | M02、M14 |
| REQ-M12-008 | 支持站内、邮件、短信等渠道按阶段启用；未配置／未核验渠道不能展示为可用 | P1 | M02、M14 |
| REQ-M12-009 | 渠道失败后不改变业务状态，并允许在业务页重新查看真实状态；可按策略重试通知但须避免重复提醒 | P0 | 所有源模块；GLB-036 |
| REQ-M12-010 | 通知模板有类别、版本、适用受众和生效范围；修改文案不能改变历史事件或追溯文本版本 | P1 | M11 |
| REQ-M12-011 | 通知正文与标题不暴露供应商密钥、原始安全错误、私有素材、他人资料、举报人身份或不必要的敏感信息 | P0 | M02、M03、M14 |
| REQ-M12-012 | 账户状态变化／注销后，待发通知重新核验可发送资格、必要性和接收渠道；营销发送遵循用户退订状态 | P1 | M02、M14 |

### 5.2 通知状态

| 状态类别 | 状态 | 含义 |
|---|---|---|
| 通知内容 | 已生成、已更新、已合并、已取消 | M12 根据源事件形成的通知对象状态 |
| 渠道尝试 | 未发送、排队中、发送中、已提交渠道、已送达（渠道可确认时）、失败、已抑制 | 不同渠道可提供不同粒度；不能伪造渠道没有返回的送达确认 |
| 用户阅读 | 未读、已读 | 用户在站内查看的交互事实；不表示接受业务结论或放弃申诉 |
| 业务状态 | 由各事实主责模块定义 | 通过通知引用展示；不会随消息状态改变 |

若邮件／短信供应渠道无法确认最终送达，只能展示“已提交发送”或“状态未知”，不能写“对方已收到”。通知重试须限于同一通知事件和可核查渠道结果，避免重复发送造成骚扰。

## 6. 客服工单与服务工作流

### 6.1 工单创建与用户流程

1. 用户从帮助入口或相关任务／账单／课程／素材／作品页面发起问题；关联业务对象在用户权限允许时自动带入，用户可补充描述与证据。
2. 创建前提示不要上传密码、供应商密钥、银行卡信息、无关身份证件或他人隐私；附件按类型和访问权限提示。
3. 提交后获得工单编号、当前状态和更新时间；创建成功不代表源业务已修复。
4. 用户可在本人权限范围查看客服回复、补充材料、确认问题仍存在或申请复核；内部备注不可见。
5. 结案须说明处理结果、源模块结果引用或无进一步行动原因；用户仍可在配置的期限／条件下重开，具体期限待确认。

### 6.2 工单分类与关联对象

| 分类 | 主要关联对象 | 默认责任队列／交接 |
|---|---|---|

### 6.4 证据、回复与内部处理

- 工单附件需标注提交者、提交时间、用途和访问受众；支持用户撤回尚未被正式引用的材料请求，实际删除仍按 M14 保留与隐私规则处理。
- 客服记录用户陈述为“用户报告”，不能把用户陈述直接改成供应商成功、重复扣费、侵权或已退款事实。
- 内部备注仅向被授权员工可见；用户回复需由客服选择明确的安全化摘要，不自动把内部运营讨论复制给用户。
- 转派时保留工单编号、用户已提交信息和处理历史，但新队列只可见完成该项工作所需材料。
- 同一问题重复提交时可建议合并至主工单；用户仍可看到关联状态，不能因此丢失不同任务／账本对象。
- 补偿必须是“补偿申请”或“补偿已由源模块执行”的不同状态。客服不能口头承诺积分、退款、佣金或课程权益已到账。

### 7.2 升级路径

1. **常规服务问题：** 客服先核对账号身份和关联对象 → 根据类别转给源业务模块 → 源模块确认事实／处理结果 → 客服向用户解释 → 用户确认或按条件结案。
2. **重复扣费／积分风险：** 客服立即标记财务敏感问题 → M04 核查任务尝试与交付、M07 核对账本及预占；如涉及外部付款凭据则转有权限财务岗位 → M07 负责账本更正／释放／实结结果 → 客服只传达 M07 确认事实。
3. **未知任务状态：** 转 M04/M11 人工核查队列；告知用户积分仍预占、不自动再次提交、不判成功／失败；只有 M04 最终核实且 M07 处理后更新用户通知。
4. **素材侵权／作品举报／隐私请求：** 转 M14 案件；M05/M06 提供对象状态并执行授权决定；客服只提供 M14 允许披露的状态和申诉方式。
5. **课程权益或案例问题：** 当前由 M10 核查人工授予记录、课程状态、课件／案例授权；涉及未来支付时另由 M08 核支付，不能将任一侧“成功”当作另一侧已完成。
6. **推广归因争议：** 当前外部合作／打款在线下确认；若未来平台佣金启用，M09 核归因和佣金状态、M08 核真实订单、M14 处理风险／申诉。
7. **紧急服务中断：** 客服创建高优先级工单并通知 M11 值班岗位；源模块负责人确认停用／恢复和受影响业务；通知由 M12 发送，不以通知送达证明恢复完成。

### 7.3 响应时限与服务目标

目前没有用户确认的客服人员规模、服务时段或响应时限依据。因此不设虚假的 SLA 数字。可在试运行时记录首响时间、用户等待时长、转派次数、解决时间及重开率，形成实测基线后再确定目标。紧急程度可先采用“普通／影响付费生成／安全隐私／系统范围中断”的相对分类，但通知承诺和升级值班安排仍待运营确认。

## 10. 订阅、退订与内容保留

- 服务通知按用户场景、必要性和适用规则分类；营销通知与服务通知分开管理。对未经确认的渠道，不假设用户同意，也不主动启用。
- 退订渠道只对该渠道／类别的可选通知生效；账户安全和重要业务告知如何适用，由 M14 根据目标地区和必要性评审，不能在本 PRD 中作法律结论。
- 工单结束后，用户只能通过账号登录查看本人记录；账户停用／注销后的访问方式、工单与附件保留期限待 M14 确认。
- 附件删除、匿名化或限制访问走 M14 隐私治理；M12 保留足以说明服务处理结果的最小必要引用，不以留存客服记录为由无限保存原始个人资料。
- 用户撤回对营销通知的订阅，不影响已有工单处理；用户关闭站内通知提示，也不改变任务、账本、订单、作品或课程事实。

## 13. 风险、工作默认与待确认事项

### 13.1 风险与控制

| 风险 | 影响 | 控制 |
|---|---|---|
| 通知先于源模块事实发送 | 用户认为结果已交付／扣费／退款，而源模块仍处理中 | 只消费源模块确认事件；通知摘要清楚区分提交、处理中和最终状态 |
| 高并发任务产生通知轰炸 | 用户关闭通知或错过重要结果 | 按业务对象合并高频更新，关键结果和行动提醒单独保留 |
| 工单客服越权 | 直接改积分、判定侵权或解锁课程，破坏事实追溯 | 工单只向主责模块发起申请；客服仅引用确认结果 |
| 工单材料暴露过多隐私 | 截图、作品或举报材料进入无关队列 | 上传前提醒、受众标记、附件最小可见范围和敏感访问留痕 |
| 营销与服务通知混为一类 | 用户退订后继续收到广告或错过必要服务事项 | 独立类别、偏好、模板与退订逻辑；适用范围由 M14 核验 |
| SLA 被误读为承诺 | 早期小团队无法兑现固定响应时限 | 先测量实际首响／处理数据，再由运营批准目标；不在本版虚构数字 |
| 外部渠道回执不准确 | 将“渠道已接受”宣传为“用户已收到” | 状态按渠道可确认粒度展示；未知／未确认不标记送达 |

### 13.2 待确认事项

1. **首发通知渠道。** 建议首发仅站内通知；邮件、短信分别核实用户场景、验证／授权和市场规则后再启用。
2. **服务通知类别与退订适用规则。** 由 M14 结合目标地区确定安全、交易、内容治理和营销通知的必要性、退订入口与留存方式。
3. **客服服务时段、首响／解决目标和紧急升级联系人。** 当前缺乏用户量、团队排班和实测数据；先记录基线，不填未经验证的 SLA。
4. **工单重开窗口及附件保留期限。** 建议保留可申诉／补充入口，期限和隐私删除策略由 M14 与运营评审。
5. **批量任务的通知合并粒度。** 建议单个工作流／批次合并进度、保留每个子任务最终结果索引；需结合实际画布批量体验评审。
