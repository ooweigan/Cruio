## 2. 模块目标

### 2.1 服务对象

- 普通创作者：只看到当前真正可用、与输入匹配的展示模型和参数，并理解必要限制。
- 模型／供应商运营：维护厂商、渠道、模型映射、能力、可见范围、渠道状态和变更记录。
- 财务／成本运营：查看受限的采购成本参考、余额或额度摘要，不接触无关用户素材和任务内容。
- 客服：查看任务使用的渠道、能力快照和已知事故摘要，不接触秘密凭证。
- 权限管理员／系统管理员：管理凭证账户的访问权限和紧急停用，但不因此自动修改模型业务事实。
- M01、M04、M05、M07、M13：消费本模块已发布、可追溯的模型渠道能力事实。

### 2.2 要解决的用户任务

1. 创作者能够按生成场景选择模型，而不是猜测营销名称、渠道别名或隐藏限制。
2. 画布能够根据当前模型渠道能力只显示有效参数和输入方式。
3. 提交生成前，系统能够确认展示模型映射到哪个精确模型版本、供应渠道和凭证账户。
4. 已提交任务能够追溯原渠道和能力快照，即使之后模型下架、参数变化或渠道异常。
5. 模型运营能够上架、灰度、暂停、下架模型渠道映射，并知道哪些项目、模板、课程和任务受影响。
6. 渠道余额不足、限流、凭证失效或供应商事故时，运营能够停止新提交并向 M04/M12 提供明确事实。
7. 成本运营能够维护采购成本参考版本，M07 能据此计算用户报价，但两者不混成一套价格。
8. 同一展示模型存在多个渠道时，系统能够说明能力差异、资产兼容性和路由规则，不能把自动换渠道当作无成本重试。

### 2.3 成功定义

- 用户界面出现的每个可执行模型都能追溯到已发布的“展示模型—渠道—精确版本—能力快照”。
- 不支持的输入、参数、厂商资产或任务操作不会被错误展示为可用。
- 已提交任务始终保留原模型、渠道、凭证账户引用、能力快照和成本参考版本。
- 渠道切换不会默认为素材 ID 通用，也不会在原任务状态未知时自动重复提交。
- Toonflow 的 provider 外壳、模型选择和参数描述得到复用，但其本地凭证、内部轮询和聚合渠道名称不被当作 Cruio 已完成的 SaaS 运营能力。
- 采购成本、用户积分报价和未来商品货币价格分别由 M03、M07、M08 主责，任何一方变化都不改写历史事实。

## 3. 定向调研

### 3.1 取证口径

1. 外部能力只采用模型厂商官方文档、官方 API 文档和固定仓库源码；第三方聚合渠道只证明该渠道自己的声明或适配代码存在。
2. 许可证、代码路径和模型服务条款分别判断。Toonflow 为 MIT 不代表其聚合渠道、模型服务或素材可无条件使用。
3. 模型展示名、系列名、精确模型 ID、固定快照和渠道别名必须分别记录。
4. 未通过本项目采购账号验证的地区、额度、价格、限流、成功率、回调和资产权限均标记待核验。
5. 本轮未执行付费调用、生产账号操作、真实素材登记或余额充值。

### 3.1.1 已确认的渠道接入基线

1. 每个模型的默认接入路径采用对应厂商官方 SDK 和官方协议，官方渠道是采购与生产接入的默认选择。
2. BaseURL 只负责指定兼容官方协议的服务地址；更换 BaseURL 不代表第三方渠道已经具备官方能力、授权、计费、模型版本或结果语义。
3. 如果供应商的请求、鉴权、任务状态或响应格式与官方协议不同，可在服务端供应商适配边界增加兼容层。兼容层负责转换外部差异，并向平台应用层保持官方协议对应的语义和结果约定。
4. 模型目录仍需记录实际供应商、渠道、精确模型 ID、凭证账户、能力快照和成本事实。兼容层不能隐藏实际渠道，也不能把未验证能力包装为官方能力。
5. Toonflow provider 和现有第三方聚合渠道代码仅作为实现参考或后备适配来源，不作为默认首发采购路径。

### 3.6 调研结论

1. Toonflow 的 provider、模型选择、参数描述、参考媒体转换和结果落盘值得直接复用，不需要为了“统一架构”重写全部适配器。
2. 当前 provider 合同只返回最终媒体，不能向平台任务层交付原始任务 ID 和供应商状态，因此必须与 M04 的持久任务语义重新衔接。
3. 代码中出现模型名只能视为渠道映射候选；正式上架需要“厂商—渠道—凭证账户—精确版本—能力快照—成本参考”全部完成核验。
4. 接入默认遵循厂商官方 SDK／协议；协议不兼容由服务端兼容层收敛到应用层使用的官方协议语义。实际服务方、能力、素材 ID、审核规则、结果链接、状态、价格和服务条款仍需分别记录与核验。
5. 本轮不决定首发最终模型清单，不填未经采购账号验证的价格与限额。

## 4. 范围、边界与功能树

### 4.1 本模块负责

- 模型厂商、模型系列、展示模型和精确模型版本目录。
- 供应渠道、凭证账户、地区／权益／额度摘要和渠道状态。
- 展示模型与渠道精确版本的模型渠道映射。
- 生成场景、输入模态、参考类型、参数、任务形态、厂商资产兼容性和结果约束的能力快照。
- 模型和渠道的草稿、验证、上架、限量、暂停、下架与退役。
- 用户可见范围、场景可见范围和渠道选择政策。
- 采购成本参考版本、余额／额度告警和成本变更记录。
- 渠道健康、限流、余额不足、凭证失效、区域不可用和供应商事故摘要。
- 能力变更、渠道停用和模型退役的受影响对象查询。
- 凭证账户的业务归属和访问权限；秘密值本身按最小权限保护。

### 4.2 本模块不负责

- 不执行或持久化生成任务、重试、取消、未知状态和交付副本（M04）。
- 不保存用户私有素材或厂商资产实例、Asset ID 和登记状态（M05）。
- 不定义用户积分售价、预占、实结、退回或账本（M07）。
- 不定义未来商品货币价格、订单、支付或退款（M08）。
- 不拥有后台待办或操作入口外壳（M11），但主责模型、渠道和能力事实。
- 不拥有客服工单（M12）或报表指标（M13）。
- 不替代 M14 的内容安全、真人授权、地区法规与供应商政策决定。
- 不把 provider 文件、任务队列、密钥存储或路由代码当作业务模块。

### 5.2 凭证权限原则

1. 凭证账户是平台采购身份，不是普通用户账户，也不是一个 API Key 字符串。
2. 普通创作者、客服、老师、分销者和无关运营不得查看秘密凭证。
3. 模型运营可选择已授权凭证账户和查看脱敏状态；查看或更换秘密值需更高的受控权限。
4. 停用凭证账户不得删除使用该账户的历史任务、成本和事故事实。
5. 凭证所属地区、权限、额度和状态是能力的一部分；更换凭证后必须重新验证渠道映射。

## 6. 信息架构与页面

### 6.1 用户侧模型选择

用户侧不要求独立“模型商城”。M01 画布中的模型选择器消费 M03 已发布信息，至少展示：

- 展示模型名、适用场景和简短能力说明；
- 当前输入是否兼容及缺失条件；
- 可选参数、组合限制和厂商资产要求；
- 当前可用、暂不可用、即将退役或仅限特定范围等状态；
- M07 提供的预计积分，而不是 M03 的采购成本；
- 会显著影响结果、授权或素材登记的渠道差异。普通情况下不向用户暴露内部渠道 ID 和凭证账户。

空态必须说明是“没有已核验可用模型”“当前输入不兼容”还是“渠道暂不可用”，不能统一显示为加载失败。

## 7. 关键用户流程

### 7.1 新增模型与渠道

1. 模型运营登记模型厂商、系列、展示候选和供应渠道。
2. 登记凭证账户的业务归属、地区、权限、额度摘要和责任人；秘密值只由有权人员处理。
3. 建立渠道下的精确模型版本，不以展示名或 Toonflow 代码标签代替。
4. 根据官方证据和受控验证建立能力快照，记录证据日期与未知项。
5. 建立模型渠道映射，配置参数白名单、用户范围、场景范围和成本参考。
6. 完成非付费资料审查与必要的受控实测后，映射才可进入已验证。
7. 发布时通知 M01、M04、M05、M07；未完成项保持关闭，不以“先展示再说”代替核验。

### 7.2 创作者选择并提交模型

1. M01 提交当前场景、输入类型、素材／厂商资产引用和用户范围。
2. M03 返回兼容且当前可用的展示模型、参数和必要限制。
3. 用户选择展示模型；平台按已发布路由政策解析一个可执行渠道映射。
4. M07 基于选定能力、参数和成本／报价规则产生预计积分。
5. 用户确认报价后，M04 固定精确模型、渠道、凭证账户引用、能力快照和报价版本再提交。
6. 从该时点起，M03 后续上下架不得改写已提交任务的原渠道事实。

### 7.3 渠道异常与提交前切换

1. 渠道出现凭证失效、余额不足、限流或供应商事故，M03 将其置为受限、异常或暂停新提交。
2. 尚未提交的请求可重新解析其他已核验且输入、参数、资产均兼容的渠道。
3. 如切换改变参数、预计积分、授权或资产登记要求，必须重新展示差异并由用户重新确认报价。
4. 没有等价渠道时停止提交，提供稍后重试、修改输入或选择其他展示模型的路径。
5. M12 可发送事故通知，但通知失败不改变渠道和任务事实。

### 7.4 已提交任务状态未知

1. M04 已经取得原渠道任务事实，但无法确认最终状态。
2. M03 提供该渠道当前状态、查询能力和事故信息，不修改任务状态。
3. 系统不得自动换渠道重新提交，也不得把“另一个渠道可用”当作原任务失败。
4. 积分继续保持预占，由 M04/M07/M11 按 GLB-025 人工核查。
5. 只有原任务最终失败或经核查确定未形成可交付结果后，才可按新请求、当前能力和新报价重新提交。

### 7.5 能力变化影响旧项目、模板与课程

1. 运营建立新能力快照，不覆盖已发布旧快照。
2. 系统列出引用旧模型渠道映射的项目、模板、课程练习和未提交草稿摘要。
3. 已提交历史任务继续按原快照解释；不自动迁移。
4. 未提交项目重新打开时显示“原模型仍可用”“参数需调整”“需重新登记资产”或“模型已退役”。
5. 模板／课程维护者可以选择兼容替代项并重新发布；普通用户的私有项目不得被后台静默改写。

### 7.6 厂商资产与渠道切换

1. M05 提供用户厂商资产的所属渠道、精确资产标识和当前可用状态。
2. M03 判断目标模型渠道映射是否接受该资产类型。
3. 同厂商不同渠道或同展示模型不同渠道都不得默认复用资产 ID。
4. 需要重新登记、授权或审核时，提交前明确告知并交给 M05 处理。
5. 旧渠道资产继续保留其历史关系，不因新渠道登记成功而覆盖。

### 7.7 成本参考变更

1. 成本运营登记新采购成本来源、单位、币种、税费说明和生效时间。
2. 新版本经有权限人员发布后，M07 才可将其作为新报价输入。
3. 已确认报价和已提交任务继续引用原版本；不追溯改价。
4. 成本变化不自动等于用户积分价格变化，更不修改未来商品货币价格。

### 7.8 凭证账户停用或人员离岗

1. 有权人员停用凭证账户或撤回操作人员权限前，查看受影响渠道映射和运行中任务。
2. 停止新的渠道选择；运行中任务由 M04 按原任务能力查询和核查。
3. 如需换用另一凭证账户，先重新验证地区、权限、额度和模型能力，再发布新映射版本。
4. 历史任务继续保留原凭证账户引用的受控标识，不保留可泄露的秘密值。

## 9. 业务对象与状态

### 9.1 主责业务对象

| 对象 | 业务定义 | 重要属性语义 |
|---|---|---|
| 模型厂商 | 对模型或云服务承担官方发布责任的主体 | 官方名称、来源、政策／地区摘要 |
| 模型系列 | 用于认知的一组相关模型 | 系列名、说明、与精确版本关系 |
| 展示模型 | 面向用户的一项产品化选择 | 用户名、场景、说明、生命周期、可见范围 |
| 精确模型版本 | 渠道实际接受的模型 ID、固定快照或等价标识 | 渠道内 ID、版本阶段、厂商归属、适用日期 |
| 供应渠道 | 平台实际采购和调用模型的来源 | 官方／聚合性质、地区、状态、责任人 |
| 凭证账户 | 平台访问渠道的采购账户身份 | 脱敏别名、地区、权限、额度摘要、状态；不等于秘密值 |
| 模型渠道映射 | 展示模型到某渠道精确版本的可执行关系 | 渠道、凭证账户、能力快照、成本版本、可见范围、状态 |
| 能力快照 | 特定时点的输入、参数、任务、资产和输出能力 | 证据、实测、未知项、生效范围、历史只读 |
| 参数规格 | 某能力快照允许的参数和组合约束 | 名称、选项、默认值、条件、互斥关系、用户说明 |
| 采购成本参考 | 某渠道精确版本在一定范围内的成本依据 | 单位、币种、税费说明、来源、生效／结束时间 |
| 渠道事故 | 渠道能力异常及影响范围事实 | 类型、范围、开始、状态、恢复、说明 |
| 变更记录 | 模型供应事实的变化链 | 目标、操作者、原因、前后版本、结果 |

### 9.2 模型渠道映射状态

| 状态 | 含义 | 是否可用于新提交 |
|---|---|---|
| 草稿 | 正在录入，证据与能力未完成 | 否 |
| 待验证 | 配置已具备但尚未完成必要验证 | 否 |
| 已验证 | 能力和凭证通过受控验证，尚未对用户发布 | 否 |
| 已上架 | 对指定范围可见并可用于新提交 | 是 |
| 限量 | 只对指定用户、场景或额度开放 | 仅范围内 |
| 已暂停 | 因事故、额度、凭证或运营决定停止新提交 | 否；历史任务保留 |
| 已下架 | 不再向用户展示，不接受新提交 | 否；旧项目显示替代说明 |
| 已退役 | 版本生命周期结束，仅供历史追溯 | 否 |

### 9.3 渠道状态

| 状态 | 含义 | 产品行为 |
|---|---|---|
| 待配置 | 缺少可用凭证账户或必要权益 | 不可验证或提交 |
| 验证中 | 正在核验渠道、凭证和模型能力 | 仅运营可见 |
| 可用 | 当前证据与状态允许新提交 | 按已发布映射使用 |
| 受限 | 限流、余额、额度、地区或部分能力受限 | 只允许明确仍可用范围 |
| 异常 | 出现系统性错误或供应商事故 | 暂停受影响新提交，通知相关模块 |
| 状态未知 | 无法取得可靠状态 | 不宣称可用；按风险暂停或限量 |
| 已暂停 | 人工停止新提交 | 历史任务继续核查 |
| 已退役 | 渠道不再使用 | 只保留历史追溯 |

### 9.4 凭证账户状态

| 状态 | 含义 | 对映射的影响 |
|---|---|---|
| 待验证 | 账户已登记但权限、地区或额度未确认 | 不可发布 |
| 可用 | 可支持已核验映射 | 可参与提交前路由 |
| 预警 | 余额、额度、到期或安全风险接近阈值 | 提醒运营，可限制新提交 |
| 不可用 | 凭证失效、无权限、余额耗尽或被停用 | 关联映射停止新提交 |
| 已撤销 | 不再允许平台使用 | 只保留历史受控引用 |

### 9.5 非主责投影

- M04：任务提交、供应商原始任务状态、失败／取消／未知和交付结果；
- M05：用户厂商资产实例、Asset ID、授权与可用状态；
- M07：用户报价、积分预占、实结和退回；
- M11：运营待办和后台工作台；
- M13：成本与任务汇总指标；
- M14：政策、授权和治理决定。

### 9.6 节点创作要求的能力表达

M01 保存用户希望获得的创作要求和来源，M03 负责判断这些要求在当前模型、渠道、精确版本、账号和操作模式中如何表达。能力快照对每项要求采用以下四类结果：

| 表达方式 | M03 负责的事实 | M01/M04 的使用方式 |
|---|---|---|
| 原生参数 | 已核验接口存在对应字段及组合限制 | 显示实际提交字段；仍不承诺结果必然符合 |
| 参考素材 | 已核验接口接受对应媒体类型、数量和用途 | 保留首帧、尾帧、角色或风格等具名用途 |
| 文字意图 | 当前只能编译进提示词或文字条件 | 明确标为软约束，允许用户确认后提交 |
| 不可表达 | 当前操作没有经过验证的可用映射 | 阻止提交或要求用户明确移除／更换模式 |

项目锁定项、节点局部要求和素材用途之间的业务合并由 M01 组织；M03 不按连线顺序拼接请求。M03 返回字段级能力判断、冲突和降级说明，M04 在用户确认后冻结实际生效结果及能力快照。切换模型、渠道或操作模式必须重新计算，不能沿用旧的“已生效”外观。

### 10.1 供应商异常对用户与后台的影响

| 上游现象 | 用户侧 | 后台处理 | 积分影响主责 |

## 14. 分期与非目标

### 14.1 分期

| 阶段 | 功能深度 |
|---|---|
| 首发 | 精选少量图片／视频展示模型；每项至少一个已核验渠道；模型渠道映射、能力快照、参数白名单、凭证账户、上架／暂停／下架、人工渠道状态、成本参考版本、受影响任务查询；Toonflow provider 按实际能力接入 M04 |
| 下一阶段 | 经实测的备渠道、限量／灰度、自动余额与配额告警、完整事故管理、模板／课程迁移、成本对账增强 |
| 未来 | 多地区、多采购账户、复杂质量／成本／延迟路由、自动化供应商评估；仍不得在未知任务上无成本重提 |

### 14.2 明确非目标

- 不在本轮确定首发最终模型与采购渠道清单。
- 不填写未经当前官方资料或采购账号验证的价格、限额、成功率和延迟。
- 不为追求统一而重写所有 Toonflow provider；只补齐业务能力和任务交接缺口。
- 不允许用户自行填写平台级供应商密钥或任意添加未经运营核验的模型。
- 不在 M03 执行任务、保存结果、扣退积分或创建作品。
- 不建设自动按最低成本切换渠道的黑箱路由。
- 不在原任务状态未知时自动换供应商重试。
- 不把不同渠道的厂商资产 ID、审核或真人授权状态视为通用。
- 不自部署模型；MiniMax H3 开放权重路径不在本项目范围。
