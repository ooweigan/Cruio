## 1. 模块目标

M09 让被授权推广者清楚知道自己能推广什么、通过哪个标识带来哪些合资格线索，以及未来平台启用交易后哪些真实有效订单可按已发布规则形成佣金。运营能审核推广资格、处理归因争议和异常；财务能根据可结算事实处理未来结算，并核对退款、拒付和已付款佣金的追补。

成功意味着：访问、注册、购买、佣金和打款是不同事实；线下成交不会被伪造为平台佣金；每笔佣金追溯到有效推广身份、明确归因规则版本、真实 M08 订单和退款变化；单层归因，无拉人头／多层团队奖励；异议或反作弊冻结有理由、复核入口和历史记录。

## 2. 使用者与主要任务

| 用户／角色 | 主要任务 | 权限边界 |
|---|---|---|
| 推广者／分销者 | 申请或接受推广资格，取得个人推广链接／邀请码，查看本人访问／注册／合资格订单摘要及佣金状态 | 不可查看其他推广者或被推荐用户的私人创作、支付凭据、完整个人资料 |
| 分销运营 | 处理资格、推广素材、归因冲突、违规举报、佣金资格与申诉 | 不能伪造 M08 订单或直接改 M09 之外的账本 |
| 财务运营 | 查看达到可结算条件的佣金和已完成的线下结算凭据／状态 | 只有经授权可查看收款／税务资料；不直接改归因或订单支付事实 |
| 客服 | 处理推广链接、归因未显示、佣金冻结、结算状态问题 | 可发起核查，不自行判定佣金成立或已打款 |
| 普通用户／游客 | 通过链接／邀请码访问、注册或购买，并了解推广披露及数据使用提示 | 不因访问推广内容自动成为推广者或被追踪超出明确用途 |
| 安全／治理岗位 | 调查欺诈、广告披露、隐私或推广内容违规 | 按 M14 的案件与授权查看必要信息，不浏览无关用户数据 |

### 3.2 事实、建议与未决事项

- **已核验事实：** 官方资料表明广告可识别性、传销风险要素、税务处理及平台角色都依活动事实与适用市场而定；没有一个可直接跨国复用的佣金规则。
- **设计建议：** 先采用单层推荐与清晰广告披露；将线索归因与订单佣金分开；平台佣金只依未来 M08 真实支付订单形成；运营配置费率、归因窗口与结算期但不在本轮赋予具体数值。
- **待核验事项：** 目标市场、推广媒介／平台政策、商业合作主体、推广者身份与税务资料、个人信息处理依据、广告标识、支付／结算流程和申诉责任。

本轮未创建真实推广账号、发布推广广告、跟踪真实用户流量或执行佣金付款。

## 4. 范围与责任边界

### 4.1 M09 主责

- 推广者资格与授权范围、推广标识／邀请码、推广素材使用许可。
- 经允许采集的访问／注册／购买触点归因记录和冲突决策结果。
- 未来基于真实 M08 订单形成的佣金规则快照、佣金事实、冻结／解冻、退回／冲正和结算申请。
- 推广活动合规提示、异常归因复核、本人佣金与结算查询及申诉交接。

### 4.2 M09 不负责

- M08 主责商品、订单、支付、退款及实际收款／退款事实；外部成交不能作为平台订单佣金来源。
- M09 不执行推广合作款的当前线上打款；当前合作费与推广佣金全部在线下合同／财务或第三方渠道完成。
- M07 主责创作积分账户与账本；佣金不是积分，不可直接互换或冲抵。
- M02 主责账户、角色授予和封禁状态；推广者资格不等于管理员或老师权限。
- M14 主责法律／平台规则下的治理、授权、反作弊决定与申诉；M09 按决定冻结、限制或恢复推广资格。
- M11 是受控后台入口，不代替 M09 写入佣金或归因事实；M13 只汇总，不计算第二本佣金账。

### 4.3 线索归因与佣金的区别

| 事实 | 当前可否产生 | 表示什么 | 是否形成佣金 |
|---|---|---|---|
| 推广链接访问 | 在下一阶段启用线索验证并满足 M14 数据规则后可记录 | 用户访问推广入口的候选触点 | 否 |
| 注册／邀请码关联 | 在授权范围内可进行试点 | 用户注册时登记的推广关系或来源 | 否 |
| 外部渠道成交／转账 | 产品外发生，由线下财务确认 | 外部商业合作或成交流程 | 否；不可伪造 M08 订单或 M09 佣金 |
| M08 真实线上支付订单 | 当前关闭；未来启用交易后可作为佣金来源 | 平台确认的订单／退款事实 | 仍需按资格、归因、冻结和规则确认后形成 |
| 佣金结算 | 当前线下完成；未来可记录实际结果 | 应付／可结算佣金的外部支付结果 | 不改变用户积分或订单支付事实 |

## 5. 分期与商业模型候选

| 阶段 | 功能深度 | 状态 |
|---|---|---|
| 当前／首发 | 不开放平台佣金、结算申请或佣金余额；推广合作及打款在线下。是否开放推广身份与线索标记按下一阶段实验评估，不以线索生成收益承诺 | 用户已明确资金边界 |
| 下一阶段建议 | 受邀／审核通过推广者、推广码和链接；在合适的数据告知与同意后，统计点击与注册来源候选；可查看自己的线索汇总；无费率承诺、不产生平台佣金 | 推荐用于验证身份和渠道质量 |
| 未来交易启用后 | 经市场／平台规则审查后，将单层推广归因绑定 M08 真实订单；版本化佣金规则、冻结和退款冲正；先记录线下结算凭据，不默认自动打款 | 须与 M08/M14 同步通过启用门槛 |
| 后续候选 | 多活动对照、多个渠道归因、可配置优惠码、推广素材版本和经核验的自动结算能力 | 单层归因和风控稳定后再评估 |
| 明确非目标 | 多层／团队佣金、按发展人数付酬、入门费／购买积分才能取得推广资格、投资收益承诺、佣金积分互换 | 当前不建设，也不以文案包装变相推出 |

## 8. 推广资格与推广内容流程

1. 用户提交资格申请或接受运营邀请，确认适用规则、禁止行为、推广披露和数据使用说明。
2. 分销运营根据产品策略审核身份、渠道和内容范围；获批后由 M02 授予限定作用域的推广者角色。
3. M09 为有效资格生成唯一推广标识／邀请码，并绑定活动、产品范围、有效期和规则版本。
4. 推广者只能使用经批准、当前有效的产品说明和素材；不得改写成保证生成效果、投资回报、永久可用、官方背书或未确认价格。
5. 公开推广内容涉及商业推广时，根据实际市场／媒介展示清晰披露；违规内容可暂停标识并转 M14 治理。
6. 资格到期、主动退出、账号封禁或治理限制后停止新归因；既有访问、订单和佣金历史仍保留并按适用规则处理。

## 9. 归因规则与冲突处理

### 9.1 归因优先级建议

| 顺序 | 可核验触点 | 建议处理 | 注意事项 |
|---:|---|---|---|
| 1 | 新用户注册时主动填写有效邀请码／专属推荐码 | 若无已锁定推广归属且活动允许，作为注册归因候选 | 保存用户主动输入事实；无效码说明原因，不自动替换为其他人 |
| 2 | 无邀请码时存在有效推广链接触点 | 在配置的归因窗口内按推荐的“最后一个有效非直接推广触点”确定候选 | 直接访问不覆盖已有有效推广触点；记录窗口与规则版本 |
| 3 | 用户已有推广归属或已有账户 | 默认不通过另一个链接静默改绑；只有明确活动支持重新归因且用户知情时才处理 | 老用户复购默认不产生持续佣金，除非产品规则另有明确配置 |
| 4 | 多个推广码／触点冲突、作弊信号或跨设备无法核验 | 标记归因待核查／无法判定，不自动猜测 | 运营处理需说明证据，不以设备指纹等超范围追踪补齐归因 |
| 5 | 线下／第三方渠道成交 | 只记录 M11 外部凭据时的必要来源说明，不建 M08 平台订单佣金 | 用户已明确禁止外部成交伪造成平台订单／佣金 |

### 9.2 工作默认

- **单层推荐：** 只归因直接推广者，不因该推广者邀请了其他推广者而向上级计提。
- **触点留痕：** 可分别保留首次有效触点与最近有效触点用于分析，但 commission attribution 按规则版本确定，不能由运营随意挑选更有利的一次。
- **注册归属锁定：** 推荐以新用户注册时确认的有效邀请码为稳定来源；只有明确公开活动规则时才允许用户在订单环节使用另一推广标识，且不得追溯改写已确认订单。
- **归因窗口：** 采用可配置变量 `W_attribution`；建议试点从 30 个日历日作为工作初值，活动规则明确后再发布。过期访问不形成订单佣金归因。
- **复购归因：** 首期未来佣金候选只覆盖符合条件的首次真实有效订单；老用户复购、续费、积分追加购买和课程交叉销售默认不产生佣金，除非商品规则单独明确。
- **统计保留：** 为反作弊和复核保存必要的触点时间、活动、标识及规则版本；原始 IP、设备标识等仅在 M14 规定的合法、必要范围处理，不作为默认无限期追踪手段。

以上均为可评审产品默认，不是用户确认的推广商业政策，也不能据此判断某一市场的广告法律适用性。

## 10. 未来佣金计算基线

### 10.1 资格条件

未来只有同时满足以下条件时才可形成佣金事实：

1. 推广者在订单对应时间具有有效资格，推广内容／渠道未被暂停；
2. M08 存在真实且确认支付成功的订单／商品项目；
3. 订单商品版本明确列入可参与推广的产品范围；
4. 订单存在符合当时归因规则的推广来源，且无自买、退款、拒付、欺诈或其他排除条件；
5. M14 和目标市场合规门槛已通过；
6. M09 记录计算基数、佣金规则版本、金额和状态，不能仅凭点击、注册或外部截图产生佣金。

### 10.2 佣金基数候选

推荐将未来规则表达为：

`佣金基数 = 符合资格的订单商品行实收金额 − 该商品行已确认退款／拒付金额 − 依目标市场确认应剔除的税费／代收款`

`佣金 = 佣金基数 × 当时适用的费率`，具体计算和舍入规则需在商品／活动版本中确定。

当前不填写费率、最低金额或真实金额，不决定支付手续费由平台还是推广者承担，也不把支付手续费自动从基数扣除。费率应由业务、财务和目标市场审查后发布。积分兑换、赠送或没有 M08 实付金额的外部成交不形成此佣金基数。

### 10.3 商品适用矩阵

| 商品／交易 | 当前 | 未来建议 |
|---|---|---|
| 外部线下积分包成交 | 无 M09 平台佣金 | 继续不伪造平台订单；如有线下合作佣金，记录在产品外合同／财务 |
| M08 线上积分包 | 当前不存在 | 仅当商品版本明确可推广并已付款后进入佣金候选；扣回依退款／拒付结果 |
| 单课／课程包 | 当前不在线上销售 | 需 M10 授权结构、老师合作协议和课程退款规则明确后逐品启用 |
| 会员／续费 | 当前明确不做会员 | 未来单独确认首次购买、续费是否计佣、取消和退款冲正；不默认无限期返佣 |
| 组合套餐 | 当前未启用 | 佣金按订单商品行／权益分项的购买快照分摊；无可靠分摊数据时不计佣或由平台规则明确处理 |
| 免费体验、活动赠送或无金额权益 | 不形成金额佣金 | 除非另有经批准且不违反市场规则的固定推广费用政策；不得伪装成销售佣金 |

## 11. 佣金状态与退款冲正

### 11.1 佣金状态

| 状态 | 含义 | 进入条件 |
|---|---|---|
| 无佣金／不符合资格 | 订单未启用佣金、无有效归因或命中排除条件 | 形成明确结果并保存原因 |
| 候选 | 有可核验归因／订单关系，但尚未满足真实支付／商品范围条件 | 访问、注册或待付订单只用于候选归因 |
| 待确认 | M08 支付成功且满足初步资格，仍在退款／风险观察窗口 | 计算金额及冻结依据有规则版本 |
| 冻结／争议中 | 存在退款、拒付、欺诈信号、归因争议或治理案件 | 保留原记录，不允许申请结算争议金额 |
| 可结算 | 冻结条件解除，订单有效、佣金数值确认 | 达到配置的观察／退款窗口；实际期限待定 |
| 结算申请中 | 推广者或授权运营申请结算 | 按结算资料和最低门槛政策（未来配置） |
| 结算处理中 | 结算申请通过，等待未来外部支付结果 | 保存拟结算金额和参考编号 |
| 已结算 | 财务核实外部资金已实际支付 | 有结算日期、金额、币种、受限凭据／外部参考 |
| 部分退回／冲正 | 原订单部分退款或佣金金额部分修正 | M08 提供退款事实，M09 追加负向佣金记录 |
| 已退回／已冲正 | 整笔佣金已冲回或资格撤销 | 有原佣金与纠正事实关联 |
| 结算失败／待重试 | 外部支付未完成、银行信息错误或状态未知 | 不显示已付款；查询原结算，不重复付款 |

### 11.2 退款／拒付处理

1. M08 产生退款／拒付事实后，M09 依据订单行退款金额和已结算状态计算候选冲正；不能以用户提交退款申请代替实际退款成功。
2. 未结算佣金：冻结待处理部分，退款成功后按规则减少或冲正。
3. 部分退款：只对受影响商品行／对应基数重新计算；无可信分摊时进入人工核查，不按整单比例猜测。
4. 已结算佣金：保留原始付款记录，追加佣金退回／冲正事项；不能静默从推广者余额或用户积分扣除。
5. **已结算后追补候选：** 推荐优先从该推广者未来可结算佣金中抵扣已经确认的冲正额，并显示原订单、金额和申诉入口；若无后续佣金，不自动生成负佣金现金债务或未经约定的线下追款，应进入人工／合同核查。最终方案待业务协议与目标市场确认。
6. 退款失败、支付拒付结果未知或 M08/M09 状态冲突时，保持冻结／核查，不先行完成佣金退回。

## 12. 反作弊、争议与申诉

| 风险场景 | 默认处理建议 | 申诉／事实主责 |
|---|---|---|
| 推广者自购或关联身份购买 | 标记自购候选；规则未通过人工核查前不确认佣金，不自动封禁账户 | M09 核对归因；M02/M14 处理账户／身份风险；可申诉 |
| 同用户多账号／重复注册 | 暂停争议佣金并提供证据摘要；只使用目标市场允许且必要的关联依据 | M02/M14 主责身份和隐私边界，M09 不自行无限采集设备指纹 |
| 点击刷量／自动化流量／异常转化 | 将异常活动归因隔离并抽检；保留原始与过滤后的统计口径 | M14／运营核查规则与误伤申诉 |
| 推广链接劫持／cookie stuffing／恶意覆盖 | 保护已锁定注册归属，不静默改绑；暂停相关推广标识 | M09 处理触点事实；用户可提交邀请记录 |
| 虚假宣传、未披露商业关系、擅用素材 | 暂停该内容／标识并转交 M14；不自动抹除已发生订单／佣金事实 | M14 主责治理结论；M06/M11按决定执行公开状态变化 |
| 退款、拒付、争议订单 | 冻结相关佣金，不冻结无关用户权益 | M08 提供支付／退款事实，M09处理佣金状态 |
| 佣金计算／规则版本错误 | 暂停受影响项目，追加纠正／冲正条目并通知相关方 | M09 负责金额规则与账；M11留存运营记录 |
| 推广者账号停用／资格撤销 | 停止新的归因；历史佣金和争议按规则保留 | M02管理角色，M09处理推广对象，M14处理治理 |

冻结必须有原因类别、时间、受影响订单／活动范围、处理责任和复核／申诉入口。为了调查而冻结某笔佣金，不自动冻结推广者积分、作品、课程或整个 Cruio 账户。

## 14. 后台运营与对账

### 14.1 运营工作台

- 推广资格队列：申请来源、活动范围、审核状态、角色授权结果和失效时间。
- 活动与标识：产品／渠道范围、链接／邀请码、素材版本、披露要求、归因规则版本和启停记录。
- 归因审查：触点时间线、注册绑定来源、冲突原因、被过滤事件和修正依据；不展示无关用户私有信息。
- 佣金核对（未来）：订单商品行、实付基数、退款／拒付、费率快照、冻结条件、币种和佣金计算过程。
- 结算差异（未来）：申请人、可结算金额、扣缴／资料待核验项、外部支付参考和实际完成时间；不得在没有资金证据时标为已付。
- 举报／申诉：关联 M14 案件、处理责任、时限和决定结果。

### 14.2 记录与修正

归因、佣金和结算调整必须保留原始事件、规则版本、来源模块、操作者、理由和纠正引用。退款／拒付通过新冲正项调整佣金；归因冲突通过“原结果—复核决定”记录解决。任何后台“编辑佣金数值”都必须生成明确的有据调整记录，不允许覆盖历史或改造 M08 支付事实。

### 17.2 按用户指示采用的工作默认
