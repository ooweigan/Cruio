## 1. 模块目标

当线下业务流程无法承接且产品作出启用决策后，M08 为用户提供可理解的商品购买与订单履约过程，为运营提供订单、支付、权益差异、退款和对账的可追溯事实。M08 负责真实平台交易事实和权益发放／回收的协调，不代替积分、课程或分销模块创建各自领域事实。

成功意味着：商品、订单、支付、退款和权益状态相互关联但不混为一谈；支付成功不伪装成权益已到账；重复通知不会重复扣款或发权；部分履约失败能定位责任并补偿；退款规则按目标市场和商品类型明确，且不承诺回收不可追回的上游成本。

## 2. 使用者与主要任务

| 用户／角色 | 主要任务 | 权限边界 |
|---|---|---|
| 购买用户 | 浏览可售商品、理解价格和权益，确认订单、完成支付、查看支付与权益履约状态，申请适用的退款 | 只能查看本人订单和支付／权益摘要；不得改写支付结果 |
| 财务／订单运营 | 查询订单、支付、退款和对账差异，处理待核实交易 | 只能按岗位查看必要资料；不直接修改 M07 积分或 M10 课程权益 |
| 客服 | 受理购买、付款未确认、权益未到账和退款问题 | 可发起查询／补偿请求，不判定支付成功或直接授予权益 |
| 商品／内容运营 | 配置商品、售卖期、价格版本、权益包和上下架 | 发布前需校验商品权益与目标市场要求；不能写入支付事实 |
| 权限／安全运营 | 管理岗位权限、风险限制、争议和隐私处理 | 依据 M02/M14 进行权限或安全处置，不自行结算订单 |
| 分销运营 | 未来核对真实订单归因及佣金来源 | M09 主责佣金；M08 仅提供符合规则的交易／退款事实 |

### 3.2 已核验事实、设计建议与待核验事项

- **已核验事实：** 存在明确的地域法律差异与数字内容／商品履行条件；中国官方法规和欧盟指令均显示退货／撤回规则不是可跨市场直接照搬的单一条款。
- **设计建议：** M08 将订单、支付、退款、权益履约分开记录，商品页面与结账保存当时的价格、权益和重要条件快照；真实资金处理通过未来经核实的服务路径进行。
- **待核验事项：** 目标市场、销售主体、支付服务资质与合同、税务／发票、支付凭据保存、退款资格和时限、拒付／争议、未成年人购买、消费者申诉和数据跨境等事项。

本轮没有真实支付、退款或支付机构接入操作。文中未来流程属于产品需求建议，不代替法律、支付机构或财税意见。

## 4. 完整范围与当前边界

### 4.1 M08 完整蓝图范围

- 商品目录、商品版本、价格快照、售卖状态、限购、优惠和活动（经启用决策后）。
- 积分包、单课／课程包、未来会员权益、组合套餐等同一商品与订单框架。
- 购买确认、订单创建、付款状态、支付结果核实、关单和交易对账。
- 订单应发权益的拆分、向 M07/M10 的发放请求、补发和履约差异。
- 会员有效期、续费／取消续订等未来候选；只有明确商业与用户授权时才启用。
- 退款申请／审批／结果记录、支付渠道退款、积分／课程权益回收与佣金冲正协调。
- 售后、发票／凭证需求、订单查询、后台权限和报表交接；具体内容按目标市场确定。

### 4.2 当前暂缓范围

当前只销售积分包且真实成交、收款、退款都在线下或其他渠道完成。M08 不创建商品、订单、支付、平台退款、会员或平台佣金事实；线下交易凭据由 M11 管理、积分变化由 M07 记账。M08 后续启用需满足第 17 节所列全部门槛。

## 5. 商品与权益组合矩阵

| 商品类型 | 典型适用场景 | 订单内可发权益 | 优点 | 复杂度／风险 | 候选上线深度 |
|---|---|---|---|---|---|
| 按次积分包 | 用户按需要购买一定生成额度 | M07 积分入账 | 易理解、与当前积分使用闭环一致；无周期承诺 | 需定义有效期、退款后已使用积分处理、定价与上游成本差 | 线上化条件满足后优先候选；当前线下售卖，不启用平台订单 |
| 周期会员 | 高复购用户获得一段时期内明确权益 | M08 会员有效期记录；M07/M10 按会员权益清单逐项发放 | 收入较可预测，适合验证稳定高频需求 | 周期续费授权、取消续订、到期权益、扣款失败、退款、价格变更和消费者规则复杂 | **当前明确不做；未来经复购数据与合规评估后再评估** |
| 单课／课程包 | 用户只为一门课程或系列课程付费 | M10 课程／课节权益 | 购买内容与学习目标直接对应 | 课程访问、时效、已学习内容和部分退款需要明确；不自动含积分 | 未来若验证线上教学商业模式，按 M10 独立发权 |
| 会员含课 | 会员在有效期内访问明确课程集合 | 会员身份由 M08 记录，课程访问由 M10 依据会员有效权利授予 | 组合促活 | 会员结束／退款时课程权益同步、历史学习与撤权争议，权益范围易被误解 | 后续候选，不纳入首个交易版本 |
| 积分＋课程组合套餐 | 单订单同时购买创作额度和教学内容 | M07 积分＋M10 课程权益 | 可形成创作学习闭环 | 订单需分项快照、发放可部分失败、退款需按组件处理 | 单独积分包、单课订单稳定后再评估 |
| 其他数字工具／内容包 | 用户购买某工具时长、模板或素材许可 | 对应模块的限范围权益 | 支持未来产品扩展 | M01/M05/M06/M14 的许可、期限和来源权利必须明确 | 只有权益事实主责模块就绪后才考虑 |

所有商品统一由 M08 管理商品、价格和订单；各权益由其事实主责模块落账。当前唯一允许的商业模式是用户决策明确的积分包，且积分包通过线下／其他渠道销售，并非本平台线上商品。

## 8. 商品、订单和权益交互流程

### 8.1 商品定义与发布

1. 商品运营选定商品类型、可售范围、商品版本、价格／币种、税费展示策略、权益包组成、有效期、限购和售后条件。
2. M08 检查每项权益均有对应事实主责模块、明确额度／范围／期限和失效处理方式。
3. 对折扣、组合商品或受限数字权益，生成用户可读的购买前说明和条款版本；法律／财税待确认不标记为已通过。
4. 经授权人员发布后，商品版本在明确生效期内可购买；修改权益或价格产生新版本，不追溯修改已付款订单。
5. 当前未满足启用门槛时，商品保持关闭，任何管理台草稿不对外形成交易。

### 8.2 创建订单与支付

1. 用户确认当前商品、数量、价格／折扣、币种、应付金额、权益内容及重要售后条件。
2. M08 创建待支付订单和商品快照；重复点击同一购买流程应复用／识别原待处理订单，避免重复购买或重复发起支付。
3. 订单过期前付款结果由支付服务路径核实；用户关闭页面或未返回时，订单状态以可核验的支付结果为准。
4. 收到重复通知／查询结果时按同一交易事实去重；订单过期后支付成功不得丢弃，转入迟到支付核查及履约／退款处理。
5. 确认支付成功后，订单记录支付事实并为每项权益创建独立履约请求；未确认支付不得授予付费权益。

### 8.3 权益分项发放与补偿

1. M08 将订单商品快照拆为积分、课程、会员或其他明确权益请求，分别提交给 M07、M10 或未来主责模块。
2. 各模块确认权益已生效后，M08 更新该项履约结果；支付已成功不因发权失败改成支付失败。
3. 某项权益失败时只重试／补发该项，不能再次创建支付或重复发放其他成功权益。
4. 用户订单页显示“支付成功，部分权益待处理”，客服和订单运营可定位差异。
5. 经核查无法补发时，由 M08 协调适用的替代履约或退款决定；权益模块负责自身撤回／调整结果，M09 判断佣金影响，M12 通知用户。

### 8.4 退款申请与实际退款

1. 用户针对具体订单／商品项目提交退款申请，说明原因；M08 依据该商品成交时的条款快照和目标市场已核验政策判定是否可受理。
2. 退款审批／资格与支付渠道实际退款分开记录；受理不等于资金已经退回。
3. 对可退款部分形成明确商品行／金额／币种和各权益处理清单；积分由 M07 回收／冲正，课程由 M10 处理，会员期限由 M08 及权益主责模块处理，佣金由 M09 处理。
4. 支付渠道确认退款结果后，M08 更新退款事实；支付退款失败时不提前宣称已退款，也不在缺乏规则依据时永久剥夺权益。
5. 不承诺必然回收上游供应商成本；费用吸收、拒绝退款或部分退款须依据当时适用的市场规则、商品条款和已完成服务事实。
6. 当前线上退款能力关闭。外部退款必须先在线下／第三方渠道完成，再由 M11 登记凭据并由 M07 扣回积分，不经过 M08。

## 11. 订单、支付、退款与权益状态

### 11.1 订单状态

| 状态 | 含义 | 后续动作 |
|---|---|---|
| 草稿／待确认 | 用户尚未最终确认购买内容 | 可编辑或放弃，不创建支付事实 |
| 待支付 | 已确认订单快照，支付尚未核实成功 | 在有效期内等待；重复购买请求识别原单 |
| 支付确认中 | 前端返回或通知暂不充分，正在核验 | 不授予权益，不创建第二笔付款 |
| 已支付／履约中 | 支付事实已确认，至少一项权益待处理 | 分项调用权益主责模块并显示进度 |
| 部分履约 | 有权益到账、其他权益失败／处理中 | 继续补发／处理，不将订单标成全部完成 |
| 已完成 | 支付成功且所有订单内应发权益达到明确终态 | 仍可有后续售后／退款记录 |
| 已关闭 | 订单关闭且无成功支付事实 | 若后到支付成功，转入迟到支付异常，不丢失事实 |
| 退款处理中 | 已提出或受理退款，资金与权益步骤未全部完成 | 单独显示退款资格与渠道处理阶段 |
| 已退款／部分退款 | 支付渠道已确认相应金额退回，且权益处理结果可追溯 | 可保留未回收权益或差异说明，依具体规则 |
| 争议／核查中 | 支付、退款、用户身份或履约事实冲突 | 进入受控待办，不擅自改写源事实 |

### 11.2 支付状态

| 状态 | 含义 | 订单／权益影响 |
|---|---|---|
| 未发起 | 尚无支付请求 | 不授予权益 |
| 待支付 | 支付路径已开始，未确认结果 | 保持待支付 |
| 处理中／未知 | 返回、通知或查询结果不足／冲突 | 保持支付确认中；不重复扣款或发权 |
| 成功 | 依据未来确认的支付服务事实核实交易已成功 | 记录金额、币种、交易参考号和时间；触发权益请求 |
| 失败 | 明确未成功且不存在迟到成功风险 | 订单可重试或关闭，按市场流程执行 |
| 已关闭／取消 | 支付请求未继续，且经核查没有成功交易 | 不发权；迟到成功另起差异处理 |
| 退款处理中／已退款／退款失败 | 支付服务退款交易状态 | 与权益回收状态分开显示 |

### 11.3 退款状态

| 状态 | 含义 | 必须区分 |
|---|---|---|
| 未申请 | 无售后请求 | 不代表任何退款资格结论 |
| 已申请／待受理 | 收到用户请求，资格尚未确定 | 不应先行全额回收权益 |
| 已受理／拒绝／需补资料 | 业务资格决定 | 受理不等于钱已退；拒绝应给适用理由及可用申诉入口 |
| 退款执行中 | 已向支付渠道发起退款或等待确认 | 不提前显示已退款 |
| 退款成功／部分成功 | 支付渠道确认实际退回的金额和币种 | M08 记录资金退款事实，权益模块仍单独反馈回收结果 |
| 退款失败 | 渠道未能退款或结果不确定 | 不伪装为完成；进入核查或重试流程 |
| 权益回收处理中／部分完成／完成／失败 | M07/M10/M09 等源模块处理退款相关权益 | 与退款支付结果分开呈现和对账 |

### 11.4 权益履约状态

每一项应发权益独立采用“待发放、处理中、已到账、发放失败、补发中、已撤回／部分回收、回收失败、无需发放”等状态。订单整体只能根据其全部权益项汇总“履约中、部分履约、已完成或待核查”，不能抹平各权益模块事实。

任何补偿都必须遵循 GLB-032：交易事实、权益事实与客服送达各自保持真实。补发不是新支付，退款受理不是资金退回，资金退回也不自动等于所有权益均已撤销。

### 12.1 未来退款政策候选（非当前规则）

| 候选 | 规则概要 | 适用性 | 复杂度与风险 | 建议 |
|---|---|---|---|---|
| A. 对适用且未使用的权益退款，已消费部分按可核实使用记录处理 | 依商品项目／权益项确认未履行部分；组合商品按购买时快照的已确定分摊规则计算；已使用积分、已学习课程或已享受会员权益不自动假定可全额退款 | 积分包、课程和组合套餐的差异化数字服务 | 需要定义“已使用”、部分履约比例、适用法定权利、履约证明与定价分摊；不能以技术可回收性替代法律资格 | **推荐作为未来业务讨论起点，但须目标市场法律／消费者规则核验后才能发布** |
| B. 对满足退款条件的整笔商品整单退款 | 符合规则时退回整项／整单价款，权益按同一决定回收或停止 | 履行尚未开始、权益不可分割或市场政策要求的订单 | 用户容易理解；已消费积分、课程访问和已结算佣金难以协调，且成本不可必然收回 | 仅用于适用场景，不能作为所有数字商品默认 |
| C. 权益发放后一概不退款 | 以发放即履行为由排除退款 | 运营简单 | 可能与具体市场强制消费者权利、商品瑕疵或未履约救济冲突，争议风险高 | **不推荐作为统一规则** |

暂定方向：未来若启用线上积分包，先评估 A 作为可调整政策基线；只在当地规则允许并且购买前充分披露时，才计算未消费部分。已消耗积分、课程已学习、自动续费和组合套餐的具体处理不由本文件擅自定案。当前外部退款积分扣回继续按用户已确认规则走 M11/M07，与本候选线上政策完全分开。

## 14. 运营后台、对账与记录

### 14.1 后台工作台

- **商品管理：** 草稿、价格／权益版本、审批／发布结果、售卖状态、促销和上下架时间。
- **订单查询：** 按订单号、用户标识、商品、日期、状态和交易参考号受限检索；查询理由及敏感字段访问需按岗位权限控制。
- **支付核对：** 展示平台订单与未来支付渠道核对状态、重复通知、迟到支付、金额／币种不一致和渠道核查待办。
- **权益履约：** 逐项展示积分、课程和会员权益的原始请求、责任模块、结果和可重试状态；仅向源模块提出补发请求。
- **退款处理：** 依据适用商品／市场规则记录资格决定、申请金额、支付退款请求、渠道最终结果和逐项权益回收。
- **风险与权限：** 客服、订单、财务、商品运营和治理岗位按最小需要分权；付款凭据、身份资料和调查材料不因“订单详情”默认全量开放。
- **对账与报表：** 对账差异按订单／支付／退款／权益四域分别统计，由 M13 维护汇总定义。

### 14.2 记录和幂等原则

每个订单、支付、退款和权益处理结果都有可追溯业务关联；收到重复通知或人工重试时，先定位已有事实，不重复创建交易或权益。错误通过冲正、退款纠正、重新发权或新处理记录解决，不覆盖旧状态历史。后台不提供把订单状态从“失败”手动改成“支付成功”的无凭据按钮。

## 17. 分期、启用门槛与待决策事项

### 17.1 当前阶段

- 关闭平台商品、线上订单、支付、会员、平台退款和订单驱动佣金。
- 当前线下／第三方成交由 M11 登记凭据，M07 写积分账本；外部退款由后管登记并由 M07 扣回积分。
- 不允许“为运营方便”人工补建平台订单，不将外部支付截图变成平台支付状态。
- M08 的设计可作为未来蓝图，但不得计入当前可交付产品能力。

### 17.2 推荐的未来渐进路径

1. **准备期：** 明确目标市场、销售主体、合同关系、税务与发票处理、消费者规则、支付服务路径和投诉／争议责任；完成安全与运营评估。
2. **首个线上商品候选：** 若决策启用，先验证单一币种、无自动续费的积分包购买和最小订单／支付／M07 发权／退款差异闭环。此候选不得在准备期提前开放。
3. **单课／课程包：** 在 M10 权益、访问期限、售后和老师内容角色明确后再接入同一商品订单框架。
4. **组合套餐与促销：** 等各权益单独稳定后再增加分项履约、部分退款和优惠规则。
5. **会员／订阅：** 当前明确排除；只有复购与使用频率数据、取消续订体验、周期权益、退款和合规条件均明确后，重新决策是否建设。

上述是产品准备顺序，不是开发排期，也不构成未来上线承诺。

### 17.3 启用门槛

只有以下条件均有明确结论，才允许打开任何真实线上收款：

1. 目标销售国家／地区、经营主体、币种、目标用户和税务／发票责任已确认。
2. 支付服务商、商户合同、退款／拒付查询责任、交易参考号和数据处理边界已核验；产品不充当未经授权的支付服务主体。
3. 消费者权益、商品描述、数字内容履行／撤回、自动续费（如适用）、退款资格和用户申诉流程已有针对性审核。
4. 当前所售商品、价格、权益、期限、折扣、退款说明和支付前确认内容均形成版本快照。
5. M07/M10 权益发放、重复事件、部分失败补偿、订单对账、客服通知和异常运营均通过端到端验收。
6. 隐私、安全、敏感凭据访问、账务留痕和数据保存符合目标市场及合同要求。
7. 商业规模与收益足以证明从线下流程切换到平台收款的必要性；用户或运营有明确责任人可处理差异。
