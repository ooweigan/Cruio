本文定义运营与管理岗位完成跨业务工作的受控入口。M11 是工作台、配置发布、运营待办和操作记录的主责模块；它不复制业务模块的事实、状态或账本，也不等同于数据库管理、部署运维或开发人员控制台。

## 1. 模块目标

M11 让获授权员工能够按岗位查找待办、核对必要业务上下文、向事实主责模块发起操作并跟踪结果；让关键配置有作用范围、生效时间和历史版本；让高风险操作在发生前呈现影响、在发生后留下可核查记录；让客服、财务、内容、模型与系统管理岗位各自看见完成工作所需的最少信息。

成功意味着：后台入口不代表业务已完成；用户封禁由 M02、积分变更由 M07、模型配置由 M03、任务核查由 M04、课程权益由 M10、审核决定由 M14 等各自事实主责模块确认；后台只显示源模块状态并记录必要的操作者、原因、关联业务对象和结果，不以本地“已处理”覆盖源业务状态。

## 4. 权限模型与矩阵

权限应由岗位、动作、业务对象范围和敏感级别共同限定。用户同一身份可兼具多种业务角色，但后台权限按岗位另行授予、撤销和留存有效期；角色不能因为在一个页面可见，就自动取得其他页面权限。

标记：**查**＝查看必要字段；**申请**＝发起源模块操作；**执**＝在源模块授权范围内执行；**复**＝复核源模块结果／决定；**—**＝默认无权。具体员工可被授予一个或多个岗位，但不默认合并为全权管理员。

### 5.2 用户与客服上下文

- 用户检索应以经过授权的用户标识为入口，并对无权限岗位隐藏敏感字段；结果只展示账户状态、相关权益和工单／任务关联的最小摘要。
- 用户概览提供按业务域跳转的受控摘要：项目／素材／作品只显示与案件有关的信息；积分显示 M07 账本摘要；订单和课程权益显示各自主责状态。
- 客服可创建或关联 M12 工单、发起核查请求、记录用户沟通结果；不能从后台直接把积分余额改成用户期望值，不能将供应商“处理中”改成已交付。
- 账号封禁／解封作为对 M02 的受控请求或授权动作，必须区分临时限制、生成限制和账户停用范围，避免用全账号封禁代替针对功能的措施。

### 5.4 积分人工操作页面

当前此页面是 M11 核心入口，按用户已确认的最小流程设计：

1. 选择操作类型：外部成交积分入账或外部退款后积分扣回；不提供线上付款、退款执行、订单创建或佣金打款入口。
2. 关联用户和外部交易／合同依据，填写成交渠道、外部订单号或合同号、积分数量、截图／凭据、备注。
3. 凭据上传／查看区域提醒遮挡无关姓名、地址、账号等隐私；非财务授权岗位只可见脱敏摘要或凭据是否存在。
4. 提交前显示影响预览：当前余额、拟入账／扣回数量、扣回后可能的负余额与生成限制；具体余额和可用额由 M07 返回。
5. 操作者确认并发起 M07 账本动作；M11 显示处理中、成功、失败或需人工核查，只有收到 M07 结果后才能显示“积分已入账／扣回”。
6. 更正错误通过 M07 支持的冲正／补正另行形成新事实；M11 可补充说明凭据关系，不删除或覆写原操作记录。

按用户决定不设置双人复核、复杂审批或线上财务审批流。必要的二次确认仅用于操作前核对目标用户、积分数和影响，不等同于审批；权限控制、原因记录、M07 账本与 M11 操作留痕仍须保留。

## 8. 业务状态、异常与用户沟通

### 8.1 运营待办状态

待办状态只描述后台处理流，不替代业务状态：

| 待办状态 | 含义 |
|---|---|
| 新建／待分派 | 源模块已提出待处理事项，尚无当前责任人 |
| 处理中 | 有授权岗位正在核查或向源模块发起操作 |
| 等待外部／用户 | 依赖供应商、用户补充资料或线下凭据；需显示阻塞原因 |
| 等待源模块结果 | 请求已发送但 M02/M03/M04/M07/M10/M14 尚未确认最终结果 |
| 已完成 | 源事实主责模块已返回可验证的完成状态，并完成必要沟通 |
| 失败／需升级 | 操作失败、信息不足或存在风险，需转交有权岗位；不能伪装完成 |
| 已取消 | 请求被合法撤回或源模块确认无需继续；保留取消原因 |

### 8.2 紧急停用与补偿

1. 供应商故障或安全风险出现时，供应商运营可按授权向 M03 请求暂停新提交；M03 返回实际配置结果。
2. 停用页面说明影响范围和生效时点；M04 对在途任务逐项按任务状态核查，不由 M11 批量伪造失败／成功。
3. 对已预占任务，由 M04/M07 按已确认规则保持预占、实结或释放；未知状态不能因后台紧急停用而自动释放积分。
4. 相关模板、课程练习、平台素材或作品分享是否限制，由对应模块与 M14 依据真实依赖和授权处理。
5. 用户可观察的能力变化、交付延误或替代方式由源业务模块提供事实，M12 负责通知；通知失败不会回滚停用或任务状态。

### 8.3 处理错误与重复操作

- 操作请求等待超时或页面刷新时，后台先查源业务状态，避免重复发起积分入账、扣回、封禁或配置发布。
- 同一外部凭据已关联既有积分操作时，提示可能重复，并要求财务确认是否属于新一笔外部交易；不擅自合并或覆盖。
- 操作请求返回失败但源模块状态未知时，将待办标记为“等待核查”，不自动重放高影响操作。
- 误操作通过事实主责模块支持的撤销／恢复／冲正流程处理，另记补救结果；M11 不删除审计记录。

## 9. 配置、审计与访问记录

### 9.1 必要操作记录

后台操作记录至少应能回答：谁在什么岗位、何时、基于什么理由，对哪个业务对象执行／请求了什么动作；请求经过什么确认／治理依据；源事实主责模块返回了什么结果；若失败、撤回或补救，原因和关联后续操作是什么。

| 记录类别 | 必要字段语义 | 敏感信息规则 |
|---|---|---|
| 业务操作请求 | 操作者、岗位、对象标识、动作、原因、提交时间、请求状态、源模块结果引用 | 不复制无关个人资料或素材原件 |
| 外部凭据操作 | 目标用户、成交／退款渠道、外部号／合同号、积分数量、凭据引用、经办人、时间、M07 结果 | 凭据原件仅财务等授权范围可查；其他岗位显示遮蔽摘要 |
| 配置版本 | 配置负责人、版本、范围、旧／新值的安全化摘要、生效时间、审批／发布角色（如适用） | 秘钥值不得入日志；仅保留掩码标识或轮换事件 |
| 角色权限变化 | 被授予／撤销人、角色、业务范围、期限、理由、操作者和执行结果 | 不在普通审计页暴露身份验证秘密 |
| 内容／安全处置 | 对象版本、治理决定引用、执行动作、可见性结果和申诉状态 | 案件材料仅授权岗位可看；普通内容运营查看安全化摘要 |
| 敏感资料访问 | 访问人、业务理由、案件／工单引用、查看字段类别和时间 | 不把审计查看能力本身作为访问任意敏感材料的授权 |

### 9.2 留存与查询

具体审计和凭据保留期限需结合适用市场、争议／安全需要和 M14 隐私治理确定；未确定前不得由 M11 自行永久保留所有原始资料。软删除不会抹除积分账本、任务、外部交易凭据或其他必要历史事实；永久删除／匿名化通过 M14 独立流程协调各模块。
