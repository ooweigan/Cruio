> 文档状态：规划草案  
> 版本：v0.4  
> 日期：2026-09-28  
> 依据：`AI_Video_SaaS_PRD_Prompts.md` 中 P00 与 P01  
> 用途：确定产品模块、职责边界、主要用户任务、模块依赖和分阶段功能深度，作为后续总 PRD 与分模块 PRD 的范围基线。  
> 声明：除明确标记“已确认”的决策外，本文中的分期与商业模式仍为设计建议。画布首发路线已确认基于固定 Toonflow MIT 版本复用；外部模型能力、供应渠道和价格仍须以对应调研证据及后续实测为准。

**已确认的初期范围约束：** 初期不建设线上商品、订单、支付、平台退款、会员和平台佣金功能。真实收款、退款、老师合作费用、推广佣金打款及其他资金结算均在线下或第三方渠道完成。外部成交确认后，由有权限的后管人员登记凭据并执行积分入账；外部退款确认后执行积分扣回。M07 记录不可覆盖的积分账本，M11 提供受控操作与凭据入口，但不为积分操作建设线上审批流、双人复核或复杂审计系统。M08、M09 的线上经营能力仍保留在完整蓝图中，但暂缓启用。

## 1. 产品概览

### 1.1 产品定位

本产品是面向 AI 图片／视频创作者的 Web SaaS。以画布式创作台为核心，连接参考素材、模型选择、云端生成、任务交付、作品沉淀与可持续经营。产品的核心不是单次调用某个模型，而是让用户能在明确的成本、进度、失败处理和权利边界下，反复完成创作。

### 1.2 目标用户与角色

| 角色 | 核心诉求 | 本轮判定 |
|---|---|---|
| 普通创作者 | 快速完成图片／视频创作，管理素材和作品，看懂用量与费用 | 已明确的核心用户 |
| 进阶创作者／内容生产者 | 复用角色、主体等厂商素材，管理多项目，公开作品或案例 | 用户群假设，需验证优先级 |
| 学员 | 获得课程权益，跟做练习，从学习返回创作 | 完整范围内的经营用户，首发深度待定 |
| 老师 | 维护运营分配的课程、课节、案例、练习和授权范围内教学内容 | 已确认的受邀内容角色；当前不自由入驻、定价、线上售课或参与系统内分成 |
| 推广者／分销者 | 获取推广身份，查看归因与佣金，申请结算 | 完整范围内的经营用户，资格与合规待定 |
| 客服／内容运营／财务运营 | 初期处理工单、内容、外部成交积分入账、外部退款积分扣回和对账异常；后续可处理平台订单与佣金 | 已明确需要经营后台，具体岗位待定 |
| 模型运营／系统管理员 | 维护模型能力、供应渠道、可用性、全局配置与管理权限 | 已明确需要，与业务运营必须分权 |

### 1.3 核心价值

1. **创作连续性**：在同一项目画布中组织意图、参考素材、生成结果与后续加工。
2. **多模型可用性**：将不同模型与供应渠道的能力、限制、预估消耗和可用状态转换为用户可理解的选择。
3. **稳定交付与可恢复性**：将远程生成视为可跟踪任务，明确等待、失败、重试、取消、交付和结算结果。
4. **可持续经营**：初期以线下／其他渠道成交和后管依据凭据执行积分入账支撑收费；完整蓝图中再以订单、展示、课程和分销形成增长链路，并提供客服、报表和治理能力。

### 1.4 范围边界

**完整产品范围**包含：账户与权限、项目与画布、模型与供应渠道、生成任务、私有素材与平台素材及模型厂商素材库、作品管理与公开展示、积分与用量结算、商品订单与支付退款、分销与佣金、课程与学习权益、通知客服、经营分析、内容安全与隐私、业务运营与系统管理。

**本轮不在范围**：Electron、原生移动端、本地或自部署生成模型、软件实现、技术栈、部署架构、物理数据模型、API 路径、开发工期和外部能力的无条件效果承诺。

### 1.5 三个使用视角

| 视角 | 服务对象 | 主要任务 | 说明 |
|---|---|---|---|
| 用户端 | 游客、创作者、学员、推广者 | 初期完成注册、学习、浏览公开作品和查看账户权益；后续可增加线上购买与分销信息 | 面向用户的站点和个人中心入口 |
| 创作台 | 已授权创作者 | 管理项目、画布、素材、厂商素材、生成任务和作品 | 核心工作区，画布优先复用成熟应用级项目 |
| 管理后台 | 客服、内容、模型、财务、运营与系统管理员 | 运营业务、处理异常、维护配置、审核与对账 | 是受权限约束的管理入口，不是第三套独立产品 |

## 2. 用户要完成的关键任务

### 2.1 创作者任务

1. 注册、登录，了解当前身份、积分、学习和创作权益。
2. 创建项目并进入画布，保存、继续和复用创作上下文。
3. 上传、分类、检索私有素材，并选用平台可用素材。
4. 必要时将角色、主体或参考资产登记到指定模型厂商，理解授权和可用范围。
5. 表达创作意图，选择适配模型与参数，在提交前看到限制、预估消耗和可用状态。
6. 提交生成，跟踪进度，处理排队、失败、超时、重试或取消。
7. 查看交付结果与实际结算，将结果回填画布、保存为作品或继续创作。
8. 管理私有作品，在可控权限下分享或申请公开展示。
9. 初期在线下或其他渠道完成交易后，查看后管手工发放的积分、发放说明与账本变化；后续才可在产品内购买并查看订单、支付和退款。
10. 学习课程、从案例或练习入口打开创作项目，完成再创作。

### 2.2 经营与管理任务

1. 维护可向用户提供的模型能力、供应渠道、策略、状态和成本参考。
2. 维护用户可见的积分价格规则、课程、平台素材、案例与运营内容；后续启用线上交易时再维护商品。
3. 初期处理生成异常、外部成交积分入账、外部退款积分扣回、内容审核、用户申诉与客服工单；后续增加平台订单与退款处理。
4. 管理推广资格、归因异常、佣金确认、退回与结算。
5. 初期按统一口径观察生成交付、模型成本参考、积分发放与用量；后续再纳入订单收入、退款、佣金和学习转化。
6. 配置后台角色和高风险操作权限，查看审计记录，管理全局开关与业务参数。

### 2.3 用户任务到模块的归纳

| 任务组 | 主责模块 | 主要协作模块 |
|---|---|---|
| 获得身份与权益 | M02 账户、用户与权限 | 初期为 M11、M07；后续可增加 M08、M10 |
| 组织创作上下文 | M01 项目与画布创作 | M03、M04、M05、M06 |
| 准备和登记参考资产 | M05 素材与厂商资产库 | M01、M03、M14 |
| 发起并获得生成结果 | M04 生成任务与交付 | M01、M03、M05、M07、M14 |
| 沉淀、分享与展示内容 | M06 作品管理与展示 | M01、M04、M10、M14 |
| 获得并使用生成权益 | 初期为 M11 后管发起、M07 积分到账与结算；后续线上交易由 M08 主责 | M02、M04，后续可增加 M10 |
| 通过内容学习和再创作 | M10 教学课程与学习权益 | M01、M06；初期如需手工发放权益则协作 M11，未来线上购买协作 M08 |
| 推广、归因与获得佣金 | M09 分销与佣金 | M02、M08、M13、M14 |
| 咨询、接收结果与处理异常 | M12 通知与客服 | 所有业务模块 |
| 运营、分析、配置和治理 | M11、M13、M14 | 所有业务模块 |

## 4. 模块职责表

### M01 项目与画布创作

| 维度 | 规划 |
|---|---|
| 服务对象／主要角色 | 创作者；辅助角色为客服和创作运营 |
| 核心职责 | 维护“一次持续创作”的项目与画布上下文，组织意图、参考资产、模型选择、任务占位和结果回填 |
| 包含功能 | 项目创建／打开／重命名／复制／归档；画布编辑与持续保存；素材、意图、生成操作与结果的画布内组织；从模板／课程练习建立项目；创作上下文恢复 |
| 明确不包含 | 不维护供应商能力真相；不执行远程生成；不记录积分账本；不把画布中间结果自动当作公开作品 |
| 主责业务对象 | 项目、画布文档、画布项、创作上下文、画布版本（业务语义） |
| 上下游依赖 | 依赖 M02 权限、M03 可选能力、M05 资产引用；向 M04 提交创作请求，接收 M04 交付结果；向 M06 发起保存作品 |
| 复用策略 | **已确认采用固定 Toonflow MIT 版本及现有技术栈。** 首发保留其画布、节点、生成交互、参考素材传递、参数、工具和任务展示等创作内核；重点替换账户权限、资源归属、模型供应、任务、积分、素材、作品和经营规则。固定提交、第三方依赖和生产可用性仍需留痕与验收 |
| 建议上线深度 | 首发达到可完成核心创作闭环；后续增强协作、版本对比和复杂模板 |

### M02 账户、用户与权限

| 维度 | 规划 |
|---|---|
| 服务对象／主要角色 | 游客、注册用户、学员、推广者、各类后台管理员 |

| 包含功能 | 注册、登录、登出、账户恢复；个人资料和账户安全；用户状态；前后台角色与权限；资源归属；账户注销发起 |

| 建议上线深度 | 首发支持精选模型与主备渠道的基础运营；后续引入更精细的路由与成本策略 |

### M04 生成任务与交付

| 维度 | 规划 |
|---|---|
| 服务对象／主要角色 | 创作者、客服、模型运营人员 |
| 核心职责 | 将已确认的创作请求转为可跟踪的云端生成任务，管理提交、进度、结果、失败、恢复和交付 |
| 包含功能 | 提交前校验；任务创建与跟踪；排队／执行／成功／失败／超时／取消；能力允许时的重试；结果验收与交付；异常处理入口；结算事实输出 |
| 明确不包含 | 不决定模型对外售价；不自己更改用户积分账本；不承诺供应商的成功率、效果或耗时；不主责长期作品管理 |

| 上下游依赖 | 接收 M01 创作请求、M03 能力与渠道、M05 可用资产、M14 安全决策、M07 额度预校验；向 M07 输出实际结算事实，向 M01/M06 交付结果，向 M12 输出通知事件 |
| 复用策略 | 优先复用成熟画布应用已有的生成交互和任务展示；任务语义、异常责任和结算交接必须纳入本产品的统一规则 |
| 建议上线深度 | 首发必须完成全状态可见、可恢复和可结算闭环；后续再扩展批量、优先级等高级能力 |

### M05 素材与厂商资产库

| 维度 | 规划 |
|---|---|
| 服务对象／主要角色 | 创作者、素材运营人员、客服 |
| 核心职责 | 管理输入创作的可复用资产，清楚区分私有素材、平台素材和登记到外部模型厂商的资产 |
| 包含功能 | 上传／导入、预览、分类、标签、检索、删除／失效；平台素材库；厂商资产登记、状态、适用模型／渠道、更新与失效；资产来源与授权声明；画布选用 |
| 明确不包含 | 不将生成结果自动视为素材；不负责作品发布；不维护模型能力目录；不保证厂商资产永久可用 |

| 建议上线深度 | 首发支持私有素材、精选平台素材和必要的厂商资产登记闭环；后续增强批量管理与素材运营 |

### M06 作品管理与展示

| 维度 | 规划 |
|---|---|

## 5. 边界易混点

| 易混边界 | 主责划分 | 关键规则 |
|---|---|---|
| 素材 vs. 作品 | M05 主责创作输入与可复用参考资产；M06 主责用户确认沉淀的成品 | 任务结果既不自动成为素材，也不自动成为作品；须由用户选择保存或转为后续输入 |
| 私有素材 vs. 平台素材 vs. 厂商资产 | 均由 M05 管理资产生命周期；M03 只定义厂商资产的能力约束 | 三者必须保留来源、归属、授权、适用模型与失效方式的差异 |
| 作品 vs. 公开展示 | M06 同一模块内的两个阶段；M14 提供公开安全决策 | 作品默认不公开；分享与公开发布是不同授权级别；展示撤下不等于删除私有作品 |
| 模型成本 vs. 积分售价 | M03 主责采购成本参考；M07 主责面向用户的积分报价 | 二者可关联但不等同；历史任务必须能追溯提交时适用的报价与成本参考版本 |
| 外部成交 vs. 平台交易 | 初期的线下／其他渠道成交不在产品内形成订单；M11 登记外部凭据并执行积分入账，M07 记录账本结果 | 必须记录目标用户、积分数量、渠道、外部订单号／合同号、凭据、操作人、时间和必要备注；不得生成虚假平台订单或支付记录 |
| 外部退款 vs. 平台退款 | 当前退款由线下／第三方渠道处理；M11 登记凭据并执行积分扣回，M07 记录扣回与负余额 | 不在产品内建设退款申请或退款资格判断；余额不足保持负值并暂停新付费生成，后续入账优先填平 |
| 商品订单 vs. 积分账本（后续） | 未来启用 M08 后，M08 记录交易、支付和应发权益；M07 记录积分实际到账与后续消耗 | 支付成功后发放可失败，不得伪装成已到账；退款与积分回收须分别留痕 |
| 积分 vs. 佣金 | M07 是产品内生成额度，M09 是分销收益与结算义务 | 两套账本、两套规则，不互相冲抵；是否允许佣金兑换积分属独立商业决策 |
| 画布状态 vs. 任务状态 | M01 主责编辑文档和画布项状态；M04 主责远程生成执行状态 | 画布中的任务占位是 M04 状态的投影；删除占位不必然取消任务，取消必须由 M04 确认 |
| 业务后台 vs. 系统管理 | M11 提供同一管理入口下的分权工作区 | 运营可编辑授权业务内容；系统管理员才能处理全局、敏感、安全相关配置；积分入账／扣回需留痕但当前不建审批或双人复核 |
| 普通删除 vs. 永久删除／匿名化 | 各对象主责模块执行软删除，M14 协调永久删除或匿名化治理 | 软删除后停止展示、搜索、新引用和新生成；积分、任务、外部凭据等历史事实不得被普通删除破坏 |
| 课程权限 vs. 生成额度 | M10 主责能否学习；M07 主责能否消耗积分创作 | 课程可附带独立积分或练习额度，但必须通过 M07 发放；拥有课程不默认拥有无限生成权 |
| 业务事实 vs. 报表数据 | 业务模块是真实事实主责；M13 负责口径与汇总 | 报表差异回到业务主责模块修正，不在报表层“改账” |

### 6.1 主业务链：从注册到作品沉淀

```text
M02 注册／获得身份
  → 线下／其他渠道完成交易（产品外）
  → M11 有权限的后管登记外部成交凭据并执行积分入账

  → M01 组织画布与创作意图
  → M03 提供当前可用模型／渠道能力

  → M14 安全／授权校验
  → M04 提交、跟踪、异常恢复与可靠交付
  → M07 在可靠交付后实结；失败释放；未知状态保持预占待人工核查
  → M01 回填画布
  → M06 用户选择保存为作品
```

贯穿链路：M12 发送关键结果与承接工单；M13 汇总交付与结算事实；M11 提供异常处理和人工核查入口。负余额用户不得发起新的付费生成。

### 6.2 内容经营扩展链：作品到再创作

```text
M06 作品申请公开／案例化
  → M14 内容安全与授权决策
  → M06 公开展示／案例
  → M10 关联课程、课节与练习
  → [初期] M11 根据外部成交／运营依据发起学习权益发放
  → [未来] 启用 M08 后可在产品内购买学习权益
  → M10 发放课程权限并记录学习进度
  → M01 从练习模板／案例打开画布
  → 回到主创作链
```

课程若附带生成积分，初期由 M11 根据外部成交／运营依据发起，M07 单独到账并按主创作链消耗；未来启用 M08 后，改由 M08 提供订单权益发放依据。

### 6.3 交易增长扩展链：推广到结算（未来，不属于初期）

```text
M09 生成推广身份／标识
  → M09 记录访问、注册或购买候选归因
  → M08 创建订单、支付和发起权益发放
  → M07/M10 完成对应权益到账
  → M09 基于可归因订单产生待确认佣金
  → [正常] M09 到期确认、可结算、复核后结算
  → [退款] M08 记录退款 → M07/M10 处理权益 → M09 退回／冲正佣金
```

M14 贯穿合规、授权与反作弊；M13 按业务模块事实生成交易、权益、退款和佣金对账。

初期不用“人工创建订单”模拟这条链路；推广合作及佣金打款在线下完成，只在 M11 登记外部成交／退款凭据并由 M07 完成积分入账或扣回。

### 6.4 关键交接责任

| 交接 | 输入与输出语义 | 失败主责 |
|---|---|---|
| M01 → M04 | 已组织的创作意图、模型选择、参数和资产引用 | M04 返回可理解校验结果；M01 保留未提交的创作上下文 |
| M03/M05 → M04 | 可执行的能力／渠道和当前有效的厂商资产 | 能力或渠道问题由 M03 处理；资产失效由 M05 处理；M04 记录当次任务失败 |
| M07 ↔ M04 | 报价确认、逐任务预占与可靠交付／失败事实 | M07 主责预占、实结、释放和账本差异；M04 主责任务与交付事实；未知状态保持预占并进入人工核查 |
| M04 → M01/M06 | 交付结果、来源任务和可继续使用的上下文 | M04 主责交付可用性；M01/M06 分别主责回填和作品保存失败 |
| M11 → M07（初期） | 外部成交／退款事实、目标用户、积分数量、渠道、外部订单号／合同号、凭据、操作人、时间和必要备注 | M11 主责操作权限、凭据与输入完整性；M07 主责入账、扣回、负余额、冲正与账本一致性；失败不得标记为已完成 |
| M08 → M07/M10（未来） | 支付成功后的权益发放依据，含商品快照 | M08 主责交易事实；M07/M10 主责对应权益到账；不一致进入对账待办 |
| M08 → M09（未来） | 可归因订单、有效支付与退款事实 | M08 主责订单真实性；M09 主责归因和佣金计算 |

| 业务模块 → M12 | 可通知事件及对用户可披露的内容 | M12 主责送达与重试；原业务模块主责事实与文案语义 |
| 业务模块 → M13 | 可汇总事实与口径维度 | M13 主责口径与汇总；业务模块主责源事实修正 |

## 7. 版本功能深度（建议，未批准）

### 7.1 阶段定义

- **首发：稳定创作与外部成交积分闭环。** 个人用户在线下／其他渠道完成交易后，由后管依据凭据入账积分；用户准备素材、确认报价、由系统逐任务预占、提交生成，在结果可靠交付后实结并保存作品。运营可登记外部退款并扣回积分、处理未知任务和对账异常。首发不建设线上商品、订单、支付、平台退款、会员和平台佣金功能。
- **下一阶段：内容经营与增长验证。** 补强公开展示、课程、练习回流和更完整的客服运营；分销可先验证推广身份与线索归因，不在 M08 未启用时虚构平台订单佣金。
- **后续阶段：线上交易、规模化协作与精细运营。** 在商业决策明确后可启用 M08，再建立订单驱动的分销链路；同时根据已验证需求扩展团队协作、高级创作、更复杂的商品／教学和深度分析。

### 7.2 各模块功能深度

| 模块 | 首发建议 | 下一阶段建议 | 后续阶段建议 |
|---|---|---|---|
| M01 项目与画布 | 应用级复用落地；项目、画布编辑／保存／恢复；素材、模型、任务、结果闭环；图片手动遮挡、模糊、区域编辑和经授权局部重绘 | 模板、课程练习画布、更强版本恢复 | 团队协作、复杂版本管理和高级编排；视频／音频隐私处理须另行决策 |
| M02 账户权限 | 个人账户、资源归属、基础账户安全、后台分角色 | 业务身份与更精细后台分权 | 团队／组织空间、邀请与成员权限，需先确认客群 |
| M03 模型供应 | 精选模型目录、参数约束、主备渠道、上下线与基础成本参考 | 渠道健康、更灵活的运营策略和版本管理 | 按质量／成本／速度精细路由与更广模型组合 |
| M04 生成任务 | 提交、进度、失败、超时、取消／重试、交付与结算事实 | 批量任务、更强恢复和客服诊断 | 优先级、长流程编排和更复杂交付 |
| M05 素材与厂商资产 | 私有素材、精选平台素材、必要的厂商资产登记／状态／失效处理 | 批量管理、素材集、平台素材运营 | 团队资产库、更丰富授权与复用规则 |
| M06 作品展示 | 私有作品库、来源追溯、可控链接分享；公开展示可限定为运营精选小范围验证 | 公开广场、案例运营、再创作入口 | 收藏、关注等社交能力，须先验证内容运营价值和治理成本 |
| M07 积分结算 | 外部成交入账／外部退款扣回的可追溯账本；报价确认、逐任务预占、可靠交付后实结、失败释放、未知持续预占；负余额限制与后续入账优先填平 | 多类积分批次和更强对账，支撑课程权益 | 与未来 M08 权益发放对接，以及团队额度、预算与用量策略 |
| M08 商品订单 | **不实现；不创建线上商品、订单、支付或退款功能，也不用人工订单模拟外部成交** | 继续保留为完整蓝图；是否启用以明确商业决策为前提 | 启用后再建设商品、订单、支付、权益发放、退款和对账；订阅与多市场支付需专项合规 |

| M11 运营与系统管理 | 分角色后台、外部成交积分入账／外部退款扣回入口、规定凭据与受限查看、基础配置、异常待办和必要操作留痕；不建积分审批／双人复核 | 公开内容、课程、分销专项工作台 | 更精细分权和跨模块运营自动化；复杂审批仅在未来确有需要时评估 |
| M12 通知客服 | 站内关键结果、联系客服、轻量工单与业务对象关联 | 多渠道通知、更完整工单流程和帮助中心 | 智能分流、服务时效、知识库与更精细服务运营 |
| M13 分析报表 | 生成交付、模型用量、手工发放—积分—任务对账和基础运营健康 | 内容、课程、分销和用户漏斗 | 启用 M08 后的订单对账，以及分群、留存、收入／成本深度分析与受控自助报表 |
| M14 安全授权隐私 | 来源／权利声明、生成与发布检查、审核、举报申诉、软删除与独立永久删除／匿名化治理、隐私请求；约束图片蒙版用途与宣传 | 公开内容治理、分销反作弊和更完整授权管理 | 多市场规则、团队治理和更精细风险策略；真人识别／身份认证／活体认证不因进入后续阶段而自动纳入 |

### 7.3 阶段准入原则

1. 首发不以“页面能打开”作为完成，而以主业务链中身份、外部成交凭据、积分入账、额度、资产、任务、可靠交付、结算和作品事实能相互对应为准。
2. 外部模型供应不稳定时，产品应诚实呈现并提供恢复，不以 PRD 承诺模型效果、时延或成功率。
3. 公开展示、分销和课程即使不在首发对外开放，仍保留模块边界和上游交接，避免首发实施切断后续链路。
4. 初期积分操作上线前必须落实已确认的角色权限、凭据字段、凭据隐私、入账／扣回、负余额、冲正和必要留痕规则。未来任何支付、平台退款、线上分销结算，以及各阶段的公开发布或真实素材登记能力，上线前均需完成相应业务决策、授权与合规核验。

## 8. 模块保留／合并／拆分取舍

| 决策 | 对象 | 理由 |
|---|---|---|
| 保留 | M01–M10 | 均有独立用户任务、主责业务对象与错误处理责任；特别是模型、任务、积分、订单、佣金和课程不能为省模块而混成一本账 |
| 合并但分区 | M11 业务运营 + 系统管理 | 共用管理入口、权限与审计，现阶段拆成两个模块会造成重复框架；但两者必须分角色、分工作区、分高风险权限 |
| 合并但分子域 | M06 作品管理 + 公开展示 | 公开展示是作品经用户授权和审核后的发布阶段，共享同一作品身份；在模块内明确“私有—分享—公开”边界即可 |
| 独立保留 | M12 通知与客服 | 通知跨越所有业务链，工单又有独立生命周期、客服角色和异常交接责任；若散落到各模块会产生不一致用户体验 |
| 独立保留 | M13 经营分析与报表 | 报表应统一口径、分权和对账，但只汇总事实，不取代业务账本 |
| 独立保留 | M14 安全、授权与隐私 | 该能力从素材输入贯穿到生成、作品公开、分销、账户注销和申诉，需统一规则与审计主责 |
| 暂不拆分 | M05 素材库 + 厂商资产库 | 二者都服务于创作输入资产，共享归属、授权、检索和选用任务；厂商资产作为子域保留独特状态和适用范围 |
