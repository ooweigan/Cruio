# CRUIO 创作工作台：节点与工作流设计规范

**文档性质：** 产品与交互设计规范  
**适用团队：** 产品、设计、前端、后端、模型接入、测试  
**架构原则：** AI 推理全部调用远程 API；媒体处理通过受控媒体服务完成。  
**节点体系：** 8 类创作节点 + 1 类工作流复用节点。  
**能力范围：** 40 项业务能力，分别由节点操作、专业工具、通用面板、项目设置和执行系统承接。

**文档层级：** 本文是 M01 项目与画布创作下的节点产品模型与交互规范，负责用户节点分类、节点模式、端口语义、通用交互和工作流复用体验。本文不另建模型能力、生成任务、素材、积分、作品或治理事实；相关事实分别以 M03、M04、M05、M07、M06、M14 为准。  
**范围权威：** 节点与能力的完整蓝图以本文描述，实际版本范围和开放顺序以 `requirements/92-版本范围与需求基线.md` 为准。九类节点是稳定分类，不表示九类入口必须在同一版本全部展示；未实现、未验证或未获权限的类型和操作不得出现在可执行入口中。  
**实现关系：** 用户节点类型不要求与前端组件、插件包或后端模块一一对应。现有 Toonflow 节点实现可以作为适配器承接一种或多种节点模式，但不得把运行时插件名称直接扩张为新的用户顶层节点类型。
**UI 参考稿：** [`node-design.html`](./node-design.html) 是节点内容、状态密度、费用提示与专业视觉方向的探索稿，只作为设计输入，不是可直接复制的页面实现、当前版本范围或业务事实来源。Coding Agent 使用前必须执行本文 §12.3 的共用布局设计和问题修正流程。

## 1. 产品定位与设计目标

### 1.1 产品定位

CRUIO 是面向创作者的多模型 API 工作台。用户通过剧本、分镜、素材、导演、图片、视频、声音、剪辑和工作流，完成从创作意图到成片交付的生产过程。

产品提供两种并存的工作方式：使用现成任务模板快速开始；在画布上自由连接节点，组织自己的创作方法。两种方式共用资产、版本和执行系统，不形成两套割裂的项目。

**核心心智：节点是创作工位，连线是内容的使用关系，模型是执行工具，工作流是可以复用的创作方法。**

### 1.2 设计目标

| 目标 | 产品要求 |
|---|---|
| 降低首次使用门槛 | 用户可从一张图片、一段文字或已有视频开始，不必先理解完整生产链 |
| 保留专业控制力 | 镜头、运镜、轨迹、风格、光色和表演可独立管理、组合和复用 |
| 减少重复操作 | 同一节点支持逐镜头执行、逐句配音和单项重做，不要求手动复制大量节点 |
| 控制费用和影响范围 | 每次付费执行明确范围；修改上游不自动重跑下游 |
| 支持可靠复用 | 工作流具有固定版本、清楚的输入输出、可检查的内部任务和权限边界 |
| 保持供应商可替换 | 创作要求与模型请求分离；切换模型时重新检查能力，不静默丢失要求 |

### 1.3 产品边界

| 工作类别 | 实现方式 | 用户是否需要理解技术细节 |
|---|---|---|
| 写作、拆分分镜、图像／视频／声音生成、语义分析 | 远程模型 API | 只理解任务、输入、结果和费用 |
| 文件导入、内容编辑、参数合并、排序、条件判断 | 应用自身逻辑 | 只理解操作目的 |
| 裁切、抽帧、转码、混音、字幕合成、导出 | 媒体处理或云端渲染服务 API | 不需要理解编解码实现 |
| 构图网格、轨迹编辑、空间示意 | 浏览器或非 AI 渲染服务 | 明确这是拍摄示意，不是生成结果 |
| 凭据、回调、轮询、预算、缓存、归档 | 执行基础设施 | 可查看状态，不需要自行搭建 |

不提供本地模型加载、采样器、潜空间、文本编码器、模型权重或显存管理节点。不把网页产品的某项功能自动视为可调用 API，也不承诺所有模型拥有相同参数。

文档中的功能代表设计范围。生产环境仅开放已经实现、经过接入验证且当前账号有权限使用的操作；未接入能力不得以可点击的假入口展示。

## 2. 节点体系与功能分层

### 2.1 九类用户节点

| 编号 | 名称 | 用户问题 | 节点内主要操作 | 主要产物 |
|---|---|---|---|---|
| C01 | 剧本 | 我要讲什么？ | 导入、手动写作、AI 创作、改写、台词整理 | 剧本、文案、配音文本 |
| C02 | 分镜 | 具体要拍哪些镜头？ | 拆分、编辑、排序、确认 | 单镜头或镜头清单 |
| C03 | 素材 | 我要用哪些已有内容？ | 上传、素材库选择、组织角色／场景／产品参考包 | 媒体资产、参考包 |
| C04 | 导演 | 这个镜头应该怎样拍？ | 镜头、运镜／轨迹、风格／光色、表演／走位 | 导演配置、拍摄示意 |
| C05 | 图片 | 我要生成或修改哪张图？ | 生成、参考图生成、图像编辑 | 图片及候选版本 |
| C06 | 视频 | 我要生成或修改哪个片段？ | 生成、编辑、延展、口型处理 | 视频及候选版本 |
| C07 | 声音 | 我要怎样的配音、音乐或音效？ | 配音、音乐、音效生成 | 音频及候选版本 |
| C08 | 剪辑 | 这些素材如何组成作品？ | 时间线、裁切、混音、字幕、导出 | 剪辑工程、成片 |
| C09 | 工作流 | 我要复用哪套做法？ | 调用已发布流程、填写参数、运行、检查内部过程 | 声明的业务产物 |

前八类放在“创作”区，工作流放在“复用”区。内部编号不显示在普通用户界面中。模型品牌、模板名称、角色类型和操作模式不产生新的顶层节点类型。

### 2.2 五层承载方式

| 层次 | 放什么 | 示例 |
|---|---|---|
| 用户节点 | 可独立放置、连接、运行、替换的创作工位 | 图片、视频、工作流 |
| 节点模式与专业工具 | 围绕同类产物的具体任务 | 剧本导入、图片扩图、视频延展、导演轨迹 |
| 通用面板 | 跨节点一致的使用能力 | 候选对比、采用、创作确认、批量、质量检查 |
| 项目与工作流设置 | 跨节点共享的规则和接口 | 项目简报、预算、输入输出、条件规则、触发方式 |
| 执行系统 | 用户不应手动搭建的可靠性机制 | 类型转换、调度、回调、恢复、归档、费用记录 |

40 项能力是产品与研发的功能目录，不是用户需要学习的 40 种节点。

### 2.3 同型节点可以有多个实例

合并节点类型，不合并独立的创作任务。用户可以自由创建多个同类型节点，每个实例保留自己的输入、配置、结果、版本和执行记录。

```text
剧本「载入原稿」 → 剧本「改写广告脚本」 → 分镜

导演「全片风格」 ──→ 导演「镜头 03 运镜」 ──→ 视频

视频「原始片段」 → 视频「延展结尾」 → 视频「对口型」
```

当一个操作需要独立连线或复用时，创建相同类型的新实例即可，不为它增加新的顶层类型。

### 2.4 节点拆分规则

一项能力适合独立成节点，需要同时说明：用户为什么会在画布上单独放置它；它产生什么可连接的业务产物；拆开后如何改善替换、复用或依赖理解。

独立 API、独立费用、不同参数、不同开发模块，都不足以单独构成新增节点的理由。节点内的操作仍必须保留独立任务与费用记录。

## 3. 工作区与渐进式交互

### 3.1 工作区结构

| 区域 | 主要内容 |
|---|---|
| 顶栏 | 项目、保存状态、撤销／重做、运行入口、预算与任务摘要 |
| 左侧入口 | 起步模板、添加节点、项目素材、工作流库 |
| 画布 | 节点、连线、编组、运行与结果摘要 |
| 右侧面板 | 当前节点的输入、配置、候选、历史、检查与执行详情 |
| 专用编辑器 | 分镜表、导演工具、图像编辑、时间线；按需打开 |
| 项目设置 | 创作简报、画幅、语言、默认风格、预算、成员权限、模型连接 |

画布负责表达内容依赖，时间线负责表达播放顺序。画布中节点的左右位置不决定视频中片段的先后。

### 3.2 首次进入

首屏推荐“图片动起来”“文字生成画面”“剧本转短片”“使用现成工作流”等任务。选择模板后，直接聚焦第一个需要用户填写的位置，并显示下一步操作。

用户可以进入空白画布，但不得被迫先阅读完整节点目录。模板中的节点可以查看和修改；模板不是不可检查的封闭向导。

### 3.3 添加与连接

点击“添加节点”或拖出连线时，优先推荐与当前数据兼容的节点。搜索按任务词匹配，例如“加载剧本”定位到剧本的导入模式，“轨迹”定位到导演工具，“配音”定位到声音的配音模式。

拖入图片、视频或音频，默认创建素材节点。导入文字文件时提示“作为剧本载入”。生成结果由 M04 自动取得并保存可靠交付副本，但不因此自动成为 M05 素材或 M06 作品，也不自动在画布上添加重复的素材节点；用户明确“另存为素材”或“保存为作品”后，才交由对应模块建立新业务记录。

### 3.4 信息展开层级

| 层级 | 用户看到什么 |
|---|---|
| 卡片 | 名称、任务模式、必要输入、关键参数、预览、状态、主操作 |
| 基础侧栏 | 当前任务必需的输入与常用配置 |
| 专业工具 | 轨迹、区域编辑、音轨、字幕等任务相关编辑器 |
| 执行详情 | 生效要求、模型映射、输入版本、子任务、费用、错误 |

缺输入、不支持的能力、过期结果、待创作确认和费用风险始终可见，不隐藏在高级设置中。模式切换后只展示相应字段，不把所有模式拼成一个长表单。

### 3.5 项目简报与公共约束

项目简报包含内容目标、受众、语言、画幅、目标片长、品牌信息、必须出现和不得改动的内容。预算、供应商权限和存储政策单独管理，不拼进创作提示词。

普通偏好可在镜头中显式覆盖；被锁定的项目约束不可静默覆盖。节点显示当前值来自项目、导演配置还是本地编辑。修改公共设置时，先展示影响范围，再决定是否应用。

## 4. 节点通用交互与输出规则

### 4.1 通用卡片

卡片最多突出一个主要操作，辅助操作收纳于菜单或结果区。状态包括当前任务状态、已采用结果、输入更新提示和必要的费用信息，不用单个“成功”标签包办所有含义。

通用操作包含改名、复制配置、查看输入来源、查看版本、候选对比、采用结果、检查输入、运行当前节点、查看历史、删除和保存为工作流。仅对适用节点显示相关操作。

复制节点不复制运行中的远程任务，不携带明文凭据；可选择复制配置或同时选择已有结果。删除画布实例不默认删除资产库中被其他节点使用的文件。

### 4.2 保存、采用、创作确认与执行

| 操作 | 行为 | 不会发生的事情 |
|---|---|---|
| 自动保存 | 保存当前编辑草稿 | 不自动替换下游正在使用的内容 |
| 载入素材 | 完成解析／入库并选择一个明确的资产版本 | 不自动调用生成模型 |
| 采用此稿／采用此候选 | 更新节点的正式输出选择，记录版本 | 不自动重跑已完成的付费任务 |
| 应用导演设置 | 发布一份导演配置供后续任务使用 | 不表示视频已经按设置生成 |
| 创作确认通过 | 批准特定产物、任务范围和预算范围 | 不对未来全部版本永久放行，也不代表 M14 治理通过 |
| 生成新版本 | 发起新的生成意图并产生候选 | 不以相同输入为由偷偷返回旧结果 |
| 导出成片 | 根据固定剪辑工程创建渲染任务 | 不重新生成所有镜头 |

编辑中的草稿与正式输出分离。用户可以继续编辑，但已提交任务始终读取运行时冻结的快照。

### 4.3 输出端口

默认业务端口输出已采用、已发布或明确选定的数据，不把“最新返回的候选”当作正式输出。需要输出全部候选的工作流必须显式声明集合类型。

同一节点可以存在不同类型的具名输出。例如剪辑节点可输出“剪辑工程”“成片”“字幕文件”；视频节点可从结果工具中输出“选定视频”“抽取帧”“抽取音轨”。只有对应操作完成后，相应端口才具备可用产物。

### 4.4 输入用途

连线必须表达用途，不只表达先后关系。图片用于首帧、尾帧、角色参考和风格参考时，应当连接到不同的具名输入或带用途标签的槽位。

建立连线不会发起付费任务。接入集合时，明确选择逐项执行、选择单项或将集合整体作为一个受支持的输入，不自动展开为不透明的批量调用。

### 4.5 状态的四个维度

| 维度 | 示例 | 说明 |
|---|---|---|
| 执行 | 未运行、排队、运行、待恢复、成功、失败 | 一次任务执行到了哪里 |
| 采用 | 未采用、已采用、备用 | 哪个结果供下游使用 |
| 创作确认 | 不要求、待确认、通过、退回、需重新确认 | 当前版本是否得到流程内对应批准 |
| 新鲜度 | 当前输入、输入已更新、锁定旧输入 | 结果是否对应计划使用的内容 |

旧任务可以保持执行成功，同时提示输入已更新。新候选生成成功不改变已采用版本。创作确认、M14 治理决定与预算授权分别存储，界面可以合并展示，但不能相互替代。

本文所称“审核”若用于候选采用、工作流等待点或“确认后继续”，统一指创作流程内的**创作确认门禁**；它不等同于 M14 的内容安全审核、素材授权、隐私治理或申诉决定。界面与新增需求优先使用“创作确认”或“人工门禁”，避免用一个“审核通过”同时表达两类事实。

## 5. 九类节点详细设计

### 5.1 C01 剧本

**用户目标：** 接入或创作故事、需求、文案及对白，让文字成为可继续生产的内容。

| 项目 | 规格 |
|---|---|
| 输入 | 粘贴文本、已支持的文档文件、已采用剧本、项目简报、可选主体设定 |
| 任务模式 | 导入、手动编辑、AI 创作、AI 改写 |
| 必填内容 | 导入模式选择来源；创作模式填写要求；改写模式提供原稿和修改目标 |
| 主要配置 | 语言、内容结构、篇幅、改写范围、保留项、模型 |
| 输出 | `ScriptDocument`；需要时输出结构化 `VoiceScript` |
| 主操作 | 载入剧本、保存并采用、生成新稿、生成改写稿 |
| 功能覆盖 | F02 剧本加载、F07 创作与改写、F10 台词与旁白编排 |

#### 交互与设计逻辑

正文是操作中心，来源和任务模式清楚可见。短创意、广告文案和单镜头描述也使用剧本节点，不额外增加几乎相同的“文本节点”。用户可以重命名实例以表达具体用途。

导入只保留和解析原文，不自动润色或拆分。AI 创作和改写产生候选稿，支持原稿／新稿对比、按段采纳、保留原版。部分采纳形成新的完整文稿版本，不直接修改历史记录。

长篇内容按章节组织。章节锁定、局部改写和生成范围必须在提交前可见。模型输出未完整返回或结构校验失败时，保留可见草稿，不发布为可供下游消费的正式稿。

#### 台词与旁白

提供“台词与旁白”页，记录句子 ID、说话人、正文、语言、停顿、情绪和关联镜头。人工整理不调用模型；“AI 整理台词”是独立、可计费的操作。

每句台词有稳定身份，方便只重生成一句配音。跨镜头旁白不强制复制到每个镜头。字幕文字、配音原文和实际录音文本分别保留，修改文字不会自动改变已有声音。

#### 异常与边界

不支持的文件格式明确提示；扫描文档需要文字识别服务时单独确认。解析结果缺页、乱码或为空时不得假装导入成功。原文、来源文件、解析文本和人工修正记录分别保存。

导入内容是业务数据，不因正文包含命令句而获得执行权限。改写范围超出当前模型限制时，明确分段处理方式、预计调用和失败处理，不静默截断重要内容。

#### 验收重点

导入不触发写作费用；原稿可恢复；改写不覆盖已采用稿；同类型两个实例能够组成“原稿 → 改写稿”的独立链路。

### 5.2 C02 分镜

**用户目标：** 将剧本或手工创意组织成可持续编辑、可追踪的镜头计划，并查看图文分镜。C02 的主产物是固定版本的 `ShotListVersion`；详细字段提案见 `creativeNodeFieldDraft.md` 的 C02 章节。

| 项目 | 规格 |
|---|---|
| 输入 | 固定版本剧本、手工建立或导入的镜头清单；可选项目约束与参考包 |
| 核心操作 | AI 规划、手动新增、编辑、拆分／合并、排序、确认、排除生产 |
| 主要配置 | 规划重点、镜头粒度、目标镜头数、目标总时长、视觉展开范围 |
| 输出 | 固定版本的 `ShotListVersion`；有独立编排需求时另关联 `StoryboardVersion` |
| 主操作 | 拆分分镜、确认选中镜头 |
| 功能覆盖 | F08 分镜拆分、F09 编辑与确认、F10 台词与旁白编排 |

#### 镜头表字段

| 字段 | 默认展示 | 作用 |
|---|---|---|
| 镜号 | 是 | 便于阅读的顺序编号，不作为稳定身份 |
| 画面内容 | 是 | 本镜呈现的主体、环境、动作与叙事任务；不兼作生成模型提示词 |
| 角色／场景／产品 | 是 | 本镜的使用关系，可关联固定版本参考包；未绑定时保留局部称呼 |
| 目标时长 | 是 | 生产计划，不等于生成文件实际时长 |
| 台词／旁白 | 可展开 | 固定原文位置的语义关联，不表示配音次数或音频时码 |
| 状态 | 是 | 由独立的确认／评审记录呈现，不作为另一份镜头正文 |
| 原文位置 | 可展开 | 支持一镜对应多段原文，也允许手工镜头无原文 |

#### 交互与设计逻辑

AI 规划、人工修改与确认围绕同一份镜头清单完成，不要求串接三个节点。支持表格和图文视图，显示计划总时长、未填写时长和未匹配的主体。只显示已有媒体缩略图时不新增图板对象；需要一镜多图、镜内顺序和独立版本时，再建立附属的 `StoryboardVersion`。图板、生成候选和正式采用分别记录。

确认分镜只发布生产计划，不默认生成全部媒体。连接到图片或视频节点时，提示“已收到镜头清单”，再由用户选择生产范围和候选数量。

#### 镜头身份与重新拆分

每个镜头使用稳定 `shotId`。`ShotListVersion.shots` 的数组顺序是唯一权威叙事顺序；排序不改变镜头身份。内容修改形成新清单版本；拆分和合并创建新身份并记录来源关系。原文对应使用固定剧本版本及稳定文本块 ID，可多对多关联。

重新拆分生成新的计划草稿，提供对比和保留选项，不用行号覆盖原有镜头。已经生成的媒体继续关联其原镜头与内容版本。

#### 验收重点

镜头顺序调整不会串错素材；未确认清单不会自动触发批量付费生成；只修改一个镜头时能够定位该镜头的影响范围。

### 5.3 C03 素材

以下是目标能力；现有实现只有私人图片素材和单个 `assetId` 引用。集合、参考包、素材修订及视频／音频素材接入仍待建设。C03/C04 的字段边界与阶段判断见 [八类创作节点字段草案](creativeNodeFieldDraft.md)。

**用户目标：** 引入已有内容，并把跨镜头复用的主体设定组织清楚。

| 项目 | 规格 |
|---|---|
| 输入 | 文件上传、项目素材库、已授权资产、经安全校验的远程素材地址 |
| 组织模式 | 单素材、同类集合、角色包、场景包、道具／产品包 |
| 主要配置 | 用途、选定版本、名称、说明、参考视角、不可改动项 |
| 输出 | 类型明确的 `AssetRef`、`AssetList` 或 `ReferencePack` |
| 主操作 | 添加素材、选择素材、应用参考包 |
| 功能覆盖 | F03 素材加载、F04 角色设定、F05 场景设定、F06 道具与产品设定 |

#### 加载与使用

上传或引用素材不触发生成模型。显示缩略图／播放、实际格式、尺寸、时长、音轨、来源和权限。资产未上传完成、无法解码或访问失效时不可作为可用输入。

生成节点的结果可直接连接下游，不需要绕经素材节点。素材节点主要用于引入已有内容、明确选择资产以及打包长期复用的设定。

#### 三种参考包

| 参考包 | 主要内容 | 设计目的 |
|---|---|---|
| 角色 | 名称、外貌、服装、正侧面参考、造型版本、已授权参考音频 | 保持不同镜头使用同一外观与造型基准；角色身份和声音模型另行定义 |
| 场景 | 环境、时间、天气、空间关系、光线方向、多个视角 | 统一场景连续性，不把场景仅当成单张图片 |
| 道具／产品 | 外形、材质、颜色、细节图、标识、必须准确的文字 | 管理商品和关键物件的不可改动要求 |

参考包本身不训练模型，也不保证模型精确复现。需要生成定妆图、场景图或产品画面时，选择“创建图片任务”，建立带该设定输入的图片节点，不在素材节点中偷偷执行生成。

#### 引用范围与版本

输出参考包时，下游明确选择使用哪些字段、哪几份文件及其用途，不把整个包无差别发送给模型。更新角色造型或场景版本后，展示受影响镜头；历史结果不被覆盖。

对严格要求准确的包装、商标和文字，允许保留原始图层并在剪辑中确定性叠加。产品中的“不可改动”表示必须保留该要求并进行验收，不表示生成结果天然满足。

#### 媒体工具

将来若在预览内接入裁切、缩放、抽帧或抽音轨，应按实际已实现的操作开放。操作产出独立派生资产，保留原文件与处理配方；需要远程收费处理时先提示。经“另建任务”保留为可连线实例时，按产物类型使用图片、视频或声音节点的处理模式，不增加媒体处理顶层节点。

#### 验收重点

单素材、集合和参考包不可混用；同一资产可按不同用途进入不同任务；更新参考包不会偷偷改写已完成镜头。

### 5.4 C04 导演

以下是目标能力；现有 `directorNode` 仍为占位节点。首版模型优先确定固定镜头版本、明确作用范围和导演意图，轨迹关键点、预演及自动组合待具体规则确定。

**用户目标：** 用拍摄语言表达镜头意图，并将它变成可编辑、可复用的配置。

`DirectorSpec` 保存作用于镜头、镜头组或整份清单的摄影与导演表达配置，包括景别、机位、构图、运镜、视觉风格和表演指导；不拥有 `shotId`、镜头切分边界或叙事顺序。导演可以提出拆镜或重排建议，被采用的结构仍归 `ShotListVersion`。

| 项目 | 规格 |
|---|---|
| 输入 | 单镜头或镜头清单、参考素材、已有导演配置；也可直接建立共享预设 |
| 基础界面 | 一句拍摄要求、常用预设、配置摘要、适用镜头范围 |
| 专业工具 | 摄影镜头表达、运镜／轨迹、风格／光色、表演／走位 |
| 输出 | `DirectorSpec`；显式制作时输出 `PreviewAsset` |
| 主操作 | 应用导演设置；可用时查看构图／轨迹示意 |
| 功能覆盖 | F11 镜头、F12 轨迹、F13 风格、F14 表演、F15 导演指令组装 |

#### 四个工具页

| 工具页 | 基础操作 | 专业扩展 | 必须说明的边界 |
|---|---|---|---|
| 镜头 | 景别、机位、视角、构图、主体位置 | 焦点、景深意图、构图网格、镜头语言 | 数值若仅转为文字，不宣称物理精确控制 |
| 运镜／轨迹 | 推进、拉远、跟随、环绕、固定机位 | 时间关键点、路径、方向、缓动、空间示意 | 轨迹示意不是模型已经执行的轨迹 |
| 风格／光色 | 画风、色调、氛围、光线方向 | 色盘、材质、情绪板、局部覆盖 | 生成风格要求与后期调色是两种操作 |
| 表演／走位 | 动作、表情、眼神、进出画 | 动作节拍、主体路径、起止姿势、多人关系 | 人物运动与摄影机运动分开存储和编辑 |

#### 默认使用方式

简单任务可以只在视频节点中写“缓慢推进”，不强制添加导演节点。需要跨镜头复用或详细控制时，通过“提取为导演配置”建立独立节点，保留来源并避免两处互相覆盖。

一个导演节点可以描述整套拍摄要求。多个同型实例也可分别管理全片风格、场景光色和单镜头运镜；这些实例如何组合与覆盖尚未定稿，首版不自动合并，界面须显示各自的实际作用范围。

#### 轨迹与预演

轨迹关键点采用明确的时间基准；在生成意图中可使用归一化时间，提交前结合目标时长转换。改变时长后重新检查轨迹、动作和对白是否冲突。

预演可以是构图图、路径动画或空间示意视频。它是独立产物，制作和传入模型是两个明确动作。接口不支持视频或姿态参考时，不声称预演能够直接约束模型。

#### 导演要求组装

系统将镜头、主体设定、风格和动作合成与供应商无关的创作包。默认使用确定性规则组装；需要 AI 润色时，通过独立操作确认范围和费用。

生成节点提供“实际生效要求”面板，逐项说明要求来自哪里、如何提交、是否存在冲突或降级。不单独添加“提示词组装”节点。

#### 验收重点

一个面板能完成基础镜头、运镜和风格设置；同型实例可以组合；冲突不静默覆盖；文字意图、参考引导与原生参数清楚区分。

### 5.5 C05 图片

**用户目标：** 生成或修改静态画面，用作角色图、场景图、产品图和分镜关键帧。

| 项目 | 规格 |
|---|---|
| 输入 | 文字、单镜头／镜头清单、导演配置、带用途的参考图片；编辑时需要源图 |
| 任务模式 | 生成、参考图生成、已接入的局部编辑／扩图等模式 |
| 基础字段 | 任务要求、参考素材、模型、画幅、候选数 |
| 进阶字段 | 当前 API 真实支持的尺寸、质量、区域和其他控制参数 |
| 输出 | 图片候选；默认业务输出为已采用的 `ImageAsset` 或镜头关联集合 |
| 主操作 | 生成图片、生成修改版、采用此图 |
| 功能覆盖 | F16 图像生成、F17 图像编辑；调用 F23 媒体处理与通用检查能力 |

#### 模式与输入

纯文字生成不要求提供源图；参考图生成明确图片用途；局部编辑要求源图和实际支持的区域输入。切换模式时重新检查端口与配置，列出即将失效的输入，不静默删除已连接素材。

原图、遮罩、编辑配方和修改结果分别保存。区域编辑界面中的“保留区域”表达用户要求，界面仍需允许检查非目标区域是否发生变化。

普通裁切、缩放和格式转换不以生成式编辑名义执行。输出可保存为派生图片，用同型节点独立串联或直接使用结果端口。

#### 候选与逐镜头生成

候选画廊按镜头和生成批次分组，支持放大、原图对比、采用与备用。新候选不会替换已人工采用的图。

输入镜头清单时，进入“逐镜头生成”模式，显示每项要求、参考图和候选数量。需要细调某项时打开该项侧栏，或提取为独立图片实例并保留镜头身份和归属。

#### 模型切换

模型是图片节点中的执行选项。切换前展示参考数量、用途、尺寸、编辑区域及费用变化。不支持必需能力时阻塞；软要求需要降级时取得明确同意。

#### 验收重点

生成与修改可在同类节点内完成；源图不被覆盖；编辑范围可核查；未采用候选不会悄悄进入视频生成。

### 5.6 C06 视频

**用户目标：** 围绕一个镜头或明确的一段内容生成、修改和采用视频片段。

| 项目 | 规格 |
|---|---|
| 输入 | 镜头要求、分镜、导演配置、已支持的图像／视频／音频参考 |
| 任务模式 | 生成、视频编辑、延展、口型同步；按已接入能力开放 |
| 基础字段 | 模型、任务要求、时长、画幅、参考输入、候选数、声音策略 |
| 编辑附加字段 | 源视频、处理时间段、修改要求、保留内容、区域或主体选择 |
| 输出 | 视频候选；默认业务输出为已采用的 `VideoAsset` 或镜头关联集合 |
| 主操作 | 生成此镜头、生成选中镜头、生成修改版、采用此片段 |
| 功能覆盖 | F18 视频生成、F19 编辑与延展、F25 口型同步 |

#### 参考输入语义

首帧、尾帧、角色参考、场景参考、风格参考、动作参考和音频参考分别标记。只有经验证支持的输入组合可提交，不仅校验每个字段是否独立存在，还校验它们能否一起使用。

如果目标接口只有一般参考输入，没有专用的角色槽，实际生效面板应说明其表达方式，不伪装成更强的原生身份控制。

不强制所有流程先生成图片。视频节点根据已选模式和真实能力接受文字或其他合法输入。

#### 一个镜头与一组镜头

单镜头模式用于逐条精修；逐镜头模式用于处理清单。二者共用镜头 ID、参数覆盖、候选选择、任务与费用记录。

如接入的 API 原生支持一段请求内的多镜头叙事，应作为明确的“合并生成”模式，说明返回的是一个整体片段。不得冒充每个镜头都可以独立重做的逐项批量。

#### 编辑、延展和对口型

编辑与延展保留原片段，提供修改时间段和前后同步预览。普通裁切放在媒体工具或剪辑中，不调用生成模型。

口型同步需要视频和已采用配音，明确目标人物、时间范围、长度策略和原音保留方式。它是额外的视频生成任务，不是一个零成本的“自动同步”开关。人像和声音的使用权限必须满足项目要求。

#### 原生声音与实际时长

视频产物记录实际时长、帧率和是否含音轨。原生音轨保持可查看，在剪辑中明确选择保留、静音或混合；不假定每个视频都有声音，也不默认叠加重复音轨。

目标时长与实际时长分开显示。实际时长与计划不符时，提示裁切、重新生成或调整时间线，不偷偷改速以掩盖差异。

#### 结果与状态

排队、生成、结果接收、文件校验和归档分别记录。供应商返回完成但文件不可用时，不发布正常成功结果。已经成功生成但下载失败时，优先恢复取回，不重新生成。

#### 验收重点

不同模式保持清楚输入边界；仅重做指定镜头；旧候选保持稳定；取消和超时不被虚假描述为免费撤销。

### 5.7 C07 声音

**用户目标：** 创作配音、音乐和音效，并独立试听、修改和采用。

| 项目 | 规格 |
|---|---|
| 输入 | 台词／旁白、音乐或音效描述；可选已授权参考 |
| 创作模式 | 配音、音乐、音效 |
| 上下文工具 | 对已有声音进行裁选、转写、对齐、节拍分析等已实现操作 |
| 输出 | 已采用 `AudioAsset`、逐句音频集合；分析操作可输出 `TimedText` 或 `BeatTrack` |
| 主操作 | 生成配音、生成音乐、生成音效；分析时使用对应明确动词 |
| 功能覆盖 | F20 配音、F21 音乐、F22 音效；承接 F24 音频分析入口 |

#### 三种创作表单

| 模式 | 主要字段 | 组织单位 | 结果检查 |
|---|---|---|---|
| 配音 | 文本、说话人、音色、语言、语速、情绪、停顿、发音要求 | 句子或段落 | 发音、情绪、停顿、实际时长 |
| 音乐 | 情绪、风格、乐器、节奏、结构、目标时长、人声策略 | 音乐段落或整首 | 段落起伏、时长、衔接 |
| 音效 | 声音事件、环境、强弱、持续时间、单次／循环意图 | 声音事件 | 声音内容、头尾、可用片段 |

模式可以由不同 API 执行，不共享一组含糊参数。未支持的音色控制、分轨、循环或参考能力不展示为可用。

#### 配音版本与时间

台词按 `utterance_id` 关联，支持只重生成一句。采用新配音后，剪辑显示对应片段“可更新”，不自动替换已经编辑好的音轨。

预计朗读时长不能充当真实文件时长，字符位置不能充当时间戳。接口没有可靠时间戳时，需要独立对齐或人工调整。

#### 分析与生成的区别

“转写字幕”输出带时间的文字；“节拍分析”输出节奏事件；“生成音乐”输出新的声音。不同操作分别计费和记录，不共用一个“处理声音”按钮。

音频分析可从声音预览、素材预览或剪辑中发起。需要在画布上独立复用结果时，使用声音节点的分析操作。分析不自动卡点，不自动改变摄影机运动，也不替用户无限重生成内容。

#### 授权与验收

音色、人声和参考音频保留授权信息。未授权的声音克隆流程不开放。产品不对素材使用权作笼统的无限制保证。

已有声音可直接从素材进入剪辑，无需经过声音生成节点。声音节点试听通过不等于已完成音画同步，最终同步仍在时间线核验。

### 5.8 C08 剪辑

**用户目标：** 将选定镜头和声音组织成可预览、可交付的作品。

| 项目 | 规格 |
|---|---|
| 输入 | 图片／视频及有序集合、音频、可选镜头顺序、字幕和品牌素材 |
| 基础操作 | 排序、入出点裁切、音量、字幕、基础转场、导出 |
| 专业操作 | 多轨道、速度映射、音频避让、细分字幕样式等已实现能力 |
| 输出 | `TimelineSpec`；成功渲染后为 `DeliveryPackage` |
| 主操作 | 打开剪辑、保存工程、导出成片 |
| 功能覆盖 | F27 时间线、F28 混音字幕、F29 渲染导出；提供 F23、F24、F39 相关入口 |

#### 编辑器结构

专用编辑器包含播放器、素材区、轨道时间线和属性面板。画布卡片只显示工程名称、时长、素材完整性、当前预览和导出状态。

可依据已确认的分镜顺序提出粗剪草稿，用户确认后形成工程。只生成工程不表示已经生成最终视频文件。

#### 素材版本与缺失处理

时间线的每个片段锁定资产版本，记录 `clip_id`、源资产、源入出点、轨道位置和时间映射。新候选返回或源节点采用新版本时，显示更新提示，由用户逐项接受。

镜头缺失、未采用、失效或已被排除时分别标记，不把失败项压缩掉并假装整片完整。用户可以显式跳过、替换或使用占位进行内部预览；正式导出默认阻塞未解决的占位与缺失素材。

#### 混音与字幕

画面自带声音、配音、音乐和音效分别管理。默认显示原音策略，避免重复播放相同内容。

字幕可手动输入、导入或由转写生成。字幕时间基准与源音频版本绑定；裁切、改速和替换音频后重新映射或提示需要对齐。仅修改字幕文字不会修改配音，系统应提醒核对二者是否一致。

#### 导出与交付

导出前检查文件可访问性、素材版本、音轨、字幕、画幅、时长、渲染器支持情况和费用。导出冻结工程快照，用户继续编辑不会改变正在渲染的任务。

完成后显示实际成片、附属字幕和交付文件列表。渲染失败保留工程；保存失败只恢复保存阶段，不重复渲染或生成媒体。

媒体合成通过受控服务执行，不把它包装成新的视频创作请求。预览不支持的效果不得暗示最终导出支持，反之亦然。

#### 验收重点

编辑与导出状态分离；成片可解码并能核验实际规格；换素材必须显式确认；原音、混音和字幕在预览与成片中一致。

### 5.9 C09 工作流

**用户目标：** 将一套成熟流程作为一个节点调用，同时保留内部透明性。

| 项目 | 规格 |
|---|---|
| 输入 | 已发布流程声明的文字、镜头、图片、视频、音频、参考包或其他受支持类型 |
| 配置 | 固定工作流版本、公开参数、输入映射、连接授权、运行与预算限制 |
| 输出 | 发布接口声明的具名业务产物，不根据“最后一个节点”猜测 |
| 主操作 | 运行此工作流、查看内部、复制为可编辑流程 |
| 功能覆盖 | F36 工作流输入、F37 工作流输出、F38 子工作流调用 |
| 扩展设置 | F32 条件规则、F35 数据映射、F39 交付目标、F40 外部触发 |

#### 外层卡片

卡片展示业务名称、固定版本、必需输入、关键参数、预计任务范围、预算和待确认点。运行时展示内部各阶段、逐项进度与失败原因。

工作流输出可以直接连接图片、视频、声音或剪辑。若工作流已完成剪辑与导出，可以直接返回成片，不要求再加一个剪辑节点。

#### 三种复用方式

| 方式 | 用途 | 行为 |
|---|---|---|
| 编组 | 整理当前画布 | 不改变输入输出和执行边界 |
| 模板复制 | 创建可独立修改的新流程 | 副本独立演进，不自动跟随模板更新 |
| 工作流调用 | 使用稳定接口运行已发布方法 | 固定版本，生成真实子执行记录 |

保存模板不等于发布可调用工作流，发布工作流不等于授予调用方使用作者私人素材或模型账号的权限。

#### 发布与接口

选中节点后点击“保存为工作流”。系统分析跨边界输入输出，提出接口草稿。作者在发布面板命名字段、声明类型和必填性、设置默认值、映射内部参数、选择正式输出，并检查资产与连接权限。

工作流输入、输出和变量映射存在于发布配置，不要求普通用户在画布上再搭建接口节点。发布后版本不可原地修改，修改形成新的草稿并另行发布。

#### 运行与恢复

每次调用创建独立子运行，绑定父运行、工作流版本、输入快照、预算和审批范围。人工等待可持久化暂停；关闭页面后可继续处理，不需要重新提交所有内部模型任务。

只允许重试有必要的阶段。返回结果未被采用或缺少必需输出时，工作流等待处理或报告不完整，不将随机候选作为正式返回。

#### 验收重点

固定版本不自动升级；外层能定位内部错误与费用；参数、资产和凭据遵循发布接口；未经授权不触发外部交付。

## 7. 导演要求与 API 能力适配

### 7.1 两层模型

创作层保存用户希望获得的画面与声音，不包含供应商专属请求结构。适配层负责将这些意图转换为当前账号、模型、接口版本和任务模式实际接受的请求。

```text
项目要求 + 分镜 + 主体参考 + 导演配置 + 节点局部要求
                           ↓
                  结构化创作包 CreativeSpec
                           ↓
              冲突检查 → 能力检查 → 生效预览
                           ↓
                  经确认的供应商实际请求
                           ↓
                       远程 API
```

切换模型不破坏创作配置，但必须重新编译并检查兼容性。提交请求和获得符合预期的结果是两件事，产品分别记录。

### 7.2 能力的两种分类

**接入状态**分为“已验证支持”“已验证不支持”“尚未验证”。尚未验证的能力不得作为可靠生产能力自动调用。

**表达方式**分为以下四种，两种分类不能混为一谈：

| 表达方式 | 实际行为 | 用户可见说明 |
|---|---|---|
| 原生参数 | 以接口明确接受的字段提交 | 已作为模型参数提交；结果仍需检查 |
| 参考素材 | 传入对应用途的图片、视频或音频 | 通过参考素材引导，不保证完全复现 |
| 文字意图 | 编译进提示词或文本条件 | 属于软约束，不是精确控制 |
| 不可表达 | 没有经过验证的可用映射 | 当前模式不支持，或尚未验证 |

“原生参数”不意味着结果必然正确；“硬性要求”不意味着模型获得强制执行能力。硬性要求表示系统不得静默移除或降级该要求，并要求对结果进行相应检查。

### 7.3 合并与冲突

按字段合并配置，不按节点连接顺序粗暴拼接。规则如下：

1. 项目锁定约束和主体锁定约束先检查；互相冲突时阻塞，用户必须明确修订。
2. 未锁定字段中，用户确认的单镜头覆盖优先于共享导演配置，共享配置优先于项目默认值。
3. 同一作用域存在多个不同值时，展示来源和差异，要求选择；不得“最后连接的自动获胜”。
4. 文字要求与结构字段相互矛盾时提示冲突，例如“固定机位”与“全程环绕”，不靠追加更多提示词掩盖。

合并后每项要求保留来源、作用范围、锁定状态和生效方式。用户能定位是哪份角色、哪个导演设置或哪段局部文字影响了任务。

### 7.4 生效预览

| 用户要求 | 来源 | 当前提交方式 | 状态 |
|---|---|---|---|
| 角色采用银色短发造型 | 角色包 | 选定参考图与文字 | 可提交，需验收 |
| 缓慢推进 | 导演运镜 | 文字意图 | 软约束 |
| 指定结尾画面 | 尾帧输入 | 当前模式不可表达 | 阻塞，待更换模式或明确移除 |
| 输出画幅 | 项目设置 | 原生参数 | 已映射 |

此表是交互示意，不预设任何具体模型的实际能力。

用户确认软要求降级后，记录被删除或改写的字段、确认人和时间。实质性的模型、参考用途、费用或处理范围变化，需要重新确认；预算、账号密钥和存储策略不进入提示词。

### 7.5 对专业工具的约束

轨迹、姿态、镜头角度和材质等设置必须说明实际如何进入请求。没有进入请求的控件不得保持“已生效”外观。

导演工具可以先用于人工规划与预演，再选择适合的生成方式。无可用执行方式时，配置仍可保存，但生产提交必须明确受阻，不能以假预览替代真实结果。

| `TimelineSpec` | 轨道、片段、素材版本、时间映射、字幕与混音 | 编辑与渲染 |
| `DeliveryPackage` | 成片、附属文件、实际规格、交付状态 | 下载与外部交付 |
| `QualityReport` | 方法、问题、证据、检查范围、人工结论 | 内容与技术检查 |
| `WorkflowDefinition` | 图结构、公开接口、规则、固定版本、权限需求 | 工作流发布 |
| `BatchResult<T>` | 逐项状态、业务身份、顺序、候选、已采用产物、费用 | 批量运行与汇总 |

这些是内部契约，不作为普通用户必须认识的数据类型菜单。界面使用“剧本”“镜头清单”“图片”“角色参考”等业务名称。

### 8.2 单项、集合与参考包

`T`、`List<T>` 和 `ReferencePack` 必须区分。连接方式由用户意图决定：选择一个条目；逐项执行；把整组素材用于同一个接口支持的任务；按镜头 ID 匹配。

系统不得把图片集合自动当作多镜头，也不得把镜头集合悄悄拼成一条提示词。多个人物、多个场景和多个镜头相连时，不自动创建所有组合的笛卡尔积。

如果下游接受单图而上游提供多个候选，必须先选择候选或显式进入集合模式，不根据返回顺序取一张。

### 8.3 连线契约

每条连接至少包含源节点与端口、目标节点与字段、数据类型、单项／集合模式、素材用途、版本绑定策略和缺失值策略。

默认连接表示“下一次执行时读取源节点当前已采用版本”。执行计划确认后，解析结果冻结到快照。已完成任务与时间线不跟随新的采用结果自动变化。

需要固定旧输入时，用户可锁定具体版本，界面显示“已锁定旧输入”。解锁时重新计算影响，不直接重跑。

### 8.4 稳定身份与版本边界

| 身份 | 用途 | 不可替代它的值 |
|---|---|---|
| `node_instance_id` | 哪个画布实例 | 节点显示名称 |
| `shot_id` | 哪个业务镜头 | 当前镜号或行号 |
| `utterance_id` | 哪句台词 | 文本当前位置 |
| `asset_id` + `asset_revision` | 哪一份资产及内容版本 | 临时下载链接 |
| `generation_intent_id` | 哪次明确的新生成 | 网络请求重试序号 |
| `attempt_id` | 同一任务的哪次收费或技术尝试 | 镜头身份 |
| `provider_task_id` | 供应商接受的哪个任务 | 项目业务身份 |
| `workflow_run_id` + `child_run_id` | 哪次父子执行 | 工作流发布版本 |

镜头内容版本、清单顺序版本和剪辑工程版本分开。仅重排镜头只影响顺序相关结果，不使未变的图像和视频生成配方失效。

### 8.5 资产持久化

节点数据保存资产 ID 和版本，不塞入完整二进制文件，也不把供应商临时地址当作永久交付位置。调用时由服务端根据权限生成临时访问地址或按接口要求上传。

结果先登记来源，再安全取回、校验格式与实际元信息并按留存政策归档，最后成为可用业务产物。供应商完成、文件可用和外部交付完成是不同状态。

已获得供应商结果但归档失败时，任务进入取回／归档待恢复状态，优先补偿当前阶段。过期且无法恢复的文件必须显示不可用，不能继续声称可下载。

### 8.6 来源与请求记录示意

```json
{
  "asset_id": "asset_video_003",
  "asset_revision": "r2",
  "media_type": "video",
  "shot_id": "shot_003",
  "shot_revision": "r4",
  "metadata": {
    "duration_seconds": 5.04,
    "width": 1280,
    "height": 720,
    "has_audio": true
  },
  "provenance": {
    "workflow_run_id": "run_100",
    "node_instance_id": "node_video_1",
    "generation_intent_id": "gen_201",
    "input_snapshot_id": "snapshot_300",
    "capability_snapshot_id": "capability_12"
  }
}
```

示例仅用于说明内部结构，数值不代表任何供应商规格。实际媒体元信息必须从返回文件读取和校验。

### 8.7 时间基准

目标时长、实际素材时长、台词时间戳和工程播放时间分别记录。时间线以明确的项目时间基准计算，内部使用可精确表示的时间单位或有理数帧率，不靠显示文字推断。

轨迹归一化时间、音效建议落点和节拍分析结果在落入时间线时执行显式转换。裁切、改速或替换源媒体后，重新映射字幕与声音事件；无法可靠转换时标记待校对。

## 9. 执行计划、恢复与费用保护

### 9.1 用户可发起的执行动作

| 操作 | 执行范围 | 费用行为 |
|---|---|---|
| 检查输入 | 类型、权限、素材可用性、已登记能力与参数组合 | 不调用生成模型；额外分析必须另行确认 |
| 使用已有结果 | 选择已保存版本 | 不创建新的模型任务 |
| 生成此节点 | 当前节点，使用已有上游产物 | 明确显示本次生成范围 |
| 生成选中条目 | 当前集合中勾选的镜头或台词 | 逐项记录并汇总 |
| 运行选中流程 | 明确选择的子图与允许阶段 | 提交前展示所有预期调用和等待点 |
| 运行工作流 | 固定版本定义的计划 | 遵循调用预算、项目预算和审批 |
| 继续执行 | 从已确认、可恢复阶段继续 | 不重新执行已成功且仍适用的收费任务 |

单节点运行缺少输入时，列出缺失项。用户可以补充已有素材或确认补跑依赖；系统不得把“生成此节点”偷偷扩大为“从头生成全部”。

### 9.2 运行前计划

计划包含本次范围、逐项输入版本、操作模式、模型／接口、能力快照、预计调用数、候选数量、媒体处理任务、审批点、预算和可能的降级。

依赖执行结果才能确定的步骤标为待展开。例如先拆分镜头才知道镜头数量，先执行并确认分镜，再生成下一阶段的实际计划，不用虚假总价一次性授权。

显示请求数量时区分逻辑条目数、候选数和实际供应商调用数。一个接口可能一次返回多个候选，平台不得机械地把候选数当作请求数。

### 9.3 冻结与提交

```text
形成计划
  → 校验输入、权限和能力
  → 处理内容审核与费用授权
  → 冻结图、配置、资产、分镜和接口快照
  → 预留可计算的预算
  → 提交远程任务
  → 跟踪状态与取回产物
  → 校验、归档、登记候选
  → 采用／创作确认
  → 在已授权范围内继续
```

执行期间继续编辑生成新草稿，不修改已有快照。回调写入对应运行和候选，不覆盖当前草稿或其他并发运行的结果。

### 9.4 最小状态机

| 状态 | 含义 | 允许的主要动作 |
|---|---|---|
| `idle` | 尚未启动 | 配置、检查输入 |
| `blocked` | 输入、权限、能力或预算不满足 | 修复阻塞项 |
| `validating` | 正在校验计划 | 查看检查进度 |
| `queued` | 已被接受并排队 | 查看状态、请求取消 |
| `running` | 正在执行 | 查看进度、请求取消 |
| `fetching` | 生成已返回，正在取回与校验产物 | 查看结果接收情况 |
| `recovery_required` | 取回、归档等阶段需要恢复 | 重试最小失败阶段 |
| `waiting_selection` | 已有候选但缺少必需采用结果 | 选择候选 |
| `waiting_review` | 等待人工决定 | 通过、退回、保持等待 |
| `succeeded` | 本次操作所需结果已完成 | 查看产物与记录 |
| `failed` | 已知失败 | 查看原因、明确重试 |
| `unknown` | 不确定远程是否接收或完成 | 查询、对账、人工处理 |
| `cancel_requested` | 已请求取消，尚未证实 | 继续跟踪 |
| `cancelled` | 已确认取消或尚未提交即停止 | 查看未执行范围与实际费用 |
| `skipped` | 按已声明规则不执行 | 查看跳过原因 |

生成子任务可以成功，而节点整体因缺少采用结果处于等待选择。批量与子工作流的总体状态由必需阶段推导，不把单个供应商返回字段直接当成整体成功。

### 9.5 超时、去重和恢复

提交超时不等于供应商没有接收。支持幂等键时使用同一生成意图对应的键；支持查询时先对账。无法证明未接收又不能查询时，保留未知状态并提示重复收费风险，不盲目重发。

回调验签、防重放、重复处理去重和状态合并由服务端完成。轮询和回调同时返回时，以同一任务记录事务性处理，避免重复登记资产、费用或触发后续。

失败恢复遵循最小范围：下载失败不重新生成；外部写入失败不重新渲染；某一镜头失败不重跑整批；结构修复若需要再次调用模型，计入独立的有界尝试。

平台不在缺少供应商支持时承诺远程调用严格“只执行一次”。本地防重复提交和远程任务幂等是不同层次。

### 9.6 取消和暂停

暂停批量或工作流首先停止提交新任务。对已提交任务，只有目标接口支持取消时才请求取消，收到明确确认后才标记取消成功。

已经运行的任务可能继续完成并产生费用。取消不等于退款，也不删除已完成的合法结果。前端不得用关闭加载动画代替远程取消。

### 9.7 费用与预算

费用账本至少区分预估、已预留、已发生、待确认、已释放或调整。模型生成、媒体处理、分析和外部交付分别归属到真实计费事件。

已知收费规则时，在每次提交前检查并预留预算，支持并发安全更新。项目预算、工作流预算、单项预算和重试上限同时约束；父层显示汇总，不能再将父汇总与子明细重复相加。

不能可靠估价时显示未知或区间，不提供伪精确金额。如果无法建立可靠费用上界，不承诺绝不超额；改用明确授权、调用数量／并发上限或阻止无人值守运行。已提交任务的最终结算可能滞后，预算面板必须显示待确认费用。

多币种分别记账。需要换算展示时，记录采用的汇率、时间和换算性质，不能把不同币种的数字直接相加。

### 9.8 缓存与新生成

| 意图 | 正确处理 |
|---|---|
| 使用已确认版本 | 引用对应资产，不请求模型 |
| 生成一个新候选 | 创建新生成意图，即使输入相同也不替换成旧缓存 |
| 查询已提交任务 | 使用既有远程任务标识，不创建新生成 |
| 重做确定性媒体处理 | 配方与输入一致且权限、文件有效时可复用 |
| 重试同一技术阶段 | 继续同一运行记录，区分尝试和实际费用 |

缓存指纹包含工作区隔离、操作定义、输入内容／版本、配置、模型可得版本、能力与适配器版本。缓存命中也必须检查权限和文件可用性。

相同输入、固定种子或固定工作流版本都不构成跨模型更新的完全复现保证。平台保存可获取的请求信息和真实产物，使历史结果可追踪。

## 10. 批量、采用、创作确认与质量检查

### 10.1 批量模式

分镜集合连接到生成节点时，提示切换为“逐镜头”。用户选择本次条目、候选数和运行范围后提交，无需放置循环或汇总节点。

批量结果按稳定镜头 ID 关联，显示计划顺序、当前任务、候选数量、采用版本、费用和失败原因。完成顺序不能代替镜头顺序。

共享角色、风格和模型参数可应用到所有条目，单项覆盖单独记录。逐句配音采用相同机制，以句子 ID 作为业务身份。

### 10.2 单项提取

把某一批量条目提取为独立同型节点时，保留原镜头身份、输入来源和历史结果，并明确后续生成归属。

默认规则：该条目的后续生产由独立实例接管；原批量视图显示“由独立节点管理”，通过链接接收其正式结果。不得让两个实例在用户不知情时同时生产或重复计费。恢复批量管理需要显式操作。

### 10.3 汇总与部分成功

批量条目状态包括成功、失败、未知、跳过、取消、等待选择和等待创作确认。汇总保留每个条目的位置和原因，不丢失失败项。

完整性同时检查：需要执行的条目是否结束；必需输出是否可用；必要采用和创作确认是否完成。排队任务全结束，不等于作品已完整。

跳过必须有来源：条件规则、用户排除或明确取消。剪辑收到不完整集合时，展示缺失清单；用户决定补齐、替换或显式缩减作品范围。

### 10.4 候选对比与采用

图像支持并排或滑动对比；视频支持同步预览和关键帧检查；声音支持快速切换和逐句试听。比较功能是节点结果区的共同能力，不要求额外连线。

人工采用记录候选、资产版本、镜头／句子身份、选择人和时间。可以允许“无已有采用版本时，采用首个有效结果”的明确规则，但默认不开启，不用“最后返回”或“看似最好”进行无提示替换。

### 10.5 人工门禁

节点或工作流阶段可开启“确认后继续”。审批面板同时展示内容版本、输入摘要、检查问题、待执行范围和费用授权情况。

审批通过只覆盖相同的内容与范围。换参考素材、实质修改剧本或分镜、切换导致明显能力变化的模型、扩大预算范围后，需要重新批准。仅改变画布位置或节点名称不触发内容重审。

待审超时默认保持暂停，不默认通过。人工等待单独统计，不计入模型推理耗时。内容通过但预算不足时仍不得提交付费任务。

### 10.6 输入变化与影响提示

| 变化 | 应有影响 | 不应发生 |
|---|---|---|
| 仅移动画布节点 | 布局更新 | 媒体失效或重新生成 |
| 仅重排镜头 | 清单和粗剪顺序可更新 | 重新生成全部镜头 |
| 改一个镜头动作 | 对应镜头的生成结果提示输入已更新 | 无关镜头全部失效 |
| 更新共享角色造型 | 展示实际引用该造型的条目 | 静默替换旧参考 |
| 采用新视频候选 | 下游与时间线提示可更新 | 自动覆盖已剪好的片段 |
| 修改字幕文字 | 更新字幕工程并提示核对音频 | 声音自动变成新台词 |

影响计算依据实际输入依赖，而不是简单把节点之后的所有结果全部标坏。用户可继续保留旧版，或选择受影响范围重新生产。

### 10.7 质量与一致性检查

检查面板区分两种结果：技术检查验证可解码性、分辨率、时长、音轨和缺失输入；语义检查提示角色、产品、动作和连续性可能偏离要求。

语义检查必须显示方法、检查范围、采样方式、证据帧或时间段及不确定性。不能把未检查的片段显示为“全部通过”，也不使用无法解释的单一总分替代人工判断。

远程语义分析是明确的可计费任务。检查失败默认产生待办，不自动进入无限重生成；自动重做必须限定范围、次数、预算和停止条件。

## 11. 工作流发布、规则与自动化

### 11.1 发布步骤

| 步骤 | 作者操作 | 系统检查 |
|---|---|---|
| 选择范围 | 选择需要复用的节点 | 跨边界连接、必需依赖、循环和悬空输入 |
| 定义输入 | 命名外部需要提供的内容 | 类型、必填性、默认值和素材用途 |
| 暴露参数 | 选择调用者允许修改的字段 | 范围、枚举、权限和费用影响 |
| 定义输出 | 指定对外返回的正式产物 | 类型、必要采用／创作确认、分支完整性 |
| 设置运行规则 | 设定批量、预算、创作确认与错误处理 | 有界执行、无递归、合法恢复路径 |
| 配置连接需求 | 声明所需模型和存储连接 | 不包含明文密钥、隐私默认素材 |
| 测试 | 使用授权样例检验映射与结果 | 分清无调用校验与真实付费测试 |
| 发布 | 确认名称与固定版本 | 定义不可原地变更，调用方显式升级 |

初始封装可以将选区替换为一个工作流实例，也可以只保存到库中，选择由用户确认。原有运行历史和资产不因封装而丢失。

### 11.2 输入输出契约

输入字段包含名称、类型、必填、默认值、帮助文案、素材用途和允许范围。发布版本不得隐式依赖父画布未声明的节点或私人资产。

输出字段包含名称、类型、必需性和来源。运行元数据、供应商调试信息和业务输出分离，不默认向调用者暴露全部内部日志。

```json
{
  "workflow_id": "shot_production",
  "version": "1.0.0",
  "name": "镜头生产",
  "inputs": {
    "shot": {"type": "ShotSpec", "required": true},
    "references": {"type": "ReferencePack", "required": false},
    "direction": {"type": "DirectorSpec", "required": false},
    "first_frame": {"type": "ImageAsset", "required": false}
  },
  "exposed_parameters": {
    "model_profile": {"type": "String", "required": true},
    "candidate_count": {"type": "Integer", "minimum": 1, "default": 1}
  },
  "outputs": {
    "selected_video": {"type": "Selection<VideoAsset>", "required": true},
    "shot_id": {"type": "String", "required": true}
  },
  "execution_policy": {
    "requires_selection": true,
    "allow_recursive_calls": false,
    "partial_success": "report_incomplete"
  }
}
```

候选数量的可用上限在执行时由接口能力和预算共同决定，发布表单不能绕过验证。固定工作流版本不保证供应商的可变模型别名永远保持同样行为，运行中记录实际可得模型信息。

### 11.3 数据映射与变量模板

映射面板使用“来源字段 → 目标字段”的可视方式，支持字段选择、重命名、受控模板、按业务 ID 匹配、过滤和排序。缺失字段提供明确错误或已声明的默认值。

允许将分镜动作和导演描述组装成文字，但不允许把缺失素材伪造为占位地址、把对象默默变成字符串，或把整份参考包无差别传给所有模型。

样例预览展示输入、转换结果和错误位置。映射运行在受控表达式环境，不访问网络、文件系统或凭据，不执行用户任意代码。超长输入、集合规模和表达式复杂度均有限制。

### 11.4 条件规则

条件规则位于工作流设置，按结构化数据选择已声明路径。适用场景包括“有首帧时使用图像输入路径”“无对白时跳过配音”“未通过技术检查时等待处理”。

条件组采用可解释的互斥顺序：按展示顺序匹配第一条满足的规则，其他路径标记跳过；必须定义无命中时的处理。空值、未知任务状态和类型不符不能自动当作条件通过。

被规则控制的节点显示“按条件执行”标记。运行预览显示条件、实际输入、命中原因、启用节点和跳过范围；复杂度不应变成无法查看的隐藏逻辑。

规则只能控制已经声明的节点、操作或子工作流，不从模型文本中临时生成任意调用。每条路径都必须产生必需输出，或声明明确的不完整／等待状态。汇总不得永久等待原本就不会执行的路径。

首期以固定路径为主，条件工具按自动化阶段开放，不额外新增条件顶层节点。

### 11.5 嵌套、暂停与恢复

父子运行保存清楚的树状关系。首期支持项目调用一个已发布工作流，内部不再递归调用其他工作流；需要扩展时受平台层级上限限制，始终禁止直接和间接自调用。

每个等待点保存当前输入、采用版本、审批对象和已完成任务。恢复前复核权限、素材有效性、预算以及审批是否仍适用；不能因为流程曾经通过校验就忽略后续撤权。

内部输出未选定时父流程等待。用户替换候选只更新选择与必要的下游阶段，不强制重做前面的生成任务。

### 11.6 工作流升级

发布新版本后，旧调用实例继续固定原版本。升级前展示接口变化、参数变化、模型需求、费用和权限变化，必要时重新映射和审批。

运行中的调用不原地升级。当前供应商已下线或权限不可用时，旧版本应显示阻塞并建议显式处理，不悄悄改用另一模型。

### 11.7 结果保存与外部交付

内部归档是资产系统职责；用户指定外部存储、交付目录或分享目标，是额外的有副作用操作。

交付配置至少包含目标、访问权限、命名、覆盖策略、保留时间和是否公开。默认新增版本，不默认覆盖或公开分享。

外部写入单独生成交付记录和回执。重复尝试使用明确的交付幂等标识；保存失败时只重试写入。不能为了“重新保存”再次调用视频模型。

### 11.8 外部触发

已发布工作流可在自动化设置中启用认证请求、事件或定时入口。入口固定使用某个发布版本，填写输入映射、允许调用方、素材权限、速率、事件去重、并发、预算和人工门禁。

外部触发不能绕过类型验证、内容检查和费用授权。只有预先批准范围内的任务可以无人值守执行；无法可靠估费且没有可接受控制措施时，停在待确认阶段。

重复事件不重复创建同一业务运行。平台记录事件 ID、触发来源和因果链，防止“产物保存事件再次触发自身”的无限循环。关闭触发入口只阻止新运行，不假称已经取消正在运行的任务。

测试分为“只验证输入”和“真实运行测试”，后者明确计费。外部调用响应返回受权限控制的任务状态与结果，不泄露密钥或私人素材地址。

## 12. 服务与工程实现边界

### 12.1 系统分层

```text
创作界面
  画布 / 节点面板 / 专业编辑器 / 模板入口
                         ↓
领域服务
  剧本 / 分镜 / 资产 / 导演 / 剪辑 / 工作流版本
                         ↓
执行服务
  计划 / 类型校验 / 创作确认 / 内容治理 / 预算 / 批量 / 恢复
                         ↓
能力注册与适配
  模型操作 / 素材用途 / 参数转换 / 费用规则
                         ↓
远程模型 API 与媒体服务 API
                         ↓
结果归档、任务记录与费用账本
```

九类节点是前端和领域层的稳定概念，40 项能力是操作与服务边界。它们不要求分别对应 9 个或 40 个微服务，也不要求每项能力都采用模型实现。

### 12.2 节点定义与操作定义

节点定义负责名称、模式、输入输出、默认面板和通用交互。操作定义负责本次运行需要的输入、配置、验证、执行方式、产物和费用。

例如视频节点选择“延展”时，执行 `video.extend` 操作；选择“对口型”时执行 `video.lipsync` 操作。两者共用卡片和历史体验，但各自保留输入契约、任务和收费记录。

确定性媒体操作、生成任务和选择／创作确认操作不可混用生命周期。保存配置不产生伪生成任务，候选采用不重新请求远程模型。

#### 运行时兼容映射

九类用户节点与当前 Toonflow 运行时插件不要求一一对应。现有实现按以下方式兼容，不因迁移立即改写历史画布类型：

| 当前运行时类型 | 用户节点归属 | 新增入口的解释 |
|---|---|---|
| `textNode` | C01 剧本 | 作为手动编辑、创作或改写模式的适配器；普通旧文本继续兼容读取 |
| `promptNode` | 所属节点的配置草稿或封装 Prompt 工具 | 不长期扩张为第十类用户节点 |
| `imageNode`、`videoNode`、`audioNode` | C03 素材 | 由同一素材节点按媒介类型选择渲染适配器 |
| `imageGenerationNode` | C05 图片 | 承接图片生成模式；编辑模式可由其他适配器补充 |
| `videoGenerationNode` | C06 视频 | 承接视频生成模式；延展、编辑和口型分别使用独立操作定义 |
| `director3dNode` | C04 导演 | 作为后续专业编辑器，不作为 V1 默认导演形态 |
| `workflowReference` | C09 工作流 | 保留项目已引入固定版本的引用语义 |

项目画布和独立工作流图必须消费同一节点定义、端口校验和保存语义。产品页面可以有不同外壳，但不得各自维护一套不兼容的节点数据模型。

### 12.3 节点 UI 的设计与实现顺序

节点 UI 必须先建立一个共用布局模块，再按版本范围逐个补充具体节点。Coding Agent 不得从 C01 到 C09 同时复制九张独立卡片，也不得先写完整节点页面、最后再抽取共用结构；这种做法会让状态、端口、费用和交互在九类节点之间失去一致性。

#### 第一阶段：先完成一个共用节点布局

在实现任何一类节点的完整 UI 前，先选择一个当前版本确实可运行、能覆盖输入、结果和付费执行的代表节点进行布局设计。当前优先使用已经接入的图片或视频生成节点；若施工基线变化，则选择当时最完整的一个真实节点，不为验证布局制作假业务能力。

这个阶段只解决所有节点共用的界面接口：

| 共用区域 | 必须表达的内容 | 约束 |
|---|---|---|
| 节点头部 | 业务类型、实例名、当前模式、必要警告 | 普通用户不依赖 C01 等内部编号识别节点 |
| 端口区域 | 具名输入输出、业务类型、单项／集合、素材用途和连接状态 | 端口位置和样式一致；不把连接顺序当优先级 |
| 状态摘要 | 执行、采用、创作确认、新鲜度四个维度 | 不压缩成一个“成功／审核通过”标签 |
| 内容摘要 | 当前输入、正式输出或已采用候选的最小预览 | 节点卡不是完整表单，不堆放所有专业参数 |
| 主操作 | 当前上下文唯一最重要的下一步 | 最多突出一个；付费动作同时显示范围与费用 |
| 详情入口 | 打开右侧面板、专业编辑器、候选、历史或执行详情 | 复杂编辑离开卡片完成，不无限增高节点 |
| 运行反馈 | 缺输入、排队、运行、部分结果、失败、未知和恢复入口 | 返回结果不得覆盖任务开始后的新草稿 |

共用布局必须直接放进现有 Vue Flow 画布验证，而不是只在静态卡片列表中评审。至少覆盖默认、选中、连接中、缺输入、运行中、有候选、输入已更新、失败和禁用状态，并检查常用桌面宽度、缩放、节点重叠、长名称、长错误信息和键盘焦点。

通过条件是：同一个布局无需修改外壳结构，即可仅通过节点定义、操作定义、端口定义和内容插槽承载至少两种差异明显的节点。若图片节点与视频节点仍需要复制整张卡片才能成立，说明共用模块的接口过浅，应先继续收敛布局，不进入下一阶段。

#### 第二阶段：逐个补充节点专属 UI

共用布局通过后，Coding Agent 才能按 `requirements/92-版本范围与需求基线.md` 的开放顺序逐个设计和实现节点。每次只完成当前节点已进入施工范围的模式、字段、预览和专业工具；未开放的节点保留产品与数据契约，不创建可点击空壳。

每个节点的补充顺序统一为：

1. 读取本文对应节点章节、版本基线和主责模块需求，确认当前阶段真正开放的操作。
2. 将输入、输出、主操作和四维状态装入共用节点布局，不先新增节点私有外壳。
3. 只为无法由共用插槽表达的内容增加专属区域，例如分镜表、候选对比、波形或时间线摘要。
4. 在右侧面板或专用编辑器补充详细配置，节点卡保留摘要和下一步。
5. 验证端口连接、保存恢复、运行快照、候选采用、创作确认、费用确认和错误恢复后，再进入下一类节点。

节点专属实现应作为共用布局模块的适配器或插槽内容。差异属于内容时不建立新布局；只有真实交互结构发生变化且至少存在第二个适用节点时，才新增内部接口或布局变体。

#### 当前 UI 参考稿的使用方式

[`node-design.html`](./node-design.html) 可以引用以下设计方向：

- 紧凑、专业、偏生产工具的视觉语气；
- 付费动作在操作附近展示费用，运行前按阶段解释范围；
- 版本、候选、采用结果、具名输入和工作流内部步骤可见；
- 创作确认点、预算保护和固定工作流版本有明确提示；
- 九类节点使用一致的头部、状态和操作层级。

不得把该参考稿整体复制成新页面。实现应复用当前工作区的 Vue Flow、节点菜单、画布工具、素材库、Element Plus 交互和 Tabler 图标，并沿用现有主题变量。参考稿中的 Tailwind CDN、Google 字体／图标依赖、固定侧栏和静态三列卡片只服务视觉探索，不进入生产实现。

#### 参考稿已知问题与修正要求

| 问题 | 当前表现 | Coding Agent 必须如何修正 |
|---|---|---|
| 页面定位混合 | 同一页面同时承担画布、节点配置、网关监控、费用审计和规格矩阵 | 画布只保留创作主链；详细配置进入右侧面板，网关与审计信息进入执行队列或运营入口 |
| 不是真正节点画布 | 九类节点以三列大卡片纵向排列，底部却出现选择、连线和平移工具 | 在现有 Vue Flow 中验证节点与连线；静态总览只能作为规范展示页 |
| 完整蓝图被表现为当前可用 | C01～C09 同时显示完整操作和价格 | 标明目标态；生产节点库只展示当前已实现、已验证且有权限的子集 |
| 创作确认与治理混用 | 使用“审核：已通过／免审”“导演人工审核门禁”“审核门禁授权”等文案 | 流程等待统一使用“创作确认／人工门禁”；M14 决定单独显示为内容治理、授权或隐私状态 |
| 采用、选择和确认混用 | 勾选镜头、采用数量和待确认状态同时出现，但关系不清楚 | 分别显示本次选择、正式采用和创作确认；任何一项不得推导另外两项 |
| C09 筛选失效 | C09 放在 `creation` 父容器内，选择“复合与复用”时父容器被隐藏 | 筛选作用于同一层级的节点数据，不依赖互相嵌套的 DOM 分类 |
| 费用口径冲突 | C09 卡片显示 `48～64` 点，运行弹窗显示约 `35` 点 | 运行前计划基于本次实际范围重新报价，并解释总预算区间与本次预估的差异 |
| 时间数据冲突 | 分镜合计 `10.5s`，项目与剪辑显示 `12.5s`；同一镜头出现 `3s` 和 `5s` | 所有时长读取同一业务对象和版本；计划时长与实际媒体时长并列时明确标签 |
| 交付与素材身份混用 | 文案写“MP4 归档至 CDN 资产节点” | 改为 M04 可靠交付副本；只有用户明确另存后才创建 M05 素材或 M06 作品 |
| 技术遥测抢占创作界面 | 网关集群、缓存命中率、幂等哈希和“零本地显存”占据首屏 | 用户端只显示影响当前操作的可用性、等待、费用和恢复信息；内部指标进入运营视图 |
| 响应式与视觉故障 | `h-13`、`top-13`、`pt-13` 等无效尺寸导致顶栏遮挡；外部图标失败时显示英文图标名 | 使用项目现有样式系统和图标组件；在实际工作区尺寸验证顶栏、侧栏、缩放和降级表现 |
| 信息密度过高 | 大量 9～11px 文字、长标签和多层卡片同时出现 | 节点卡只保留摘要；正文不低于项目可读字号，详情按需展开 |
| 弹窗无障碍不足 | 预算弹窗缺少对话框语义、标题关联、焦点管理和 Escape 行为 | 复用现有对话框模块，提供可读名称、焦点圈定、键盘关闭和返回焦点 |
| 假交互与键盘缺口 | 多个模式使用 `span` 或普通容器模拟按钮 | 所有交互使用真实可聚焦控件，提供选中状态、可读名称和键盘操作 |

参考稿修正不是单独的“美化阶段”。上述问题在共用布局或对应节点首次实现时处理；不得先照搬问题，再以未来重构为由延期。

### 12.4 能力注册

能力按供应商、端点、模型可得版本、任务模式、账号权限和服务区域记录。每份记录至少包含：

| 内容 | 要求 |
|---|---|
| 支持状态 | 已验证支持、已验证不支持、尚未验证 |
| 输入 | 类型、数量、用途、组合限制、文件要求 |
| 参数 | 时长、画幅、尺寸、音频策略、编辑范围等真实可用参数 |
| 输出 | 类型、候选结构、时长／音轨信息、文件获取方式 |
| 生命周期 | 同步／异步／流式、查询、回调、取消、幂等支持 |
| 费用 | 计量单位、估算方法、结算方式、未知费用情形 |
| 追溯 | 验证时间、能力版本、适配器版本、已知限制 |

UI 表单来自产品定义与已验证能力的交集，不直接把供应商全部原始参数暴露给用户。能力未知或账号未授权时不能靠前端放开按钮绕过服务端。

### 12.5 适配器职责

| 职责 | 行为 |
|---|---|
| 读取能力 | 获得当前执行上下文的能力快照 |
| 验证输入 | 检查素材、用途、参数组合和权限 |
| 编译请求 | 将创作包转换为供应商请求，生成生效／降级报告 |
| 估算成本 | 返回有依据的金额、区间或未知状态 |
| 提交任务 | 记录生成意图、实际请求和供应商标识 |
| 查询与对账 | 在不重复创建任务的前提下恢复远程状态 |
| 处理回调 | 验证来源、去重并更新正确运行 |
| 取回产物 | 按权限下载、校验并归档 |
| 请求取消 | 只在支持的范围执行，不虚构取消成功 |

供应商切换或故障转移只允许在用户授权的范围内进行，必须重新验证能力、数据去向和预算。远程状态未知不构成自动切换另一供应商重复生成的理由。

### 12.6 核心存储对象

| 对象 | 存储内容 |
|---|---|
| 项目与画布版本 | 节点、连线、布局、项目约束及草稿 |
| 内容与资产版本 | 剧本、分镜、导演配置、媒体、来源和权限 |
| 采用与创作确认记录 | 被采用对象、创作确认范围、决定与时间；M14 治理记录独立保存 |
| 工作流发布定义 | 固定图结构、接口、规则、连接需求 |
| 运行与条目 | 父子关系、计划、快照、任务、状态与错误 |
| 收费与交付事件 | 计量、预留、结算、外部写入及回执 |

资产文件与业务元数据分开存储。前端重开项目通过已有运行恢复状态，不靠重新请求模型重建界面。

## 13. 权限、安全与数据管理

### 13.1 最小权限

| 角色 | 基础权限 |
|---|---|
| 查看者 | 查看授权的项目、产物和必要运行摘要 |
| 创作者 | 编辑内容、选择候选，在授权预算内发起任务 |
| 创作确认者 | 对指定版本和执行范围通过或退回；不因此获得 M14 治理权限 |
| 项目管理员 | 管理成员、预算、连接权限、发布与外部交付 |

具体权限按项目配置，不能因用户能编辑节点，就默认允许他使用所有付费账号、公开分享素材或改变预算。生产提交、跨项目资产读取和子工作流调用时重新检查权限。

### 13.2 凭据与数据去向

模型密钥、存储凭据和回调密钥只保存在服务端受控系统，不进入节点 JSON、模板、提示词或可下载日志。工作流只声明连接需求，由有权限的调用方绑定。

模型切换、工作流安装和外部交付显示素材将发送到的服务。复制模板不自动复制私人文件和作者的授权能力。

### 13.3 输入处理

文档、字幕、网页内容和模型返回文本都是业务数据，不能直接成为执行器指令。模型输出经过结构校验后才能进入受控字段，不允许借助文本启动任意网络请求或付费流程。

远程素材抓取限制协议、重定向、大小、超时和内网地址；检查实际内容类型，不仅检查扩展名。文件解析在隔离环境完成。大规模输入、批量条目和长文本需要资源上限。

### 13.4 素材授权与留存

对人像、声音、角色和品牌素材保留必要来源与授权说明。敏感或不适用的内容按项目和接入服务规则处理，不提供默认无限制的素材使用承诺。

素材删除前显示影响范围。留存期限、公开分享、外部交付和删除政策清楚可见；审计记录不等于永久保留所有媒体。删除或撤权后，历史记录可保留必要元信息，但不得通过缓存绕过新的访问限制。

## 14. 典型创作流程

### 14.1 已有图片做成视频

```text
素材「产品主图」 → 视频「产品展示镜头」
```

用户上传或选择图片，指定合法的输入用途，填写简单动作要求，查看本次费用并生成。采用后直接获得视频片段。无需加载剧本、拆分分镜或配置专业导演工具。

### 14.2 文案到视觉片段

```text
剧本「创意描述」 → 图片「关键画面」 → 视频「镜头片段」
```

图片节点产生候选，用户采用后才作为视频输入。修改创意后，已采用图片和视频保留，系统提示输入更新，由用户决定重做哪一步。

### 14.3 剧本转短片

```text
剧本 → 分镜 → 视频「逐镜头生成」 → 剪辑
```

先确认镜头清单，再逐项生成视频。缺少参考图片时，根据所选模式补充素材或图片节点。剪辑按确认顺序接收已采用片段，并明确显示缺失项。

### 14.4 角色连续性与导演控制

```text
主流程：剧本 → 分镜 → 导演 → 图片 → 视频 → 剪辑

素材「角色包／场景包」 → 导演、图片、视频
分镜与导演配置 → 视频
声音「配音／音乐」 → 剪辑
```

导演配置可同时影响图片与视频，原始分镜也作为明确输入保留。角色包、场景包和图片在具体接口中承担什么用途，需要逐项映射。不同镜头可覆盖运镜，不需要复制整套角色设定。

### 14.5 保留原片段并单独测试口型

```text
素材「原视频」 ───┐
                 ↓
声音「角色配音」 → 视频「口型同步」 → 剪辑
```

原视频与修改版分别保留。口型操作单独确认费用与授权，失败时不影响原视频。采用修改版后，剪辑再决定是否替换。

### 14.6 复用产品短片工作流

```text
素材「产品参考包」 → 工作流「产品短片」 → 成片输出
```

流程内部可以包含剧本、分镜、导演、图片、视频、声音和剪辑。外层用户只填写公开输入与参数，但可查看内部任务、候选、创作确认与预算。工作流已经包含渲染时，不重复添加剪辑节点。

### 14.7 只修改一个镜头

用户修改镜头 03 的动作或导演设置，查看影响预览，只为该条目生成新候选。采用新片段后，时间线定位对应位置，用户确认替换并核对长度与音轨，再选择是否重新导出。

其他镜头、已有音乐和已完成任务不重新生成。重新导出是渲染任务，不是整条创作流程重跑。

## 15. 实施范围与上线顺序

### 15.1 分阶段原则

节点分类保持稳定，按能力深度逐步开放。版本范围以 `requirements/92-版本范围与需求基线.md` 为唯一施工基线；本文只说明节点体系内部的依赖顺序，不独立提高任何功能的版本优先级。

基础状态、输入校验、采用、预算、权限、归档和失败恢复随核心闭环交付，不作为可省略的后期优化。

### 15.2 V1：当前施工基线

V1 只开放版本基线已列入首发、已经实现并通过能力与权限校验的节点入口。当前目标是完成项目／画布保存恢复、素材引用、少量封装 Prompt 工具、已验证的单节点图片／视频生成、报价确认、任务投影、可靠交付、候选选择和继续创作。

- 执行范围以单节点确认为主，不开放用户批量生成、批次部分成功或整条复杂工作流自动运行。
- 工作流先完成独立定义、固定版本、项目引入和引用节点；运行能力按 M04 与版本基线另行开放。
- 剧本、分镜、声音、导演、剪辑等分类可以保留契约和兼容数据，但未达到本版开放条件时不展示空入口或假按钮。
- M04 自动保存的可靠交付副本不等于 M05 素材或 M06 作品；后两者必须由用户明确创建。

### 15.3 V1.x：专业内容与批量执行

在核心闭环稳定后，按版本基线评审剧本／分镜专业模式、角色／场景／道具参考包、声音生成、固定路径工作流运行、逐镜头／逐句批量和子任务独立结算。批量能力必须先具备逐项状态、费用、恢复、未知态和部分成功验收，不能用一个总状态替代。

图像编辑、视频编辑／延展、音频转写／对齐、轨迹关键点、表演工具等能力按真实供应商、媒体服务和授权条件逐项启用，不因本文已有设计而默认进入 V1.x。

### 15.4 后续：剪辑、专业导演与受控自动化

完整剪辑、专业混音字幕、三维导演工具、口型同步、语义一致性检查、条件规则、外部交付、事件／定时触发和有限层级嵌套均属于后续候选。每项开放前必须具备真实执行链、清楚费用、版本保留、失败恢复与验收用例。

自动化以固定版本、预授权范围、可解释规则、有限重试和预算为前提。无人值守执行不能依赖用户看不到的隐式判断。

### 15.5 功能目录与版本基线的关系

F01–F40 是完整产品的需求索引，不是版本承诺。每项能力的实际阶段按 `requirements/92-版本范围与需求基线.md` 及对应模块 PRD 判断；同一能力可以只开放基础深度，后续再增加模式。任何阶段都不改变九类用户节点的分类原则，也不允许未接入能力以可点击入口出现。

### 16.2 学习成本测试

以首次使用者执行以下任务，观察其是否能够在不理解底层技术的情况下找到入口并预测结果：把已有图片做成视频；导入剧本并确认分镜；只修改一个镜头；将现成工作流用于自己的素材。

## 17. 产品一致性准则

**用户只需要学习九类创作工位；系统必须承担完整的执行复杂度。**

所有功能遵守以下准则：同类任务通过模式和实例表达；已有内容可以直接进入任意合法阶段；专业控制必须说明实际生效方式；付费任务必须明确范围；采用与创作确认绑定具体版本；批量不丢失单项身份；复用不隐藏内部成本；保存和剪辑不冒充生成；未支持能力不伪装为可用功能。

判断一个设计是否成立，不在于画布上有多少节点，而在于用户能否清楚回答：我正在做什么、使用了哪些内容、这次会执行什么、会影响哪里、发生失败怎样恢复，以及哪个版本最终进入作品。
