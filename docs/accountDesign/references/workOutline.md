### 最新确认的产品方向

- 客户使用统一 Cruio 账号，不要求客户登录 TF-Router/NewAPI 或手工填写模型服务地址和 API Key。
- 当前阶段由运营后台手工配置模型接入；现阶段已有本地 NewAPI 控制台，不代表 Cruio 已具备管理员后台。
- 后续可考虑将 NewAPI 的充值、用量及 API 能力集成在 Cruio 内，不引导客户跳转供应商平台；具体接口、账本与实现范围待核实。
- 下一阶段先确定账号、凭证、权限与数据边界，再实施客户入口裁剪。原定桌面端、本地项目方案继续保留；是否增加多人 Web 部署需单独确认。

以下原始清单仍作为整体范围和最终验收要求。复合条目只有全部满足才勾选；本节记录已完成的部分进度。

## 1. 目标与范围

保留 Toonflow 已有的创作功能和主要交互，用 Cruio 品牌对外提供桌面客户端。用户安装后必须登录，模型调用统一接入已经独立部署的 NewAPI 服务，项目文件保存在用户本地，约定的软件使用数据同步至服务器数据库。

### 已确认的开发范围

1. 将用户可见的 Toonflow 品牌替换为 Cruio。
2. 增加用户体系，客户端必须登录才能使用。
3. 将 TF-Router 替换为我们的模型供应商，底层接入独立 NewAPI 服务。
4. 裁剪不需要开放给用户的设置与入口。
5. 保留本地工作目录，将约定的软件使用数据同步至服务器数据库。

### 明确不做

- 不重做画布、编辑器、节点、素材库等已有创作功能。
- 不把项目组织、素材复用、角色相关创作、模板或导出等笼统列为新增功能；沿用当前版本已有能力，具体功能是否满足需求再按实际界面核验。
- 不开发、部署或改造 NewAPI 服务本身，不重建其模型渠道、上游调度和计费系统。
- 不新增自研模型网关，接入方式按现有 NewAPI 能力确定。
- 不主动扩展团队协作、完整项目云同步、创作流程重构等产品方向。
- 本大纲不额外展开数据恢复、任务中心、自动更新、发布运维、运营后台等工作。

本文中的“待确认”和“可选”不代表已纳入开发，不因列入文档自动实施。

## 2. 产品与服务边界

| 部分 | 职责 | 本次处理方式 |
| --- | --- | --- |
| Cruio 客户端 | 登录入口、现有创作界面、本地文件操作、自有供应商调用、使用数据同步 | 主要改造对象 |
| 客户端内置本地服务 | 继续承接已有本地文件、插件和模型调用适配 | 复用已有实现，增加必要的身份与配置限制 |
| 账号与使用数据服务 | 用户身份、会话、账号数据及约定的使用数据存储 | 优先接入已有服务；没有现成服务时，必要接口是独立待开发项 |
| 独立 NewAPI 服务 | 提供已经部署的模型服务及其现有配套能力 | 仅对接，不在本项目开发其内部功能 |

客户端登录与 NewAPI 调用凭证之间的关联需要明确，但不预设必须新增一套转发服务。

如果采用客户端直接调用 NewAPI，应使用用户级、可撤销的调用凭证；不得在客户端内置 NewAPI 管理密钥或所有用户共用的高权限密钥。

保留开源许可证、版权及第三方必要归属信息。品牌展示替换与开源归属信息分别处理。

**完成标准：** 用户正常使用路径呈现 Cruio 品牌；已有项目仍能读取；没有因字符串替换破坏文件格式或内部调用。

## 4. 用户体系与强制登录

### 4.1 登录流程

- [ ] 确定账号来源：自有用户服务，或复用独立服务已有身份能力。
- [ ] 按选定的身份服务实现登录页面与接口对接。
- [ ] 未登录启动时进入登录页，登录成功后进入项目页面。
- [ ] 移除当前可绕过登录进入工作区的“稍后配置”等路径。
- [ ] 恢复有效登录状态；登录失效时明确提示并引导重新登录。
- [ ] 提供当前账号信息与退出登录入口。

注册、找回密码的交互取决于账号来源：可接入既有页面或接口，不默认同时建设多种登录方式。

### 4.2 访问限制

- [ ] 页面入口、本地受保护接口和云端账号接口均检查必要的身份状态。
- [ ] 云端数据访问以服务端会话识别用户，不能直接信任客户端传入的用户 ID。
- [ ] 账号切换后刷新个人配置、模型凭证及同步上下文，避免把前一账号的数据上传给后一账号。
- [ ] 按桌面平台合适的安全存储方式保存凭证，不放入项目文件。

本地项目属于用户磁盘文件，应用内登录限制不等于对本地文件实施加密或阻止设备所有者直接访问文件。

**完成标准：** 未登录无法进入正常创作流程；登录后可使用原有功能；退出或切换账号后不会继续以旧账号访问服务。

## 5. 自有供应商与 NewAPI 接入

### 5.1 接入前需提供的信息

- [ ] NewAPI 服务地址、实际部署版本及可用接口说明。
- [ ] 用户调用凭证如何取得，以及与客户端登录账号的关联方式。
- [ ] V1 对外开放的模型清单。
- [ ] 各模型实际支持的文本、图片、视频、音频及参考输入能力。
- [ ] 如需展示余额、用量或充值入口，提供现成接口或页面地址。

不假定部署中的 NewAPI 同时支持 Toonflow 所有节点，也不假定所有媒体接口采用同一协议。缺少能力时先列出差异，由产品决定隐藏对应能力或采用现有可用模型；不自动把差异转成 NewAPI 开发任务。

### 5.2 替换工作

- [x] 复用当前供应商机制，接入一个自有供应商（Cruio/NewAPI）。
- [ ] 对接实际可用的模型目录和用户调用凭证。
- [ ] 替换文本模型、图片、视频、音频中实际依赖 TF-Router 的调用适配。
- [ ] 同步检查节点、内置助手、媒体生成工具等模型调用入口，避免只修改设置页。
- [ ] 根据模型真实能力显示参数与输入限制。
- [ ] 映射常见服务错误，保留可读的登录失效、模型不可用、额度不足等提示。
- [ ] 清理默认 TF-Router 安装、初始化及自动配置逻辑。
- [ ] 老项目引用旧供应商或旧模型时，保留内容并提示重新选择可用模型。

对已有的生成、取消和结果展示流程做协议适配，不另建新的模型任务管理产品。

### 5.3 用户侧表现

- 用户只看到我们的供应商，不需要手动填写服务地址和 API Key。
- 用户可在已经开放的模型范围内选择模型。
- 现有文本与媒体模型分类可以继续保留；一个供应商不要求重做模型选择界面。
- 余额、充值与 API 能力后续考虑站内集成；当前阶段由运营手工配置，客户不跳转供应商控制台。具体账本权威与接口能力仍待确认。

**完成标准：** 所有纳入 V1 的模型入口使用自有供应商；实际模型请求不再依赖 TF-Router；已有创作交互保持可用。

## 6. 设置与功能入口裁剪

### 6.1 已明确需要裁剪的内容

- [ ] TF-Router 的登录、账号、充值及相关品牌入口。
- [ ] 普通用户新增、导入、删除其他模型供应商的入口。
- [ ] 自定义 API 地址、API Key 和供应商代码编辑入口。
- [ ] 普通用户使用的供应商调试入口。
- [ ] 可恢复默认 TF-Router 配置的初始化或重置路径。

界面和对应配置接口同步限制。现有通用设置保存接口需要明确哪些字段允许普通用户修改，不能只把按钮隐藏。

### 6.2 直接保留

- 界面外观、语言、快捷键、画布操作等创作偏好。
- 本地项目及工作目录操作。
- 现有画布、文档、素材、节点及必要的内置工具。
- 自有供应商下的可用模型选择与参数设置。

### 6.3 裁剪前需确认

| 入口 | 需决定的范围 |
| --- | --- |
| 插件市场 | 是否仅保留内置插件，是否允许外部插件安装 |
| 云端探索 | 当前依赖 TF 内容服务；需单独决定暂不开放还是后续迁移，不能视为模型接入替换的一部分 |
| MCP | 是否向普通用户开放外部连接 |
| 设备互联、远程连接、A2A | 是否属于 Cruio V1 对外能力 |
| 开发者选项 | 是否全部隐藏，或保留少量实际需要的选项 |
| 个性化、技能编辑 | 是否继续允许用户自定义 |

这些入口不能仅因“套壳”就一并删除。先确认它们是否影响现有创作能力，再按选定范围裁剪。

**完成标准：** 用户可以使用保留的功能，但不能通过设置页面或接口恢复已经关闭的供应商配置能力。

## 7. 本地工作目录与使用数据同步

### 7.1 本地工作目录

- [ ] 保留用户选择本地目录及已有项目管理能力。
- [ ] 画布、文档、原始素材和生成结果继续保存在本地。
- [ ] 登录和退出不删除用户项目文件。
- [ ] 项目目录与账号配置分开，项目中不写入账号调用凭证。
- [ ] 继续复用现有工作区文件封装，不重建文件管理系统。

### 7.2 同步边界

“软件使用数据”仍需确定字段清单。以下是讨论用的建议分类，不代表已授权上传全部数据。

| 数据 | V1 建议 | 待确认内容 |
| --- | --- | --- |
| 账号基本信息 | 云端管理，客户端按需读取 | 账号服务来源与字段 |
| 用户偏好 | 按需同步 | 具体哪些设置需要跨设备保留 |
| 项目摘要 | 可选同步 | 是否需要项目 ID、名称及更新时间 |
| 功能使用记录 | 按明确清单同步 | 记录哪些操作、是否需要用户开关 |
| 模型调用使用记录 | 优先使用服务端已有记录，客户端只补必要的业务关联 | NewAPI 是否提供相应查询或关联能力 |
| 画布、文档、对话正文 | 默认本地，不纳入使用数据上传 | 若要求上传，应明确列为内容同步需求 |
| 图片、视频、音频文件 | 默认本地 | 不因“数据同步”自动增加素材云存储 |
| 本机路径及调用密钥 | 不作为普通使用数据上传 | 云端项目记录使用稳定标识，避免依赖本机绝对路径 |

模型推理所需的提示词和参考输入会按实际接口发送至模型服务，这与使用数据同步是两条不同的数据流。

### 7.3 必要实现

- [ ] 明确同步字段、触发时机、账号归属和云端读写接口。
- [ ] 云端数据由服务端绑定当前用户，按账号隔离。
- [ ] 同步失败不把已成功保存的本地项目误判为保存失败。
- [ ] 补传使用稳定记录标识去重，账号切换后不串传。
- [ ] 金额、余额、额度不以客户端上报值作为结算依据。

**完成标准：** 本地项目仍可按原方式保存；约定的使用数据进入正确账号的服务器记录；不会把项目内容或密钥误当统计数据上传。

## 8. 套壳范围内仍需补齐的产品交互

本节只列与本次改造直接相关的界面缺口，不新增原项目已有的创作功能，不作为独立的大功能模块开发。

| 交互点 | 需要设计的行为 | 是否新增功能 |
| --- | --- | --- |
| 登录后的首次进入 | 自有供应商已配置时直接进入项目流程，避免继续要求用户添加提供商 | 登录与供应商替换的必要衔接 |
| 未开放的模型能力 | 节点或模型入口隐藏、禁用，还是提供明确说明 | 按 NewAPI 实际能力决定 |
| 旧项目的模型选择 | 旧模型不可用时提示用户选择替代模型，保留原提示词、连线及结果 | 供应商替换的必要衔接 |
| 没有活动画布 | 提供明确的“新建／选择画布”入口，避免只显示“画布尚未就绪” | 可选的小范围提示改进；已有创建能力直接复用 |
| 本地与已同步的区别 | 是否需要展示使用数据的同步状态，避免让用户误以为完整项目已云端保存 | 取决于同步产品定义 |
| 原版入口去向 | 原充值、帮助、账号链接分别替换、隐藏还是跳转至现有自有页面 | 品牌与设置裁剪的必要衔接 |

不再添加“新素材库”“新角色系统”“模板中心”“成品导出”等宽泛建议。需要增强任何创作能力时，应先确认当前实现的具体不足，再单独立项。

## 10. 实施阶段

| 阶段 | 工作内容 | 阶段产物 |
| --- | --- | --- |
| 第一阶段：确认范围 | 品牌资料、账号来源、NewAPI 接口、模型清单、设置裁剪清单、同步字段 | 可执行的页面与接口清单 |
| 第二阶段：品牌与登录 | Cruio 品牌替换、登录流程、工作区访问条件 | 用户登录后可进入现有创作界面 |
| 第三阶段：供应商替换 | 接入自有 NewAPI、替换默认配置、校验各模型入口 | 选定模型在原节点与助手中可用 |
| 第四阶段：设置裁剪与数据同步 | 收敛用户配置能力，接入约定的使用数据同步 | 设置边界生效，本地保存和云端记录符合约定 |
| 第五阶段：整体验收 | 检查套壳后的完整使用流程及原有能力 | V1 验收记录和剩余问题清单 |

品牌资产准备和接口资料核对可以同时进行；具体开发不在账号和数据范围未确定时擅自扩展。

实际推进顺序已调整：优先完成自有模型接入与核心生成链路验证，再完成模型入口统一及平台能力探索。后续建议顺序见附件：部署边界确认 → 账号与权限 → 配置和数据隔离 → 客户入口裁剪与手工运营 → 场景验收。充值与客户 API 的站内集成是后续候选阶段。
