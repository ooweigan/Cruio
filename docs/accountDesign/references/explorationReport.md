# Cruio 账号、模型接入探索报告与方案计划

日期：2026-11-02  
关联文档：[Cruio V1 工作大纲](./workOutline.md)  
状态：只读探索已完成；方案待确定，尚未实施账号与权限改造。

## 1. 目标与核查范围

客户只使用 Cruio 账号，在 Cruio 内选择已开放模型并完成创作，不配置供应商、不登录 TF-Router 或 NewAPI。运营暂时后台手工配置，后续再考虑站内充值、用量和客户 API 集成。

本报告基于 Sol 子 Agent 对当前工作树的只读探索及主 Agent 对关键入口的复核。探索没有修改业务代码、读取实际密钥或启动付费生成。工作树包含此前模型接入改动，因此本报告描述当前 Cruio，而非未经修改的上游 Toonflow。

纯源码核查可以确认当前权限与数据结构，不能替代多用户、部署或支付验收。NewAPI 的用户管理、充值 API、媒体计费覆盖尚未完成本轮核查。

## 2. 已完成的基础

- 已建立 Cruio/NewAPI 文本与媒体适配，实际跑通文本、图片、视频和素材保存复用。
- 首页和画布 Agent 的公共模型列表统一为 Cruio；正常文本与媒体生成拒绝旧供应商 ID。
- 文本和媒体共享模型服务地址、密钥；旧供应商配置暂保留，未作为正常模型调用入口。
- 已修复推理模型的 `developer` 角色兼容问题。
- 这些工作证明本地核心生成链路可用，不代表已有客户账号、用户隔离或客户计费能力。

当前准确定位是共享数据与配置的单实例应用，可以有多个连接。若直接作为多人服务开放，客户认证、配置凭证和数据归属都存在缺口。仅隐藏设置按钮不能解决这些问题。

## 4. 产品方向与尚未确定的边界

### 已确认

- 客户使用统一 Cruio 账号，不自行配置模型地址或 API Key。
- 模型接入由运营手工配置。
- 未来充值及 API 能力优先站内集成，避免供应商外跳。
- 复用现有创作能力，不重做画布、节点与素材库。

### 必须先确定

1. **部署形态**：原工作大纲明确桌面客户端、本地项目；最新“平台使用”尚不能解释为已批准迁移到多人 Web 或云端项目存储。
2. **账号来源**：是否已有可复用的 Cruio 身份服务、数据库和管理员体系；当前仓库中未发现不代表外部不存在。
3. **调用路径**：桌面客户端直接使用用户级 NewAPI 令牌，还是由 Cruio 云端代理调用；需结合撤销、额度和上游管理凭证边界选择。
4. **额度口径**：是否在首版提供用户额度、采用何种单位，谁负责最终扣减和对账。
5. **第三方功能范围**：插件市场、云端探索、MCP、远程连接、A2A 和开发者能力的对外范围。

桌面模式下，本机设备所有者可以读取自己的项目文件，不能承诺通过应用登录保护磁盘文件。云端模式下，服务端必须按用户授权项目、素材与任务访问，不能只靠路径限制。两种模式都不能将平台管理密钥或共享高权限模型密钥交给客户。

## 5. 建议职责划分

| 部分 | 建议职责 |
| --- | --- |
| Cruio 客户端/页面 | 登录、模型选择、创作、个人偏好；只获取与当前用户有关的信息 |
| Cruio 账号与业务服务 | 身份、角色、可用模型、必要的数据归属和调用授权；是否承担模型流量转发待部署方案确定 |
| NewAPI | 模型渠道、上游凭证、路由和其已有计量能力；由运营管理 |
| 运营管理入口 | 手工建号/停用、模型开放范围、额度调整及记录查询；优先复用已有工具，不默认新建完整后台 |

系统接入配置与个人偏好必须分开。客户接口不得完整返回或覆盖全局 settings；管理员设置接口应单独鉴权，密钥更新只写入、不回显明文。客户模型目录返回名称、能力和可选参数即可。

## 7. 分阶段实施计划（建议，待确认后实施）

### P0：确定边界和复用能力

- 明确桌面/多人 Web 范围、已有身份服务和数据库。
- 核查实际部署的 NewAPI 用户、令牌、额度、日志、媒体计费接口及权限。
- 确认客户可用功能与运营手工操作清单。
- 产物：账号与模型调用时序、数据归属表、接口开放清单及明确不做项。

### P1：账号与接口权限

- 实现 Cruio 登录、有效会话、退出与账号停用，区分客户与管理员。
- 逐项覆盖生成、文件、素材、对话、任务和配置接口；服务端从可信会话获取用户身份。
- 保护供应商编辑、代码调试、插件管理等高权限能力。
- 验收：未登录请求被拒绝，普通客户不能操作管理员接口，停用或退出后的受保护调用失效。

### P2：配置与数据边界

- 将供应商凭证、个人偏好和项目列表分开存储与授权。
- 云端项目以服务端项目归属解析目录，不接受任意绝对路径作为授权依据；本地项目继续遵守原存储边界。
- 对素材、对话和任务落实与部署模式匹配的用户归属，检查账号切换。
- 明确存量共享数据的归属与迁移方法，迁移前备份；不自动删除或把全部旧数据公开给每个新账号。
- 验收：两个账号不能交叉读取或修改云端私有数据，客户响应不包含系统密钥，原本地项目仍能打开。

### P3：客户流程与手工运营

- 去掉模型配置向导与供应商外跳，登录后直接使用运营开放的模型。
- 按已确认清单裁剪客户设置和第三方入口。
- 复用已有管理工具；确有缺口时只补必要的账号、模型权限和额度管理能力。
- 如首版提供用户额度，必须由可信服务执行，并持久化调用关联；视频任务应处理重复提交、成功结算和失败释放。具体职责取决于 NewAPI 核查结果，不默认自建钱包。
- 验收：运营配置完成后，客户无需供应商凭证即可完成核心创作；无法通过旧接口恢复被关闭的能力。

### P4：场景验收

- 复验登录 → 项目 → 文本/图片/视频生成 → 保存 → 素材复用。
- 补验截取、拼接、失败处理、长任务中断及恢复边界。
- 检查不同账号、旧项目和用户额度场景。
- 按仓库规定运行已有类型检查、构建与手动验证；不新增测试代码。正式功能验收由软测人员执行。

### 后续候选：站内充值和客户 API

在账号、权限和额度口径稳定后，再确定余额、用量、订单、支付回调、退款、客户 API Key 等范围。客户操作留在 Cruio，后台对接已核实的 NewAPI 能力。该阶段尚未实施。

## 8. NewAPI 身份与账本方案

Cruio 身份应作为客户业务身份。可考虑保存 `Cruio userId → NewAPI userId/tokenId` 映射，但采用一用户一 NewAPI 用户还是一用户一令牌，需确认实际权限、限额与查询能力后决定。

应明确一个用户额度扣减权威，避免 Cruio 与 NewAPI 独立重复扣费：

- 若 NewAPI 管用户推理额度，Cruio 维护账号映射、运营调整/订单关联和展示数据。
- 若 Cruio 管独立商业余额，需要完整的预占、结算、释放、退款与对账；NewAPI 的额度作为下游限额或成本记录，不能直接当客户钱包。

客户收费与平台上游成本需分别定义，但不意味着必须自建两套账本。当前媒体 billing 中的进程内余额快照不是客户钱包，不应直接沿用为消费账本。

## 9. 本次结论与下一步

核心模型生成接入已经完成必要的实际验证；客户平台能力尚未完成。下一步应先完成 P0 的部署形态、身份服务和 NewAPI 管理能力确认，再确定最小实施任务。不要仅移除 TF-Router 页面便宣布统一账号完成，也不要将本报告中的云端隔离建议解释为已批准改变本地项目方案。

本次只更新工作大纲和探索方案文档，不继续修改登录、权限、后台或充值业务代码。
