# macOS 系统菜单实施计划

**目标：** 按已确认方案提供 Cruio、文件、编辑、视图、窗口五个菜单，直接复用现有创作操作。

**架构：** 桌面宿主维护原生菜单，Web 页面通过现有 host-message 通道同步账户、最近项目、画布和语言状态。菜单命令通过 CustomEvent 交给当前页面；项目切换先走现有路由保存守卫，再复用首页创建、打开和目录恢复逻辑。

**技术：** TypeScript、Electrobun ApplicationMenu、Vue 3、Vue Flow、现有 i18n。

## 实施步骤

- [x] 在 `apps/server/src/types/desktop.ts` 定义菜单状态及命令类型；在 `apps/desktop/src/applicationMenu.ts` 建立五个原生菜单及受限消息校验。
- [x] 在 `apps/web/src/lib/desktopMenu.ts` 接入宿主事件，维护随账户、路由、弹窗和画布状态变化的启用状态；复用 Pinia 最近项目，不另建持久化。
- [x] 为首页项目操作和设置组件增加菜单接入；画布通过现有宿主暴露视图及撤销、重做、全选操作，文本编辑继续交给原生角色。
- [x] 接入桌面主进程；macOS 关闭窗口改为隐藏并保留页面，Dock 重开恢复，退出继续走现有异步清理。
- [x] 抽取并补齐新增菜单文案，菜单随当前语言更新。
- [x] 显式执行现有 Web、Desktop、Server 类型检查、Web 与桌面构建及可用的手动验证，检查差异；不新增测试或自检文件，不提交代码。

## 验证记录

- Web、Desktop、Server、i18n 类型检查通过。
- macOS arm64 完整桌面构建通过，包含 Web、节点、工具、扩展和 MCP 构建。
- 新增菜单文案已补齐其余 20 种语言，抽取差异仅保留本轮菜单相关键与来源。
- 已用独立数据目录启动构建产物；macOS 拒绝 osascript 辅助访问，未完成原生菜单点击、焦点编辑和 Dock 重开交互验证。
- 构建仍提示配置加载兼容性和部分产物超过 500 kB。

## 行为边界

- 未登录或账户正在切换时禁用项目操作，清除宿主最近项目数据。
- 导航被保存守卫取消时，不执行创建或打开命令。
- 画布未就绪、文档面板或弹窗打开时禁用画布视图操作。
- 编辑菜单按焦点选择文本原生操作或画布历史/选择；不新增画布剪切业务。
- 自动保存沿用现状，本次不添加独立保存菜单或 Cmd+S。
- 原有未提交的文件存储调整保持不变。
